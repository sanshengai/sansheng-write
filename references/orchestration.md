# 按依赖并行，按文件收口

编排器是当前宿主中的主控制者。`pipeline.py orchestrator on` 只记录策略，不会自动启动任务；主控必须真的启动后台进程或子 Agent，保存任务 ID，并在等待期间继续独立工作。

## 执行顺序

1. **创作期**：主控确定主线与统一正文；必要的不同问题调研可以并行。正文候选固定后，事实复核和语义冷读同时读取同一快照，各自返回意见；主控统一修改，按变化复验。
2. **作者批准定稿后（schema2）**：主控接管、预置标准音频卡，交付音乐生成单。播客已启用且参数齐备时，立即后台运行 `pipeline.py --dir <文章目录> podcast-pregen`；同时主控进入视觉规划与出图。音乐尚未交回不阻塞播客和图片。
3. **视觉分支**：一张图内部按“编译 → 渲染 → 后处理 → 独立审核”顺序；不同图片在输入冻结、输出互不覆盖且工具支持时并行。不为占满 Agent 增加候选数。schema2 只用 stylebook 合同。
4. **汇合**：播客、音乐、图片都通过各自验收，主控选组装配、最终排版、完整阅读，再运行一次 `release-to-draft`。等待音频时可准备版式，不提前验收或反复渲染整篇。
5. **正式发表后**：取得永久链接再运行 `finalize`。网站排队单独跟踪 job ID，不重启文章制作，也不以 queued 冒充上线。

并行段的墙钟时间近似于最长分支，而非分支之和；最后汇合的验收仍需时间。音乐交接、外部队列分别记录，不能许诺固定“几分钟写完”。

## 谁适合用子 Agent

| 工作 | 执行者与边界 |
|---|---|
| 不同问题的必要调研 | 子 Agent，只回相关来源和结论；同一问题不重复多引擎撒网 |
| 事实复核、语义冷读 | 独立上下文并行，只读同一候选，主控统一裁决 |
| 多张图的独立审核/渲染 | 工具允许时分别处理唯一候选；不写选组、正文或状态，不覆盖正在审核的输入 |
| 播客生成、转码等固定命令 | 宿主后台进程；不占一个持续思考的 LLM Agent 等待 |
| 统一正文、改稿裁决、最终排版、发布 | 主控，保持单写者 |

没有子 Agent 时按各审核合同记录实际执行方式，不伪称独立审核。不把文章所有历史对话复制给子任务；只给当前稿、必要来源、当前合同及验收目标。

## 写入所有权

- 主控独占 `定稿.md`、元数据、`.state.json`、选组/装配、最终 HTML、发布与收尾文件。
- 播客后台进程独占实际 profile 解析出的播客目录及播客分发状态；同文章只启动一个。生成锁冲突返回 4 表示已有任务，继续观察原任务，不当作已完成或故障重试。
- 播客运行期间不运行 `distribute plan`、其他渠道状态写入、`finalize` 或实体归档；这些会共享分发状态或移动输入。主控可以处理独立图片候选和版式准备。
- 每个图像任务只写其分配的候选目录；共享账本/选组由主控汇合后写。若底层工具写共享账本，则该工具调用串行，不凭“目录不同”假定安全。
- 正文、标题、播客提示词/参数在生成期间冻结。确需改稿时保留任务；收件检查会拒绝已变化的正文、标题和提示词，不覆盖原音频。语言/长度使用本进程冻结配置；若生成期间修改了 profile，必须用新进程的消费者检查后再采用，不在后台任务中热改配置。单纯机器卡或图片装配变化不重做播客。

主控记录任务 ID/日志、当前输入与产物路径；宿主返回 running 后继续独立工作，不循环空等。汇合时先检查退出码，再验证当前输入和实际产物。进程消失、网络失败都不能凭旧 done 标记当完成。

## 最小任务包与故障处理

每个单元给 `run_id`、`unit_id`、只读输入及摘要、唯一输出位置、禁止写入/发布的范围和验证方法。只读委派明确禁止写盘。具体旧结构化合同从 [agent-contracts.md](agent-contracts.md) 按需进入。

返回后检查来源、输入是否变化、输出是否冲突，并运行该产物对应的消费者验证。确定性合同错误立即查原因；审核格式错误修调用，图像缺陷才修图。只有瞬态外部错误按工具退避策略重试，不对未改变的失败输入机械重跑三次。

草稿提交事务整体串行；已拿远端 ID 以 `_release-attempt.json` 恢复官方读回，不重新创建。`orchestrator=off` 改为串行，验收标准不变。
