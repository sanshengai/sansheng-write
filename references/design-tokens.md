# 排版设计令牌（Design Tokens）-- 视觉系统单一数据源

> **这是本 skill 所有排版组件的视觉 SSOT，但 SSOT 不在代码里，而在你的 profile。**
>
> 所有颜色 / 圆角 / 浅色底 / 边框 / 文字色，**真值来自 `profile/brand.yaml` 的 `colors` / `radius`**。改任何一个视觉值，只改那一个文件，渲染期自动全局生效--你不需要动脚本、也不需要挨个改模板。
>
> 背景：组件是不同时期分别造的，如果每个组件各写各的色值（曾出现过 7 种圆角、6 种浅色底、8 种灰、甚至两个主色相并存），就会有「同一套东西却像几个人做的」割裂感。把它们收敛成一套小尺度令牌、集中到 `brand.yaml` 一处，就能一改全改。

## 令牌怎么落地（一处改完，全局换皮）

三层协作，你只碰第一层：

| 层 | 是什么 | 你要不要动 |
|----|--------|-----------|
| **① `profile/brand.yaml`** | 令牌真值（`colors` / `radius`），你的主题在这里定义 | ✅ 只改这里 |
| **② `scripts/format_layout.py` 顶部常量** | 中性默认值（未配置 profile 时的回退）；渲染时经 `profile_config` 读 `brand.yaml` 覆盖 | ❌ 不用动 |
| **③ `templates/*.html`** | 组件模板，写的是同一套中性默认值 | ❌ 不用动 |

**机制**：模板和脚本都用「中性默认值」写死；排版末尾 `format_layout.py` 的 `process_theme()` 扫一遍产出的 HTML，把默认值批量替换成 `brand.yaml` 里的当前主题值。默认 profile 下每一项映射都是「自己换自己」，整体 no-op、零行为变更；一旦你在 `brand.yaml` 改了某个色，`process_theme()` 就把全篇对应的默认色统一换成你的值。

> **未配置 profile 是正常路径，不是错误**：`SANSHENG_WRITE_PROFILE_DIR` 没设时回退仓内 `profile.example/`，全部用下面的中性默认值，排版照常跑通。

## 六套预置主题

`brand.yaml` 的 `theme` 字段填 `themes/` 下的文件名即可整套换皮（留空则用 `colors` 段自定义）：

| 主题 | 基调 | 主色相 |
|------|------|--------|
| **slate**（默认） | 钢青，中性克制 | `#2F6F8F` |
| **ink** | 近墨黑，冷静内敛 | 墨黑系 |
| **sage** | 草木绿，温和自然 | 绿系 |
| **jade** | 青玉绿，清润明快 | `#0E926F` |
| **amber** | 琥珀赭，温暖醇厚 | `#A2661C` |
| **plum** | 梅子紫，沉静雅致 | `#8A4E7E` |

> ⚠️ **ink 主题注意**：近墨黑做主色时，正文里「主题色高亮」与普通深色文字的视觉区分度会
> 大幅下降（高亮体系近乎失效）——重视高亮语义的文章建议选其他主题，或自定义 colors 时
> 给 primary 留出明度差。
> 另：封面 / 信息图 / 图表等**生成物不随主题自动换色**（它们由生图模型按 prompt 里的色值
> 产出）——换主题后记得同步改生图 prompt 的主色，或接受生成物与排版异色。
> 4 个主色衍生 alpha 装饰值（0.12 / 0.3 / 0.14 / 0.05：PART 分节线、编号竖线、金句卡发丝线、
> 引用块底）随 primary 自动换算，非独立令牌；`TEXT_FAINT #b0b6bb` 设计上不随主题。

## 令牌表（中性默认值 = slate）

> 下表是 `brand.yaml` 的键名与 slate 默认值。想换皮就在 `brand.yaml` 改对应键的值。

| 类别 | `brand.yaml` 键 | 默认值 | 角色 |
|------|------|----|----|
| **主色·一级** | `colors.primary` | `#2F6F8F` | 主强调（重点突出 / H3 / 表头 / 一级标识） |
| **主色·二级** | `colors.secondary` | `#7FB0C4` | 次强调（次级标识 / 辅助强调；同色相偏浅，见下「深浅阶」） |
| **主色·深** | `colors.primary_deep` | `#245a75` | 主色深一档（渐变用） |
| **圆角·小件** | `radius.sm` | `6px` | 序号块 / 图标底 / URL 框 等小 UI 件 |
| **圆角·媒体** | `radius.media` | `8px` | 图片 / 缩略图 |
| **圆角·卡片** | `radius.card` | `10px` | 卡片 / 表格 / 链接卡 容器 |
| **圆角·模块** | `radius.module` | `12px` | 大模块（导读栏 / 深读模块） |
| **圆角·胶囊** | `radius.pill` | `999px` | 胶囊（标签 / 徽章） |
| **浅底·强调卡** | `colors.primary_soft` | `rgba(47, 111, 143,0.05)` | 强调卡（要点 / 金句，带 4px 左竖条） |
| **浅底·容器** | `colors.surface_soft` | `#f2f7f9` | 容器模块（深读 / 链接 / 音乐，带全边框） |
| **浅底·内嵌** | `colors.surface_inset` | `#eaf1f5` | 内嵌 URL / 图标框 |
| **浅底·表格行** | `colors.row_tint` | `rgba(47, 111, 143,0.03)` | 表格交替行（最淡） |
| **边框·卡片** | `colors.border_card` | `#d7e3ea` | 卡片 / 模块外框（主色系） |
| **边框·发丝** | `colors.surface` | `#eef0f2` | 内分隔线 / 表格行分隔 |
| **时间线竖线** | （中性常量，不随主题） | `rgba(0,0,0,0.06)` | H3 / Case 时间线竖线 |
| **文字·正文** | `colors.text_strong` | `#333333` | 正文 |
| **文字·标题** | `colors.text_title` | `#26333a` | 浅底模块里的深色标题 / 引文 |
| **文字·说明** | `colors.text_mute` | `#8a929a` | 副标题 / 说明 / 出处（中性灰） |
| **文字·链接** | `colors.text_link` | `#4a6b7a` | URL 文字 |
| **文字·极弱** | （中性常量，不随主题） | `#b0b6bb` | 极弱提示（占位 / 免责） |

> 白底上的结构性标题（H2 主标题、Case 标题、推荐阅读标题）保留中性 `#333333`；浅底模块内标题用 `text_title #26333a`。两者是语义区分，不是冲突。

## 主色深浅阶（同色相分主次）

> **「唯一主色相」针对的是消除意外漂移（曾混入的杂色相 `#0E9F6E`），不是禁止深浅分级。** 同一个色相、做明度阶，既保证色系统一、又能区分主次--这才是有纪律的做法。

| 层级 | 值（slate 默认） | 用途 | 怎么用 |
|------|----|----|----|
| **一级（主）** | `primary` 加粗 | 重点突出、核心结论、H3、表头 | `<mark>关键词</mark>` |
| **二级（次）** | `secondary` 加粗 | 次级标识、辅助强调、并列里的次要项 | `<mark class="2">次级词</mark>`（class 含 `2` 或 `sub` 均可） |
| **三级（极弱/通透）** | 各 `*_soft` / `*_tint` 半透明底 | 卡片 / 行 / 框 的背景填充 | 见上「浅底」四角色 |

- **二级色用在哪**：加粗短语 / 徽章 / 次级标题这类「能加粗或有底色」的地方。**小字正文里慎用**--`secondary` 比主色浅，纯文字对比度偏低。
- **机制**：`format_layout.py::process_highlights` 先扫 `<mark class="2">`→二级色，再把其余 `<mark>`→一级色。
- 🛡 **优雅降级**：万一 markdown 转换器吞掉了 `class`，`<mark class="2">` 会退化成一级色--仍是主题色、可读，只是少了深浅区分，不出错。
- **不要再引入第三种色相**（如曾意外混入的 `#0E9F6E`）。要分级只在「主色 → 二级色 → 半透明底」这条明度轴上走。

## 两套卡片语言（容器层级）

| 家族 | 信号 | 底色 | 边框 | 成员 |
|------|------|------|------|------|
| **强调卡** | 4px 左竖条 + 浅底 | `primary_soft` | 左竖条 `primary` | 要点提炼、金句卡 |
| **容器模块** | 全边框 + 极浅底 | `surface_soft` | `border_card` | 深读模块、链接卡、音乐栏 |
| **数据容器** | 圆角裁切 + 彩头 | 白 / `row_tint` 交替 | `border_card` | 表格 |

「这块要不要强调」用**左竖条 vs 全边框**区分，不靠底色深浅 -- 所以两个底色（0.05 vs #f2f7f9）允许很接近。

## 色彩角色分工 + 灰阶承重原则

> 借鉴公众号排版「克制用色」通行做法，把上表令牌按「角色」归位，明确谁承重、谁点缀。

| 角色 | 令牌 | 职责 | 用量 |
|------|------|------|------|
| **主色·锚点** | `primary` | 章节 / 表头 / 一级 `<mark>` / 核心结论强调 | 只在锚点，克制 |
| **二级·次强调** | `secondary` | 次级标识 / 次级标题；能加粗或有底色处 | 小字正文慎用 |
| **浅底·填充** | `primary_soft / surface_soft / surface_inset / row_tint` | 卡片 / 模块 / URL 框 / 表格行背景 | 大面积浅色，做容器 |
| **灰阶·承重** | `text_strong / text_title / text_mute` + 极弱 `#b0b6bb` | 正文 / 标题 / 说明 / 弱提示，承担 ≈90% 文字 | 主力 |

**灰阶承重原则**：约 90% 的文字交给中性灰阶，**彩色（主题色）不承担正文阅读、只做锚点 + 关键词点缀**，避免「色系太多 / 花哨」。

**用色配额（全文彩色总量）**：金句卡 ≤2/篇 · 要点卡每 800-1200 字 · 强锚点 ≤5 处 · 一段内高亮 ≤2 种 · 点缀组件 ≤3 种（详见 [layout.md 视觉层级三层表](layout.md) + 步骤2.5 配方表）。

> **灰阶档位（现 4 档）**：`#333 → #26333a → #8a929a → #b0b6bb`。长文若觉次级信息层级不够用，可评估扩到 5–6 档--⚠️ 扩档需同步 `format_layout.py` 顶部常量 + 跑回归基线防 golden 漂移（属 code-track，勿在文档里单方面加值）。

## 圆角 4 档尺度记忆法

`6 小件 / 8 媒体 / 10 卡片 / 12 模块 / 全圆胶囊` -- 越大的容器圆角越大；图片单独一档（8）。

## 新增组件 / 栏目规约（反「换皮」惰性）

新增任何排版组件 / 栏目前，**先推导它的结构模型，再落组件**，禁「照旧组件改改配色就上」。先答完这四问，答不清就先想清楚，别急着复制粘贴改：

1. **信息形态**：这块内容是 叙事 / 说明 / 数据 / 对比 中的哪种？
2. **密度**：高密度多卡 还是 低密度大留白？
3. **层级位置**：落在 锚点 / 标记 / 容器 哪一层（见 [layout.md 视觉层级三层表](layout.md)）？
4. **令牌复用**：颜色 / 圆角一律取 `brand.yaml` 令牌，**零新硬编码色值**--既保色系统一，也保证换主题时新组件自动跟着换皮（`process_theme()` 只认默认令牌值；写死别的 hex 就换不动了）。
