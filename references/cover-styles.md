# 🎨 封面风格池（5 种「文字在侧」布局：briefing / noir + montage 3 亚型）

> **默认风格 = `montage-evidence`（可在 profile 配置改默认）。** 本 skill 的封面签名视觉是「中文 L1+L2 标题 + 后方英文 OVERSIZED GHOST 半隐水印」的蒙太奇拼贴式，默认所有新文章走 `montage-evidence`。若想换默认风格，改 `profile/brand.yaml` 或在 `article-meta.yaml` 显式填 `cover_style`。
>
> **生效规则**：
> 1. `article-meta.yaml` 的 `cover_style` 未填时**默认走 `montage-evidence`**
> 2. 手动指定优先级最高：`article-meta.yaml` 显式填其他 `cover_style` 值（`briefing` / `noir` / `montage-pipeline` / `montage-starry`）即激活该风格
> 3. 历史 `works.yaml` 里其他风格的记录保留，不影响新规则
>
> **montage-evidence 封面文字基线**（每篇必带）：
> - 英文 OVERSIZED GHOST-WATERMARK：3 个关键词用 ` × ` 连接，极深灰 #1F1F25，~155% L1 字号，下部羽化，半隐在中文标题后面。**3 词必须从本文关键词/核心结论抽取**（本文专属的人/物/动作/反差），禁套 `TOOL × DATA × FUTURE` 泛词（自检：换到另一篇还成立就太泛）；**字体走工业 condensed / slab-serif 的"项目代号"气质**，与中文 clean 层做中英异质搭配
> - 中文 L1 + L2 两行标题，关键词主题色 #2F6F8F
> - L2 下方 ~24px gap，3 个 quiet-pill 胶囊（默认）：emoji + 中文短标签
> - 右侧拼贴区：主物件 + 2-3 个黑底主题色描边徽章 + 虚线箭头

> 解决"每篇封面视觉太像"的审美疲劳问题。5 种布局共享**品牌一致性**（深色底 + 主题色 + 2.35:1），但在**构图、背景氛围**上刻意拉开差异。
>
> 🔴 **版式收紧**：全部都是「文字在侧」的版式--文字在右侧或右上对角位置始终保持足够字号权重，**绝不做文字上下堆叠**。上下堆叠版式（符号居中+文字居中正下方、文字贴顶/贴底）实测会严重挤压主标题字号，导致标题在缩略图上不醒目，已删除、不可选。
>
> 🔴 **风格池已收敛为 5 种**：briefing / noir / montage-evidence / montage-pipeline / montage-starry（montage 三亚型同源）。历史下架的「对角构图 + 单物件 + 大量留白」版式（暖光物件特写 / 墨绿星河物件）实测在删副标题后对角版式失衡、与信息驱动型主线调性偏差，已下架，不再可选。

## 不变的底层铁律（所有风格必守）

- 比例：`2.35:1`（微信头条封面）
- **文字位置铁律**：文字必须在画面的**右侧**（左图右字）或**右上对角**（对角式），绝不允许放在视觉主体的正上方或正下方
- **背景色板**（只在两种深色里选，由所选风格决定）：
  - 深炭 `#0E0E10`（中性底，风格 A briefing / C montage-evidence / D montage-pipeline 用）
  - 纯黑星河 `#030712`（偏冷底 + 银河若隐若现，风格 B noir 用）
  - 严禁纯黑 `#000`、亮背景、未列入的任何色调
- 唯一强调色：主题色 `#2F6F8F`，其余白
- 主标题关键词高亮（数字/对比词/人物上主题色 + 加粗，其余纯白）
- 🔴 **双色铁律**：深色底封面**只允许主题色 + 纯白**两色--副标题分层用「字号 / 字重 / 透明度（**≥70% 不许更低**，深色底上 70% 白仍清晰，主次拉得更开）」实现层次，**严禁引入灰色色相**（gray-300 / 浅灰 / 中灰一律违规，会让封面"色系太多"）。
- 副标题数量收紧：**首发 / 仪式感场景压缩到 1 段**（如「今日发刊」「年度收官」）；常规深度文最多 2 段；**禁止 3 段以上堆叠**--文字太多反而稀释主标题视觉权重。
- 留白 40–50%，严禁堆满
- 🔴 **右下角禁止 AI 渲染任何品牌识别文字**（品牌名、账号名、编号、署名等都不要写）-- `add_logo.js` 会在后期叠加品牌 Logo，AI 再写就重复了。prompt 必须显式 forbidden：`No brand name, account name, issue number, or signature text -- logo added in post-processing.`
- 🔴 **深色纵深 · 明度阶梯**：深色封面的层次一律靠「同色相、多明度档」实现，不靠灰色相 / 描边 / 发光。深色块按明度排成阶梯--画布底 `#0E0E10` < 徽章底 `#1A1A1A` < 近底色 pill `#141416~#161618`，相邻档差仅 1–3 个亮度级。新增任何深色元素先问「它该落在哪一明度档」，别都用同一个黑。（同色相变明度 ≠ 引入新色相，双色铁律不破）
- 🔴 **全局统一光向**：全画唯一光源 = 左上 45° key light，所有元素受光面朝左上、投影朝右下，杜绝多光源廉价感。具体三级明度梯度与质感技法（薄体积 / halftone / film-grain）见下文 montage 背景段与右侧拼贴段。
- 详细文字铁律见 [iron-rules.md · 封面图文字样式铁律](iron-rules.md)

## 封面文案四招（🔴 封面标题写什么，先于选风格）

> **痛点**：全链路里外标题与封面同次生成，模型极易偷懒--**封面主标题原样复述外标题关键词**，两处一个意思、浪费封面这块黄金位。以下四招管"封面写什么文案"（比选哪种视觉风格更重要，先定文案再套风格）。

1. **封面标题 ≠ 外标题（视角错开）**：**外标题卖"为什么点开"**（钩子 / 关键词 / 利益点，见 [title.md](title.md)）；**封面主标题卖"里面讲什么核心"**（本文最硬的结论 / 反差 / 主体）。两者视角必须错开，不是同义改写。
2. **禁复述外标题核心关键词**：外标题已用的产品名 / 功能名 / 场景词，封面 **L1 大字主标题不原样复述**；产品名 / 专名只允许出现在**英文 ghost 层、emoji 副标签、或 L2**，不占 L1 视觉焦点。自检：把封面主标题和外标题并排，若核心词重复 ≥1 个 → 改。
3. **未知外标题时五视角自选、直出不问**：封面先行、外标题未定时，从五视角选一个直接出主标题--**数字反差 / 角色革命 / 案例串 / 方法论 / 情绪钩子**；仅当用户明确要"帮我定封面方向"时才列 3–5 个方向让其选。
4. **划线旧认知＝文案层反差，不依赖生图删除线**：可用"旧认知 → 新结论"的反差做主标题内在张力（如 L1 承接旧认知、L2 给新结论/反转）。⚠️ **不要求 AI 生图渲染删除线/strikethrough**（生图链不保证精确排版）--落到**文案对比**即可，真需要视觉删除线时才在后期图层处理。

> 与外标题的分工联动见 [title.md](title.md)（标题锻造阶段已标注"封面另有文案策略、勿复述"）。

## 风格 A · `briefing` 作战图式

**适合题材**：竞争格局、行业对比、横评、数据分析、巨头博弈

**背景色板**（写入 prompt 时照搬）：
- 主底色：深炭 `#0E0E10`
- 战术网格：极淡 hex-grid 或 topo 等高线 `#1A1A1C`，透明度 15%，仅覆盖视觉区背后
- 视觉主体后方：主题色 `#2F6F8F` 微光晕，10% opacity，焦点在 schematic 图的核心位置
- 严禁任何粒子、星点或暖色光

**骨架**：
- 左 42% = 视觉区（schematic 图示）
- 右 58% = 文字区（左对齐）
- 垂直居中，8% 安全边距

**视觉主体**：线性 schematic 图示
- 城堡 + 多向箭头（包围/围攻）
- 雷达环 + 坐标点（竞争格局）
- 电路节点 + 连线（生态对比）
- 流程方块 + 箭头（决策树）
- 统一：细线 flat-vector，主题色线

**文字排布**：
```
[右 58% 左对齐]
┌─────────────────┐
│ 主标题 L1（主题色 + 粗）  │
│ 主标题 L2（白 + 粗）       │  ← 两行堆叠
│ ━━━━━━━━━━                │  ← 40px 主题色分隔线
│ 副标题分层（透明度渐进）    │  ← 三段渐进
│                            │
│  ⛔ 右下角禁止任何品牌名/编号小字（Logo 后期叠加） │
└─────────────────┘
```

**氛围关键词**：briefing-room、quiet intensity、strategic、analytical

## 风格 B · `noir` 星河夜式

**适合题材**：科技叙事、未来感选题、深夜发稿感的速递文、神秘悬念文、AI 深度文

**背景色板**（写入 prompt 时照搬）：
- 主底色：**纯黑星河 `#030712`**（近黑但偏冷蓝一点的底色）
- 银河带：从画面**左上到右下**一条极淡的主题色 `#2F6F8F` 渐隐光带
  - 宽度约 8% 画面高度
  - 透明度 **10–18% opacity**（关键：**若隐若现**，缩略图上只看到一道隐约的光）
  - 边缘严重虚化不锐利（gaussian blur 感）
- 星点：**极少量**白色微星 `#FFFFFF`，只在银河带**正上/正下 3% 条带内**零星散布（**≤12 颗**），透明度 20–40% 随机
- 严禁整屏均匀撒星点（像撒芝麻）、严禁粒子、严禁其他颜色光晕
- **若隐若现原则（硬约束）**：银河是**氛围不是主体**--缩略图只看得到一道隐约的光，满屏看才能辨认是银河。prompt 里必须写满 `faint`, `subtle`, `barely visible`, `hint of galaxy`, `ghostly` 这类限定词

**骨架**：
- 左 42% = 视觉区（与 briefing 同尺寸）
- 右 58% = 文字区，左对齐
- 8% 安全边距
- 银河带斜跨画面，从视觉主体**后方**穿过，不与主文字重叠

**视觉主体**：线性 schematic 图示（与 briefing 同族但更「星际」）
- 抽象几何体 + 环形连线（星轨感）
- 3D 线框棱柱 / 晶格（星际感）
- 节点矩阵 + 连线（数据流 / 星图感）
- 单一几何符号被银河光带穿过（棱柱、立方、环）
- 统一：细线 flat-vector，主题色 `#2F6F8F` 描边 1–2px，画面正中偏左

**文字排布**：
```
[右 58% 左对齐，与 briefing 同]
┌─────────────────┐
│ 主标题 L1（主题色 + 粗）  │
│ 主标题 L2（白 + 粗）       │
│ ━━━━━━━━━━                │  ← 40px 主题色分隔线
│ 副标题分层（透明度渐进）    │
│                            │
│  ⛔ 右下角禁止任何品牌名/编号小字（Logo 后期叠加） │
└─────────────────┘
```

**氛围关键词**：noir、star-lit、cosmic、midnight briefing、scientific awe、quiet universe

**注意**：
- 银河必须**若隐若现**。AI 在看到 "galaxy" 关键词时极容易画成喧宾夺主的"星空大片"，prompt 要反复用 `faint/subtle/barely-visible` 压住
- 与 briefing 的区分：briefing 是"会议室感"，noir 是"深夜工位感"--气质不同但构图同系
- 不要在文字区叠加星点，文字必须清晰可读

## 风格 C/D · `montage` 蒙太奇拼贴式（含 2 亚型）

> **🟢 主线主推风格**：montage 系列承担信息驱动型主线封面的主要权重（目标 60%+）。两个亚型 `montage-evidence` 和 `montage-pipeline` 共享下方主框架，仅在右侧拼贴元素的语义类型上分化（详见文末「亚型分化」章节）。

**适合题材**：信息密度高的干货文 / 横评 / 工具评测 / 多源证据型反差观察 / 数据驱动决策文

> 灵感来自「高密度信息拼贴 + 英文叠加做立体感 + 项目代号风」的封面设计语言，但坚持「双色铁律 + 不上真人」--用克制换专业感。

**背景色板**（写入 prompt 时照搬）：
- 主底色：深炭 `#0E0E10`（可叠 ≤4% 单色 film-grain 微颗粒打破"死平 PPT 感"，但禁任何具象/字符纹理--见下）
- 单束暖光：从画面**左上角**斜照下来作为全画**唯一方向性 key light**，落在右侧拼贴区，主题色 `#2F6F8F` 微染色 ≤12% opacity，soft falloff
- 🔴 **方向性单光源 + 三级明度梯度（bold mood 落地）**：① 右侧拼贴核心物件为全画最亮（受光焦点）、左侧中文标题区为中间调、四周背景沉到最暗（`#0E0E10` 不再提亮），焦点与背景明度差拉满；prompt 写 `strong luminance gradient, hero object is the single brightest focal point, background sinks to deepest charcoal, no flat even lighting`。② 主物件分受光面（朝光侧主题色/白提亮）与背光面（加深到接近背景），右下落一道与光向一致的极淡 contact shadow（不发光、≤15%）；徽章同受此光统一向右下虚化。暗面=背景色加深、亮面=白/主题色提亮，不引入灰相。**对比安全阀**：强光梯度不许压暗左侧文字区，标题始终 100% 清晰可读。
- 🔴 **禁具象背景纹理，但放行抽象印刷肌理**：严禁终端代码 / 文件路径 / 命令行字符 / IDE syntax / 文件树 / 行号 / 任何 monospace 字符串作为背景装饰（踩坑根因：AI 把伪代码渲染得过显眼抢戏 + 自由发挥出杂字）。**例外允许**：`≤4% 单色 film-grain 微颗粒`（背景）+ 主物件填充/徽章底的 `主题色 halftone 半调网点`（用疏密代替渐变做明暗）--这是单色体系里不引入第二色相就能升质感的技法，与被禁的"字符/代码纹理"性质不同。
- 严禁星点 / 网格 / 银河 / 粒子

**骨架**：
- 左 50% = 文字区（英文叠加层 + 中文双行标题 + emoji 标签栏）
- 右 44% = 元素拼贴区（主物件 + 信息徽章 + 虚线箭头）
- 6% 中间空隙
- 8% 安全边距

**左侧文字层（垂直居中）**：

```
[ENGLISH OVERSIZED GHOST]   ← 极深灰 #1F1F25，bold sans uppercase，~155% L1 字号，
                              下部羽化渐变到 10% opacity，与中文 L1 顶部 30-40% 垂直重叠
   中文 L1（白）             ← BOLD，moderate 字号，叠在英文 ghost 前方
   中文 L2（白+主题色）        ← BOLD，**单行不拆**，前段白 + 末尾词主题色
                              ← ~24px gap
[🛣️ 30 公里  /  ⏱️ 40 分钟  /  🪞 三次切道]   ← emoji 标签胶囊（包在主题色渐变 pill 容器里），~30% L1 字号
```

**🆕 emoji 标签胶囊渲染规则**：

🔴 三个 emoji 标签**必须包在一条横向胶囊 pill 容器里**，不能裸露在背景上 -- 这是 montage 风格的「副标题元数据组」标识，让读者一眼识别"这是文章的关键参数标签"，不是普通副标题文字。

胶囊有两种渲染模式，按文章性格择一（默认 quiet pill）：

### 模式一 · `bright-pill` 亮绿渐变胶囊（仪表盘感）

- **形状**：rounded-rectangle pill（capsule，圆角 ≈ 50% 容器高度，做成药丸两端半圆）
- **填充**：主题色微渐变 -- 顶部 `#2F6F8F` → 底部 `#0A6B50`（subtle vertical gradient，不要太强反差），或纯色 `#2F6F8F`（次选）
- **描边**：1px 亮主题色 `#14B084` outline，80% opacity（让胶囊从深炭背景跳出来）
- **内部文字**：emoji + 白色 `#FFFFFF` 中文，` / ` ASCII 分隔符，所有文字纯白
- **气质**：像仪表盘 / 数据徽章 / 强参数标签 -- 胶囊本身是视觉重量
- **适合**：篇幅短的工具速递 / 横评 / 强参数仪表盘感选题；副标签需要"夺一眼"

### 模式二 · `quiet-pill` 近底色低对比胶囊（克制副标题感）✅ 默认

- **形状**：同上，rounded-rectangle pill，padding 18×12px
- **填充**：仅比画布底色亮 1-3 个亮度档的近底色（深炭背景下用 `#141416` ~ `#161618`；星空背景下用 `#0A0B10` ~ `#0C0D12`）
- **描边**：**无** -- 不画任何 outline / stroke，让胶囊轮廓由内填色与背景的微对比定义
- **发光 / 阴影 / 高光**：**全部禁止** -- 不要 glow、不要 drop-shadow、不要 inner-highlight、不要玻璃反光
- **内部文字**：emoji + 白色 `#FFFFFF` 中文，` / ` ASCII 分隔符
- **气质**：像主标题下方的"安静副标题元数据" -- 胶囊几乎隐形，只起分组与标签语义作用，不抢主标题视觉权重
- **适合**：长文 / 深度文 / 高概念蒸馏 / 仪式感发刊 -- 主标题字数多、信息量大，副标签必须克制
- **踩坑教训**：
  - 磨砂玻璃胶囊（90% 透明 + backdrop blur）在部分生图模型上**做不出真正的 transparent / glassmorphism 效果**--要么给一个看得见的暗色块，要么加一圈高光边框，多次迭代仍不达预期
  - 定调：放弃透明感诉求，改走"近底色低对比"路线，让胶囊视觉重量降到最低，达成"副标题不喧宾夺主"的同等效果
  - 推论：所有需要 `glass / transparency / opacity 90%` 这类描述的元素，在生图模型上都先考虑能否用"近底色低对比"等价替代，避免在透明度上死磕

**双胶囊共用规则**：
- **位置**：在 L2 下方 ~24px gap，左对齐（与文字块左边线对齐）
- **宽度**：auto-fit 内容，**不撑满**，只裹住三组 tag 即可
- **分隔符**：` / `（ASCII，前后各一空格）
- **双色铁律不破**：bright-pill 用主题色色相、quiet-pill 用近底色（仍属深炭/近黑色相），都不引入第三色。✅ 合规

**模式选择默认值**（写 cover prompt 时按调性挑）：

| 文章调性 | 默认胶囊模式 |
|---------|-------------|
| 工具速递 / 横评 / 数据驱动 / 仪表盘感 | `bright-pill` |
| 长文 / 深度文 / 高概念蒸馏 / 仪式感发刊 / 主标题信息量大 | `quiet-pill` ✅ |
| 不确定 | `quiet-pill`（默认走克制） |

**字号铁律**（踩坑：超大字号反而显得"挤"）：
- 中文 L1 + L2 的两行**总高度只占 canvas 28-30%**（不是 40%！）
- 字号 moderate，类似 briefing 风格的字号水平
- 留白比例 35-45%
- 🔴 **文字密度自适应**：当 L2 字数偏多（>13 字）逼近溢出时，按优先级让步--先缩英文 ghost 字号（155%→135%）、再把右侧徽章由 3 个减到 2 个、最后才考虑胶囊降为 2 组；**绝不靠压缩 L2 字号或拆 L2 换行解决**。守住"文字区有呼吸、主标题不被挤小"。

**英文叠加层规则**（montage 的灵魂 -- OVERSIZED GHOST-WATERMARK 模式）：
- 内容：跟文章主题相关的 2-3 个英文关键词，用 `×` 符号连接（如 `WHITE SUV × LANE CHANGE` / `RESEARCH × EVIDENCE × MIRROR`）
- 颜色：极深灰 `#1F1F25`（**绝不能太亮 -- 几乎与背景融合**），ghost watermark 感
- 字号：**~155% 的中文 L1 字号**（明显比中文标题大，撑满文字区横向宽度）
- 位置：**坐在中文标题块的"后面"**。英文文字从顶部延展下来，BOTTOM 30-40% 的英文字母与中文 L1 顶部 30-40% **垂直重叠**（英文字母的下部笔画区域被中文字遮挡）
- Z-order：**英文在后，中文在前**（中文不透明白字压在英文上）
- 渲染效果：**gradient mask 下部羽化** -- 英文字母顶部 opacity ~80%，到底部渐变到 ~10%（下部"消融到背景里"的水印效果）
- 字间距：letter-spacing 0.05em，BOLD SANS UPPERCASE
- 整体气质：oversized 半透明英文水印坐在中文加粗标题后面，提供"项目代号 + 立体感"层次，不抢戏
- 🔴 **禁止把英文叠加层做亮**：亮了就变成"两个标题打架"。如果可以毫不费力地一眼读出来就是太亮了
- 🔴 **禁止用 small + tight stack 的旧排法**（85% 字号 + 紧贴 10px gap 上方）-- 统一改用 oversized ghost 模式

**中文标题渲染铁律**（踩坑）：
- 🔴 **L2 必须单行渲染**：不论 L2 字数 12-15 字，必须单行不拆。中间的逗号是标点不是断行点。
- 🔴 **不要在 prompt 里用 `<green>...</green>` 这种 XML markup 标记主题色区段** -- 生图工具会把它当成断行点，导致 L2 拆行 + 字符重复。改用纯描述：「前 N 个字符 in pure white #FFFFFF，后 M 个字符 in PRIMARY #2F6F8F」
- 末尾主题色区段一般是 4-7 字（最锋利的判断 / 反差词 / 数字）
- 🔴 **L1/L2 字重落差**：L1 用最重字重（extra-bold / black，主结论）、L2 降一档（bold / semibold，补充语境），靠字重差立主次，严禁 L1=L2 同字重一刀切（与 [iron-rules · 封面图文字样式铁律第 7 条](iron-rules.md) 一致）

**右侧拼贴层（关键差异化）**：

主物件（右列唯一"大件"，占右列高度 55–65%、宽度 45–55%，垂直居中略偏上：顶 ~15% 留暖光入射、底 ~20% 留最近一枚徽章）：

🔴 **主物件 = 论点的具象化（隐喻判据）**：不是随手放个科技图标，而是把文章核心论点/反差用 **1–2 个有语义的元素**拼成一眼能读懂的具象隐喻--优先"物件本身就在演绎论点"（后视镜=被超越、被推走的起跑线=起跑线被挪走、复盘类=镜子/倒影、安全类=钥匙+锁、连接类=桥）。命题复杂时用「icon A + icon B」组合（放大镜+数据点=洞察、灯泡+齿轮=创新工程）。**自检**：遮住标题只看右侧主物件，能否猜到文章在讲什么？猜不到就重选。红线：宁选稍俗但秒懂的具象物件，不选抽象到缩略图认不出的几何体。

视觉规格：flat-vector 主题色描边（**bold 档描边 2px**）+ slightly 三维斜视角 + 不上真人。**薄体积质感**：保持平面调性但加一层薄体积--同色相柔投影（主题色压暗版、朝右下、与左上暖光向一致、blur 重不锐利）+ 受光面一道极克制的主题色微高光（≤15% 提亮，不引入白光斑），目标"扁平但有重量"，根治"物件像贴纸/单薄"（根因=纯平涂缺质感，非白底）。严禁真实 3D 渲染 / 金属反光 / 写实材质。

信息徽章 / 卡片（2-3 个，围绕主物件浮动）：
- 🔴 **统一用「黑底 `#1A1A1A` + 主题色 1px 描边」圆角徽章**，绝不混用白底卡片（踩坑：白底卡在深色背景上权重过重 + 内容空时像异常贴纸 + 跟其他黑徽章不协调）
- 圆角 6px，徽章内部用主标语 + 副标语两层
  - 主语：大字（数字 / 关键词）-- 可上主题色强调
  - 副语：小字（说明 / 单位）-- 纯白
- 内容必须有信息密度（不能只写一个空名词）：
  - ✅ 好示例：`× 2 倍` 主 + `事故风险` 副 / `+67%` 主 + `换两次队` 副 / `4h` 主 + `打通` 副
  - ❌ 反例：`Nature 1999` 单字段（信息过空，应改成 `Nature 1999` 主 + `权威结论` 副 或更具体）
- 徽章之间略微重叠摆放（前后层次感）

虚线箭头：
- 1px 主题色虚线，60% opacity
- 2-3 条，从徽章指向主物件（"证据指向结论"的视觉语义）
- 不要画成直线 -- 略微弯曲带弧度

🔴 **右侧拼贴单焦点律**：右列有且仅有**一个统治性主焦点 = 核心隐喻主物件**（视觉权重最大、最居中、主题色描边最实）。2-3 个黑底徽章一律降为"辅助佐证"级--尺寸 ≤ 主物件 40%、描边更细、不得与主物件等大或更抢眼；虚线箭头与微光只能是点缀。**自检**：眯眼看右列，第一眼落点必须是主物件而非某个徽章--抢戏就缩小徽章 / 降数字字号。徽章不得放在主物件正上方压它，环绕其下方/侧方浮动。

**徽章质感升级**：黑底 `#1A1A1A` 徽章在 1px 主题色描边（bold 档 2px）基础上，可加极克制的主题色内边缘微光（≤20%，沿描边内侧，不外溢成 glow 球）+ 朝右下同色相柔投影，做"卡片悬浮在背景前"的抬升；严禁白色 / 彩色发光、外溢光晕球、玻璃反光。

**三种亚型（按文章调性切换，写在 cover prompt 时拼入）**：

| 亚型 | 主物件类型 | 徽章语义 | 英文叠加层风格 | 背景 | 适合题材 |
|------|----------|---------|--------------|------|---------|
| `montage-evidence` | 文章核心隐喻物件（如后视镜 / 棋盘 / 货架） | 学术论据 / 反差数据（× 2 倍 / +67% / Tier 1） | `RESEARCH × EVIDENCE × KEYWORD` | 深炭 `#0E0E10` + 单束暖光 | 学术论据多 / 反差观察 / 决策学 |
| `montage-pipeline` | 应用 / 终端 / 工作流主界面 | 数据节点 / 时间徽章（4h / 跨平台 / 私厨） | `TOOL × DATA × OUTCOME` | 深炭 `#0E0E10` + 单束暖光 | 工具评测 / 产品介绍 / 教程 |
| `montage-starry` | 高密度物件群（如书堆 / 文档堆 / 知识塔） | 蒸馏数量 / 跨域统计（33 本 / 1000 万 tokens / 8 大学派） | `DEEP DISTILL × N × KEYWORD` | **近黑 `#05060A` + 满屏银河 + 单束暖光** | 跨学科蒸馏 / 高概念 / 仪式感发刊 / 宏大叙事 |

**氛围关键词**：editorial montage、information density、layered depth、project briefing、tools-on-the-table

**注意**：
- 不上真人 / 不上头像 / 不上手 -- 拼贴元素 only
- 双色铁律加强：黑 + 主题色 + 纯白 + 黑徽章底色 `#1A1A1A`，仅此 4 色
- 留白 35-45%，不堆满

## montage-starry 亚型扩展定义

> 仅在背景与几个关键约束上偏离主线 montage，其余（左 50% 文字区 + 6% 间隙 + 右 44% 拼贴区、英文叠加层、emoji 胶囊、徽章、虚线箭头）**完全沿用 montage 主框架**。下面只列差异。

**背景规则（覆盖主线 BACKGROUND 段）**：
- 主底色：**近黑 `#05060A`**（比深炭 `#0E0E10` 更冷更黑一档）
- **满屏星空** + **斜跨银河带**：
  - 星点：白色 1px 微星 pin-pricks 散布全画布，密度上密下疏，亮区在右上和中部，左下/文字安全区（emoji 胶囊周围）密度降低
  - 银河带：从左上斜向右下穿过画面，宽 ~30% 画面高度，**透明度 35-40%**，颜色 cool-gray-blue（neutral 不偏紫红），高斯虚化重，绝不锐利
  - 整体星空亮度 ≤20% 灰度等价，前景文字仍 100% 清晰可读
- 单束暖光：从左上角斜照下来，落在右侧拼贴区，主题色 `#2F6F8F` 微染色 ≤12% opacity -- **叠在星空上方**作为方向性渐变
- 留白 35-45%（星空虽满但因为整体偏黑，仍计入"安静空间"）

**严禁**（覆盖主线 STRICT BANS 中的星空相关条目）：
- 严禁亮星 / 星芒 / 镜头光斑 / 卡通眨眼星点 / 彗星拖尾
- 严禁紫红蓝青等彩色星云 -- 银河必须保持 neutral cool-gray
- 严禁明月 / 行星 / 卫星 / 星座连线
- 星空若与文字争夺视觉权重 -- 当场降低相应区域的星点密度

**胶囊**：默认走 `quiet-pill` 模式（近底色 `#0A0B10` ~ `#0C0D12`，无描边无阴影）-- 星空背景细节本就丰富，bright-pill 会进一步提高视觉密度，调性不对

**英文叠加层**：内容用 `DEEP DISTILL × N × KEYWORD` 结构（N 通常是文章蒸馏的数量级，KEYWORD 是核心动作）；其余规则与主线 montage 一致（OVERSIZED GHOST-WATERMARK 模式：极深灰 #1F1F25 + ~155% L1 字号 + 下部羽化 + 与中文 L1 顶部 30-40% 重叠 + 中文压在英文前方）

**适合题材**：
- 跨学科蒸馏（N 本书 / N 篇论文 / N 种工具浓缩成一张图）
- 高概念 / 宏大叙事 / 学术权威感
- 仪式感发刊（年度收官、首发系列、跨年特辑）
- ❌ 不适合：日常工具速递、横评、轻量教程 -- 调性会"用力过猛"

**频率上限**：建议 ≤10%（每 10 篇最多 1 篇用 starry，避免仪式感被稀释）

**踩坑教训**：
- 一开始让生图模型自由画"满屏银河"很容易跑偏成"科幻片宣传海报"，用力过猛抢主标题。prompt 里必须显式压住：`overall sky luminance ≤20% gray`、`Milky Way faint ≤40% opacity`、`stars never burst, never flare`、`reduce stars where they compete with text`
- 银河方向选 **左上→右下**，与暖光束方向一致，避免双方向冲突
- 物件群需要更高密度（书堆 / 文档堆 / 节点群）-- 单一隐喻物件在星空背景下显单薄
- 还试过一种"角落星空（中心保持纯黑）"亚版本，效果与纯炭灰几乎无差，星空几乎看不出 -- 故 starry 走"满屏"一种，不留 reserved 备选

## 选择机制

### 1. 默认：montage-evidence

**新文章默认走 `montage-evidence`（中文 L1+L2 + 后方英文 OVERSIZED GHOST 半隐水印的签名视觉）。** `article-meta.yaml` 的 `cover_style` 留空即默认此风格。想改全局默认改 `profile/brand.yaml`。

### 2. 例外：显式覆盖

需其他风格时，在 `article-meta.yaml` 显式填 `cover_style:`（如 `briefing` / `noir` / `montage-pipeline` / `montage-starry`）。

### 3. 写 cover.md 时

按选定 style，从本文件取对应段落的"骨架 + 视觉主体 + 文字排布"描述，拼入 cover prompt 的 LAYOUT 和 VISUAL 部分。共用的底层铁律（品牌色/文字层次/留白）由 [iron-rules.md 封面图文字样式铁律](iron-rules.md) 保证，不重复写。

🔴 **cover.md 固定命名骨架**（顺序不可乱，每段必带命名标题，缺段视为 prompt 不合格）：先写 frontmatter（`type: cover` / `aspect: 2.35:1` / `palette: dark-charcoal` / `model: gemini-3-pro-image-preview`），正文按固定顺序分段--① **CONTENT CONTEXT**（原标题 + 2-3 句摘要 + 3-5 关键词，封面四件套落地，主物件/徽章/ghost 都从这里推导）② **LAYOUT**（左 50% 文字 / 右 44% 拼贴 / 6% 间隙）③ **TEXT ELEMENTS**（英文 ghost + 中文 L1 L2 + quiet-pill 三件套）④ **RIGHT COLLAGE**（主物件 + 黑底徽章 + 虚线箭头）⑤ **COLOR & BACKGROUND**（深炭 #0E0E10 + 主题色 #2F6F8F + 纯白 + 方向性单光源）⑥ **STRICT FORBIDDEN**（见 iron-rules 必带锚句清单，含 hex 不入图）。把"决策字段"（frontmatter）与"描述 prose"分离，换 agent / 换篇出图一致、可机检。

## 🎨 封面阶段生成

封面阶段 = 按选定风格（默认 montage-evidence）模板**生成单张** `素材/cover.png`（`2.35:1` cinematic、1K 长边 ≈1024px、深色底 + 主题色、文字在侧、右下角禁品牌识别文字），走 `scripts/gen_img.py`。仅当 `article-meta.yaml` 显式填非默认的 `cover_style` 时，才生成那一种**指定**风格。
