# 封面规则

新文章默认且唯一推荐风格是 `montage-evidence`。历史风格仅用于复刻旧文章，必须由 `article-meta.yaml` 显式声明；自动流程不得随机轮换。

## 固定合同

- 比例 `2.35:1`，长边至少 1000 px。
- 信息来自定稿，不凭空增加人物、数字、Logo 或结论。
- 标题、副标题与两个标签必须由生图模型在同一次请求中随画面原生生成；禁止 SVG、
  本地字体、无字底图后期补字或“为防错字”拆分文字层。
- 深炭 `#0E0E10` 统一画布；只允许 profile 主色与纯白作为前景色。
- 左侧 50% 为主标题区，中间 6% 呼吸区，右侧 44% 为内容证据拼贴；保留 8% 微信裁切安全区。
- 标题块总高度上限为画面高度的 22%。
- 主标题优先读取 `article-meta.yaml:lead.line1`，`lead.line2` 是副标题；
  不得把两行做成同字号、同字重的“八个字一坨”，也不得把文章外标题整句重新塞进封面。
- 人物、品牌或作品是主题时，`cover_identity` 必填并必须直写进 L1/L2；底部小标签不算。
  仍只保留两行标题和两个标签，不新增第三层文字。
- 🔴 **关键词锚点与外标题有意重复，L1 就写它**（`爱因斯坦传` / `曾国藩传`）。很多读者只看图，
  图上没有这几个字就不知道这是谁的什么。**不许重复的是「那一句」**：L2 与外标题冒号后那句
  必须来自不同填法、不共用主要实词（外标题给原话，L2 就给数字 / 物件）。分工与验收见
  [title.md §封面与外标题怎么分工](title.md)。
- 标题后方只允许低对比抽象线条与图形，不生成英文 ghost、水印字或随机字符；右侧只允许一个主隐喻物件与 2--3 个次级证据徽章。

## 🔴 右区主视觉：先让读者认出主体，再谈美感

作者反馈（2026-08-28）：右区经常是抽象隐喻或与正文偏离的图形，**读者看不出这篇说的是乔布斯还是曾国藩**。
封面缩略图很小，一张能辨认的脸或一件标志性实物，识别效率远高于任何抽象构图。

**主视觉优先级（自上而下，首个可用即定）：**

| 档 | 主视觉 | 判据 | 现在能不能做 |
|---|---|---|---|
| 1 | **真实肖像裁切**（有明确人物主角时） | 公有领域或已授权的真实照片 / 画像，**裁头肩**、不用全景 | ⏳ 需下方「肖像槽位」工程支持 |
| 2 | **标志性实物证据** | 缩略图尺寸下能一眼归因到主角：家书书页、手稿、签名、他用过的物件、该品牌的产品实物 | ✅ 今天就能做 |
| 3 | **符号组合**（非人物的主旨类） | 至少 1 件标志性产品实物打主体 + 至多 2 个次级徽章；**国旗、地图、抽象箭头只能当弱化背景元素，不许单独承担主体** | ✅ 今天就能做 |
| ❌ | 抽象隐喻当主体 | 抽象几何、光效、概念拼贴做主视觉 -- 这正是「认不出主体」的病根 | 禁 |

**档 3 举例**（主题：日本制造业空心化）：主体放**一台机床或一节新干线车厢的实物特写**，
次级徽章放两个可核数字（产量、份额）。不要放国旗 -- 国旗只说明"关于日本"，
不说明"关于制造业"；品牌 logo 拼贴要留意商标使用边界，且多个 logo 并列会让主体散掉。

🔴 **禁止 AI 生成相似人物肖像**（同 iron-rules §视觉 4 与 image-routing.md）：不许把真人照片喂给
生图模型重绘成粘土风或任何风格化肖像 -- 出来的是「像又不像」的假脸，对活人是失真，
对历史人物是伪造史料。人物类封面**要么用真实肖像（档 1），要么退到实物证据（档 2），没有第三条路**。

### ✅ 已落地：真实肖像满幅出血（`portrait-bleed`）

版式由 2026-08-28 的两轮实拍对照定案（13 张真图，作者逐版选定）。**声明 `cover_portrait.file`
即自动走这条路线**：`_cover_prompt` 把 style 切成 `portrait-bleed`、右区改成留空场，
`scripts/cover_portrait.py` 在渲染之后把真实肖像确定性合成进去。

**版式规格**（改版式改 `cover_portrait.py` 顶部常量，别在别处各写一份）：

| 项 | 规格 | 为什么是这个数 |
|---|---|---|
| 肖像位置 | **顶右、顶上、顶下三边满幅出血**，无描边、无边框、无留白 | 描边和四周留白都在跟肖像抢注意力；实拍对照后作者选定此形 |
| 照片区宽度 | **按肖像自身比例反推**：`宽 = 画布高 × 肖像宽高比`，夹在画布宽的 26%--40% | 🔴 铺满整高时若照片区比原图更宽，就**必须裁掉上下** —— 实测直接切掉发顶和下巴。反推之后免垂直裁切 |
| 色彩 | 暖调映射：暖炭 `#221B17` → 暖象牙 `#FCF6EA`，gamma 0.92，对比 1.16 | 纯黑白肖像压在深炭底上偏冷（作者原话：像墓碑）。**不做 AI 上色** -- 给历史人物上色等于编造肤色眼色 |
| 左缘 | 60px 线性渐隐 | 硬切会在画面中间留一条竖线；渐隐让照片融进左区底纹 |
| 左区 | 保留低对比底纹：长曲线 + 一条淡折线图 + 细网格 + 1--2 个柔和几何形，6%--12% 对比 | 作者点名要保留；已写进 prompt，不再靠碰运气出现 |

**必须先清场**：贴图前把右区抹回环境渐变。prompt 已明写「右区留空、不要画板」，
模型照旧会画一块圆角面板 —— 照片起点比它靠右时，板的左边缘会露出来像叠了两层。
抹的取样列必须落在**纯背景**上（取最右侧 40 列的逐行中位数）；早先版本取画面中部一列，
撞进标题笔画，从字里拖出一条横线穿到右边。

**声明**（`article-meta.yaml`，缺 `source` 或 `license` 直接拒绝合成）：

```yaml
cover_portrait:
  file: "素材/portrait-src.jpg"   # 相对文章目录或绝对路径
  source: "馆藏页 / 档案编号 / 页面 URL"
  license: "公有领域（依据）或已授权（凭据）"
  credit: "需要署名时写在这里"      # 可空
  anchor: [0.45, 0.34]             # 脸部中心占原图比例，可空（默认值同此）
```

**运行顺序**（插在渲染与打水印之间）：

```bash
python "$SKILL/scripts/pipeline.py" render-visuals
python "$SKILL/scripts/cover_portrait.py" <文章目录>      # 声明了才做，未声明自动跳过
node "$SKILL/scripts/add_logo.js" "素材/*.png"
python "$SKILL/scripts/compress_images.py" 素材
python "$SKILL/scripts/pipeline.py" visual-qa
```

**边界（不许越）**：这一层只允许贴**真实且可追溯**的人物照片，且只贴在右区照片位。
不得用它贴任何文字、标签、logo 或图表 —— 封面上的字仍然必须由生图模型原生生成
（iron-rules §视觉）。不得把真人照片喂给生图模型重绘。

**什么时候不用它**：主角没有可用的公有领域 / 已授权肖像；或那张肖像是旧式黑白遗照观感强烈
（实测曾国藩的晚清肖像即属此类，作者判定不放）。这两种情况回到档 2 的标志性实物路线。

### 🔴 字号层级（锚在画布上，不是相对 L1）

**必须给 L1 一个画布级锚点。**只写“L1 是 100% 基准、L2 是它的 55%--65%”不够 --
那套百分比是自我参照的，模型可以把 L1 定成任意大小、整组等比缩掉。2026-07-28
对照四张实拍封面：同一份 prompt 跑出过 L1 占画幅高 12%（第 76/80 篇，主体感强）
和 8%（第 81 篇，画面没有主体）两种结果。

| 元素 | 尺寸 | 颜色 | 说明 |
|---|---|---|---|
| **L1 主标题** | **cap height = 画布高的 12%--14%**，行宽占左区 70%--90% | 纯白，最重字重 | 全画面唯一主体；任何其他高对比文字都不得比它大 |
| L2 副标题 | L1 cap height 的 **58%--64%** | 白 + 落点词主色 | 单行 |
| descriptor 胶囊 | L1 cap height 的 **30%--34%** | 低对比 | 不与标题争 |

### 🔴 主题色落点（只染一处）

- **只在 L2 里染色，只染收尾的 2--5 个字**（语义落点，如「抢老人」「看得见」「一张日历」）。
- **L1 一个字都不染。**它靠字号称王，再染色会把唯一的视觉焦点拆成两个。
- 落点词由 `article-meta.yaml:lead.accent` **显式指定**；缺失或不是 L2 的 2--5 字结尾子串，
  编译器直接拒绝。禁止让生图模型自己挑，避免同批封面的落点漂移。
- 除 profile 主色外禁止任何彩色。第 79 篇把落点染成蓝色，是直接违反品牌色的事故。

### 🔴 字数（只卡上限，下限不设）

L1 cap height 取 13%（1024×436 画布 ≈ 57 px），左区去掉留白可用宽 ≈ 460 px，
汉字视觉宽 ≈ cap height，故上限 ≈ 8 字。

- **L1 = 4--7 个汉字位**（数字与半角字符按 0.5 折算），**硬上限 8**
- **L2 ≤ 12 个汉字位**

**上限是硬的**：超了模型只能缩字号，规范再严也压不住。
**下限不设**：四字标题（第 80 篇「生意变了」）是 sandy 明确认可的范例 --
**能四个字说清就四个字，不要为了凑字数注水**。6--7 字是舒适上沿。

字数在标题阶段就定，见 `title.md`。

### 🔴 底部品牌胶囊（辨识度的主要来源）

2026-07-28 sandy 拍板：她认可的两张封面（第 76、80 篇）里，L2 下方那条标签胶囊
是**封面辨识度的主要来源**，要固化。

- 位置：紧贴 L2 下方，左区内，**单行不换行**
- 底色：**profile 主色 @ 78%--85% 不透明**（满色 100% 太抢眼，会跟 L1 争焦点）
- 质感：**哑光磨砂** = 半透明 + 极细颗粒。无边框、无发光、无投影、无高光条、无镜面反射、无渐变光泽
- 内容：**恰好 2 个短标签**，细竖线或斜杠分隔，纯白文字，字号为 L1 cap height 的 30%--34%
- 数据源：只读 `article-meta.yaml:lead.tag1` 与 `lead.tag2`；两项都必填、各 ≤ 4 个汉字位且不得重复。
  `lead.subtitle` 属于文章导读，不进入封面。

> ⚠️ **「磨砂」不等于「毛玻璃」。**「STRICT FORBIDDEN」里的 `glassmorphism` /
> `glossy reflections` 全图依然有效。这里要的是半透明哑光，**不是**玻璃按钮那种
> 高光条 + 镜面反射 + 彩虹边 —— 两者混淆会直接渲成廉价的 UI 控件。
- 禁止真人、照片拼贴、亮色底、底部标题条和居中海报式大标题。
- 禁止把 `largest` / `extra-black` / `ultra-black` 写进 canonical prompt。
- 默认 `quiet-pill`：低对比副标题胶囊，不使用高饱和霓虹。

## 内容提炼

封面必须从定稿提取：

1. 一句主标题。
2. 可选的一句副标题。
3. 2--4 个可视化事实或物件。
4. 不应出现的文字与元素。

这些值写入 `visual-plan.json.cover`，再由 `compile-visuals` 编译；模型不得直接自由发挥最终 prompt。

## 验收

独立视觉 QA 至少检查：

- 标题与副标题逐字一致。
- 无意外杂字、伪 Logo、乱码。
- 主标题清晰但不过度粗黑。
- L1/L2/descriptor 主次一眼可辨，不得三行等权。
- **L1 必须是全画面视觉主体**：缩略图尺寸下第一眼落在 L1 上。若 L1 与 L2 看着
  差不多大，或背景杂字先抢走注意力，一律判不通过 -- 这是 2026-07-28 前最常见的漏检项
  （第 79、81 篇都是两行等权却过了闸）。
- **主题色只出现在 L2 的落点词上**；L1 染色、两行都染、或出现非品牌色，判不通过。
- 裁切安全，右侧拼贴不抢标题。
- 实际像素符合深色品牌构图，不得以“同批图片风格一致”代替目标风格核验。

封面规则的机器实现位于 `scripts/visual_workflow.py`、`pipeline.py` 和 `visual_qa.py`；本文件不再维护第二套可执行参数。
