# 风格路由机制

> 正文写作开始前，根据大纲顶部的 `[目标风格：XXX]` 或 `[目标风格：XXX·子模式]` 标签，**只读取对应的一套风格手册，跳过其余路由**。
>
> 本文件讲的是「风格路由」这套机制怎么运转 -- 具体的作者风格招式**不写在本仓库里**，而由你在自己的 profile 语料层自建（见 [profile/corpus/authors/README.md](../profile.example/corpus/authors/README.md) 的 HOW-TO）。本仓库只带一份虚构的示例手册 `example-author` 供你照着建自己的。

---

## 一、风格标签的三段结构

大纲顶部的风格契约由三部分组成，写作时严格对齐这三者：

1. **主路由（单选，必填）**：`[目标风格：<手册名>]`，指向 `profile/corpus/authors/<手册名>.compact.md` 里的一套执行手册。任何一篇只挂**一个**主路由。
2. **子模式（0-1 个，可选）**：主路由手册内部若定义了子模式，用二级标签 `[目标风格：<手册名>·<子模式>]` 指定，如 `[目标风格：example-author·散文]`。子模式在同一套手册内做细分（题材/人称/篇幅不同），不跨手册。
3. **文体（三选一，与主路由正交）**：`[文体：深度文 / 教程文 / 方法论清单文]`。文体决定骨架差异（见 [writing-genres.md](writing-genres.md)），与风格路由**叠加**生效 -- 同一套风格可以套不同文体。

> 例：`[目标风格：example-author·时评]` + `[文体：深度文]` = 用 example-author 手册的时评子模式，走深度文骨架。

---

## 二、风格手册从哪来（BYO 语料）

**本仓库不预置任何真实作者的风格手册。** 风格路由的执行细节全部来自你自建的 profile 语料层：

- 手册路径：`profile/corpus/authors/<name>.compact.md`（约 500 字的执行手册：招式 + 句式 + 反例）
- 示例：仓内自带 `profile/corpus/authors/example-author.compact.md`（虚构作者，演示手册结构，可直接照抄改写）
- 建法：见 [profile/corpus/authors/README.md](../profile.example/corpus/authors/README.md) 的 HOW-TO -- 讲清一份 compact 手册该有哪些字段（激活条件 / noise-filter / 节奏特征 / 开篇技法 / opt-out 豁免清单 / 节奏示例）
- 无自备手册时：不挂主路由，写作退回仓内原创的基础人味兜底样本（`profile/corpus/voice-samples.md`），保证文章不至于是纯 AI 腔。

---

## 三、手册的标准字段（照 example-author 建你自己的）

每一份 `<name>.compact.md` 建议包含以下字段，写作期主 agent 会逐字段读取并落实：

- **激活条件**：大纲标注哪个标签时激活本手册（如 `[目标风格：<name>]` 或某个中文别名）。
- **noise-filter（训练语料排除）**：当你为这套风格搜集语料时，要排除哪些「不是作者亲笔」的污染源 -- 典型三类：团队代笔的日课/日更、带商品/课程链接的软广推广文、头衔挂名的访谈通稿。**理由**：直接把全集语料喂进去，模型会沉默漂移成「代笔版」而非作者本人的语态。这是 BYO 语料时最容易踩的坑，务必在手册顶部显式声明排除项。
- **节奏特征**：这套风格的句子/段落/设问/收尾节奏（8-10 条可 verify 的硬特征）。
- **开篇技法**：头几句怎么进场（是否亮观点、是否讲故事、是否直入事实）。
- **opt-out 豁免清单**：本风格对通用规则（[writing.md](writing.md)）的**覆盖项** -- 例如加粗密度上下限、单段行数、是否豁免某些黄名单词、是否豁免全文 BLOT。风格规则与通用规则叠加生效，但豁免清单**覆盖**通用规则。
- **节奏示例**：3-5 行手写示范，给模型一个可对齐的语感锚点。

> 参照 `profile/corpus/authors/example-author.compact.md` 看这些字段长什么样，再替换成你想模仿的写作者的招式。

## 四、可叠加技法库（modifier，跨路由借用）

除了单选的主路由，你还可以在 profile 语料层维护一批**可叠加技法**（modifier）：它们不作为主路由单独激活，而是在主路由之上叠加 0-1 个，借用某个局部技法（如某种开场式、某种金句收尾、某种设问节奏）。

- 存放约定：同样放 `profile/corpus/authors/` 下，在手册顶部注明「这是 modifier，不单独作主路由」。
- 借用规则：**完整借用，不许只借名字**。借一个技法就要把它的可 verify 特征整套落实，否则等于没借。
- 叠加上限：一篇最多叠 1 个 modifier，避免风格互相打架。

## 五、🔴 手册缺失时铁律（显式失败优于静默漂移）

大纲挂了 `[目标风格：<name>]`，但 `profile/corpus/authors/<name>.compact.md` **不存在**时，`prep_writing.py` 会在「缺失项」清单 + `_prep-context.md` 正文里标记「未找到 compact」。此时**必须显式停止，不得用相邻手册顶替**，二选一：

1. **创建对应手册**（照 README HOW-TO 产出 500 字执行手册）；
2. **显式切换到另一路由**（改大纲顶部 `[目标风格：X]` 标签 + 同步改 `article-meta.yaml` 的 `style` 字段）。

**严禁主 agent 自行 fallback 到相邻手册**（如「A 手册缺 → 用 B 手册顶」）-- 三标签风格契约要求路由、手册、产出三者严格对齐，任何静默替换都视为契约违反，旁观者复盘会判失败。

## 六、示例手册：example-author

仓内 `profile/corpus/authors/example-author.compact.md` 是一份**虚构**的完整手册，演示上面所有字段。它约定的标签是 `[目标风格：example-author]`，支持一个子模式 `[目标风格：example-author·散文]`（散文子模式把加粗密度降到 0-3 处）。

拿它做起点：复制一份，改名成你要模仿的写作者，逐字段替换招式，就得到你自己的一套风格路由。**不要把 example-author 直接用于正式产出** -- 它只是脚手架。

---

## 七、使用说明

正文写作时：
1. 从大纲顶部读取 `[目标风格：XXX]`（或子模式标签 `[目标风格：XXX·YYY]`）+ `[文体：...]`。
2. 到 `profile/corpus/authors/<XXX>.compact.md` **仅读取这一套手册**，其余跳过；手册不存在则走第五节铁律。
3. 手册里的风格规则与 [writing.md](writing.md) 通用规则**叠加**生效，但手册的「opt-out 豁免清单」**覆盖**通用规则。
4. 文体骨架差异见 [writing-genres.md](writing-genres.md)，与风格路由正交叠加。
5. 无自建手册时不挂主路由，走 `profile/corpus/voice-samples.md` 基础人味兜底。
