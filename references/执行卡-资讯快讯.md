# 执行卡：资讯快讯

写资讯快讯前只读这一张；出处指向原文章节，拿不准时回原文查。

## 一、适用范围与开工

- 资讯快讯写刚发布的模型、产品或大事件，作者没有亲测背书，对外分类 `news`。三款以上的横向合集归「精选」，作者亲测或自己做的归「分享」，面向新手的系统教学归「教程」（出处：title.md §定分类标签前缀；outline.md §步骤 3.5）。
- 建目录用 `python "$SKILL/scripts/pipeline.py" new "<选题名>" --genre news`，不复制上一篇的 article-meta。它预填分类与直入开篇，默认 `infographic_mode: author-shots`：不出信息图，正文至少引用 4 张作者供图（出处：autopilot.md §主流程；layout.md §输入）。
- 动笔前跑 `prep_writing.py`，否则排版被拦（出处：writing.md §写作前第一步）。

## 二、首屏速查区

正文第一段直入下判，紧接一张两列速查表，再进第一个 H2（排版后在导读栏下方）：

| 速查 | 某模型 X |
|---|---|
| 发布 | 北京时间 3 月 5 日 1:30（UTC 4 日 17:30） |
| 价格 | 输入 3 / 输出 15 美元每百万 token，上代 4 / 20 |
| 判断 | 编程追平上代旗舰，长任务仍差一档 |
| 适合谁 | 用它写代码的先试；只聊天的不必换 |

- **和结论先行的关系**：第一句照样下判，表不替代它；表里的判断是同一判断的短版，不另起结论，结尾不再复述。开篇文字压到一段：发生了什么、判断、最关键的依据（出处：writing.md §三条直球守则）。
- **四格**：时间写北京时间并括注原始时区；价格写官方价、单位、档位，附上一代或对手的同档价；判断是事实加态度，限定到什么任务、和谁比；适合谁写清谁该试、谁不必动（出处：fact-check.md §核什么；craft-techniques.md §限定词三维度）。
- **组件**：两列 Markdown 表格，每格约 20 字；几款同夜发布就按款分行。这种左短右长的两列表默认会被转成术语卡、表头丢失，要保持表格就在 meta 的 `table_widths` 首组填 `[22, 78]`（出处：wechat-compat.md §表格规则；layout-reference.md §后处理脚本说明）。不用「划重点」卡，它不进开篇区（出处：writing.md §视觉节奏标记）。

## 三、证据规范

四类分开写，每个数字和判断都说得出属于哪一类（出处：material-integrity.md §来源类型；fact-check.md §核什么）：

- **官方口径**：价格、规格、开放范围回官网文档核；「追平某某」「便宜四成」这类能力说法是自述，写「官方说」。
- **第三方实测**：写清机构、档位、题集；只在同一把尺子上比，自测和他测的数字不横比（出处：craft-techniques.md §证据四评估）。
- **网友反馈**：只证明有人这样用到，不证明多数；写明收稿时间，如「原帖收到北京时间 X 点前后」。
- **作者推断**：写「我判断」并交代依据；没亲测不写「我试了」（出处：material-integrity.md §细节真实性）。

**推文取证**：`python3 "$SKILL/scripts/tweet_evidence.py" <推文URL…> --out <文章目录>/素材`。它取全文与 UTC 时间并换算北京时间，截嵌入页图 `shot-tw-*.png`（算作者供图），输出 `tweet-evidence.json` 与 `推文证据.md`（出处：image-routing.md §是否应当生图）。它不判员工身份，也不抓浏览量：`employee` 核实后手工回填。

- 引网友原话标账号、身份（员工、合作方等写明利益相关）、北京时间和链接，链接进 SOURCES；浏览量、点赞从推文页读，写「截图时约 N 次浏览」，只作热度参考，不作结论依据（出处：anti-ai-filter.md §8.2 Prove It；craft-techniques.md §证据四评估）。

**「当夜原话」段**：

- 挑有具体场景、对比、数字或踩坑的帖子，纯情绪不单独成条（出处：content-enhance.md §策略四）。
- 每条是原话或忠实转述，加一句作者点评：它能证明什么、不能证明什么（出处：material-integrity.md §材料与推理分账）。正反都收（出处：craft-techniques.md §律师 vs 侦探）。
- 条数不设上限，取舍看新增：每条要带来新的场景、对比或数字，同义只留最具体的一条；并列满三条就插一段推进或小结，段末收拢成几条站得住的观察（出处：material-integrity.md §逐段信息账本；writing.md §段落间关系）。

## 四、结构

- **标题**：`资讯 | <专名+属性词>：<一句由正文主干兑现的话>`，冒号后按原话型、具象型、处境型的顺序选，不用悬念、反差、卖关子（出处：title.md §唯一公式；title.md §只能是这四种之一）。例：`资讯 | 某模型 X 发布：编程追平上代旗舰，价格降四分之一`。
- **开篇**：直入，第一句说发生了什么并下判；不讲故事钩子、不铺概念、不先讲个人经历，要解释它是什么就一句话讲清。骨架用 ASC 答案先行，`new` 已预填（出处：outline.md §步骤 3.5）。
- **H2**：只写纯标题，增删时同步改 `part_subtitles`（出处：writing.md §Markdown 输出规范）。按本篇核心问题挑骨架，不照抄上一篇的 H2 名称和顺序，连续几篇同一结构，模板感很重（出处：outline.md §内容骨架匹配；writing.md §近 3 篇）：
  1. 证据分层型：官方说了什么 → 第三方怎么测 → 当夜原话 → 怎么用。适合官方说法需要检验时。
  2. 问题驱动型：每节答一个读者问题（贵不贵、强在哪、要不要换），节内四类证据按标签混排。适合一两个问题就决定去留时。
  3. 场景分派型：按用途分节（写代码、长任务、聊天、API 跑量），每节给用不用和依据。适合不同读者结论不同时。
- 每个 H2 至少一个可带走的信息块；全篇三件套齐：官方数据加一句白话、与上代或对手的具体差异、读者能照做的建议（出处：writing-genres.md §技术解读文）。
- **结尾**：先做删除测试；收尾类型按 profile 白名单 `writing.closing_types_allowed` 选，写进 meta 的 `closing_type`；开了 `closing_no_question_ending` 时最后一段不能是问句，preflight 会查。默认冷收，落在动作或判断上（出处：anti-ai-filter.md §1.5 收尾菜单；craft-techniques.md §结尾技法）。

## 五、逐段写法

- **三条直球**：简洁，每节先结论，不设悬念，也不预告「后面会看到」（出处：writing.md §三条直球守则）。
- **材料先承重**：每个 H2 至少对上一条原图、文档、第三方测试或具名原帖，对不上就合并或删节（出处：material-integrity.md §材料闸门）。
- **来源不过界**：发布时间挨着不等于抢发，「推迟是因为……」没有当事人原话就是猜测（出处：material-integrity.md §来源类型）。
- **逐段有新增**：每段推进事实、动作、例子、区分、后果之一，同一判断不在开篇、中段、结论各说一遍（出处：anti-ai-filter.md §3.1 信息密度）。
- **句间引力**：上句句尾的新信息在下句句首接住；几组跑分数字连排时，中间插一句白话（出处：writing.md §句间引力；writing-genres.md §技术解读文）。
- **术语落地**：token、推理档、Elo、对数刻度、基准测试名这类词，第一次出现就用一句人话解释，别隔几段再补（出处：semantic-review.md §找什么）。
- **价格、版本、时间**：输入、输出、缓存分列，批量价、长上下文加价、订阅额度和 API 价分开说，降幅写明跟谁比并按原始数自己算；版本写官方全名；「前一天」这类相对时间按同一时区算清（出处：iron-rules.md §内容与归档）。

## 六、写后必做

1. 写完正文立刻跑 `pipeline.py preflight`（出处：autopilot.md §主流程）。
2. 磨稿：读出声 → 白名单减法（只减不加，信息守恒）→ `verify writing` 与 `audit_quant_signals` → anti-ai-filter 语义层（出处：writing.md §四、磨；polish-whitelist.md §硬边界）。
3. 并行两道外审，派发时把对应契约原文交给 subagent：
   - 事实复核：不带写作上下文，检索用便宜档、裁决用强档，产 `_fact-check.md`；✗ 改完复跑，待核实的改模糊或删（出处：fact-check.md §谁来跑；fact-check.md §条目格式）。
   - 语义冷读：只给 `定稿.md` 与靶子清单，换不同模型族（失败只降到全新会话，不许同会话自审），产带签名的 `_stutter-list.md`，点名要术语落地和时间线自洽；之后又成段改稿就重派（出处：semantic-review.md §怎么派；semantic-review.md §找什么）。
4. 文末用模板标记写 DEEP READ 与 SOURCES；SOURCES 只列正文用过的来源（出处：layout.md §文末双模块合同）。
5. 再跑 preflight 全绿，交作者审读；拍板后逐字落盘并接管，之后只读 release-runtime.md（出处：release-runtime.md §接管作者定稿）：

```bash
python "$SKILL/scripts/pipeline.py" approve draft --source-mode author-provided-final --words "<作者原话>"
python "$SKILL/scripts/pipeline.py" adopt-final
```

## 七、常见返工点

交稿前逐条自查（写法见前文）：

- 推文时间没换成北京时间，或写「美国时间下午」这类没换算的说法（出处：fact-check.md §核什么）。
- 价格单位、档位写错，降幅按错项算，订阅额度和 API 价混说（出处：iron-rules.md §内容与归档）。
- 第三方跑分写成官方口径，或官方自测写成独立结论（出处：material-integrity.md §来源类型）。
- 术语第一次出现没解释（出处：semantic-review.md §找什么）。
- 结构照抄上一篇（出处：outline.md §内容骨架匹配）。
- 指标方向写反，越低越好的降了写成退步；结论冒出正文没有的说法（出处：semantic-review.md §找什么）。
