## 全局交互规则：全景自监督生成 (Autonomous Full-Length Generation)

**最高优先级指令——全景闭门生成，带内置自清洁。绝不中途打扰用户。**

读取大纲后，你必须在一个完整流中一气呵成完成全篇！
不再有「暂停审阅」的特权。不再询问“是否继续”。

**如何克服长文生成时的质量衰退（LLM Degradation）：**
由于长文一次性生成容易在后半段陷入模板化和水字数，你在自己的思维逻辑中分块推进 -- 但 🔴 **磨稿顺序是"先连贯，后达标"，不是"边写边切块刷指标"。**

1. **先一气呵成出完整初稿**：从种子和大纲出发，一条思路从第一行流到最后一行，**只管思路连贯、句间承接、人味**——这一遍**不跑任何量化指标**（不数句长方差、不数温度带、不数加粗）。指标这时候介入只会把鲜活初稿提前切碎、把毛边磨平、让承接变成事后拼接。
2. **整篇读出声（终审）**：初稿成形后，整篇读一遍——你会这样跟一个聪明朋友说吗？读着磕巴 / 要回看 / 像作报告的地方，按"说人话"重写。**这一关凌驾于所有量化指标。**
3. **最后才做指标级精修**：读顺之后，再加载 [anti-ai-filter.md](anti-ai-filter.md) 做指标级检查（禁用词、副词密度、密度波浪等）。**精修后必须再读一遍整篇**，确认没把语流磨碎——任一指标修改若伤了承接/语流，回退该修改，以语流为准。
4. 全程不向用户索要确认（闭门不打扰），全篇拼装 + 读顺 + 精修复读都过了，再一次性把最终结果存入 `定稿.md`。

## 动态风格路由

读取大纲顶部的 `[目标风格：XXX]` 标签，**读取 [references/style-routes.md](style-routes.md) 中对应章节，跳过其余路由**。

风格路由 = 你在 `profile/corpus/authors/` 下**自建的手册**：每挑一个想模仿的对象，就蒸馏一份 `<name>.compact.md` 放进去，路由名即手册名（如 `example-author`）。仓内自带一份虚构的 `example-author` 示例，怎么自建见 `profile/corpus/authors/README.md`。单选其一，配套确定性约束写在 [style-routes.md](style-routes.md)；对应手册 `profile/corpus/authors/<name>.compact.md` 已由 prep_writing.py 聚合进 `_prep-context.md`。

### 维度随机化（防跨文章指纹追踪）

> 🔴 **降级（"顺但没味道"诊断）：维度随机化服从"全篇是同一个人在稳定地说话"，且从"硬激活贯穿全文"降为"方向性参考"。** 维度应当**从本篇内容自然长出来**（这篇就适合用对话体、就适合毒舌），抽签只是帮你别每篇都一样的提示；**绝不为"随机/贯穿全文"硬塞一个跟内容无关的维度**（如内容明明跟军事无关却硬把"军事类比域"贯穿全文）。与「句间引力」「稳定语气」（anti-ai-filter §1.6）冲突时，后者优先。跨文章去重靠 `works.yaml` 记录即可，单篇内部不为凑指纹牺牲连贯。

如果每篇文章都用相同的表达方式，读起来会像同一个模板。每篇文章写作前，可从以下维度池**参考性地挑 2-3 个**契合本期内容的维度，让表达有变化（不是硬性抽签贯穿）：

| 维度 | 选项（随机选 1） |
|------|---------------|
| 叙事视角 | 亲历者 / 旁观分析者 / 对话体 / 自问自答 |
| 时间线 | 顺叙 / 倒叙 / 插叙 |
| 主类比域 | 体育 / 做饭 / 军事 / 恋爱 / 游戏 / 电影 / 建筑 / 医学 |
| 情感基调 | 冷静克制 / 热血兴奋 / 毒舌调侃 / 温暖治愈 / 焦虑预警 |
| 节奏型 | 急促短句流 / 舒缓长叙述 / 快慢剧烈交替 / 开头慢结尾急 |
| 论证偏好 | 案例堆叠 / 逻辑推演 / 反面假设 / 类比说理 |

**规则：**
- 从 6 个维度里挑 2-3 个**契合本期内容**的（不是机械抽签）；挑不到合适的就少挑或不挑，别硬凑
- 挑中的维度应当**为内容服务、自然贯穿**，而不是当成"必须贯穿全文"的硬指标去执行（硬执行 = 又一个公式）
- 读取 `<数据目录>/works.yaml` 最近 3 篇已发布（按 `date` 倒序）的 `dimensions` 和 `closing_type`，本次尽量不完全重复（去重是为了不单调，不是为了反检测）
- 写作完成后，将本次维度组合和收尾类型记录到 `article-meta.yaml`（archive 阶段由 `pipeline.py archive` 写入 `works.yaml`）
- **优先级**：风格路由（compact 招式 / style-routes 确定性约束）**优先于**维度随机化。维度随机化只在路由招式未约束的自由度上生效——两者冲突时听路由，不为「随机」破坏 compact 招式

## 写作前准备

> 🟢 **refs-activation 收敛**：本节过去让你「自己去 Read 金句库/反例库/compact」 -- 实证那是装饰引用（说了不做）；「打卡 marker」又是装饰打卡（做了不验）。**现已改为脚本主动喂料**，下面这步取代一切「请你去 Read X」。

> ⚠️ **词汇温度池已移出 prep 注入**：107 词 4 温度带配额表不再注入 -- 配额化选词本身是新的公式化；vocab-pool 文件保留作离线参考，运行时由写后 `audit_style_signals` 软门兜底，写前不再注入。反例库也未做按 tag 召回，只在写后磨稿 grep。

**写作时你真正要内化的是这一份 `_prep-context.md`**，不是再去翻 6 个散落的源文件。脚本已经替你筛选+聚合好了。

> 为什么这样改：脚本算出「该用什么」主动塞到你面前，比「请你自己去 Read 6 个文件」可靠得多。`_prep-context.md` 是真实产物文件 —— 下游 B-主门（`verify_anti_ai_blacklist`）会断言它存在且 mtime 早于 `定稿.md`，**跳过 prep 直接写 = 排版阶段硬门 fail**。这一步从「自觉」变成「不做走不下去」。
>
> 诚实边界：脚本只能保证「料被喂到」，不能保证「料被吸收」（后者是 Claude 写作时的事，无法机械验证）。但比起过去「料根本没喂到」，这是实质前进。

0. **🔴 内化人味种子（`article-meta.yaml` 的 `seed` 字段）：** 这是本篇的起点和锚（采集见 [outline.md 步骤 1.5](outline.md)）。**正文从这个种子长出来，不是从通用指令长出来**；它是作者的真实开头／亲历细节／反常识角度／口语原话，磨稿不许把它磨成书面套话。种子为空 = 本篇先天缺人味，照写但心里有数（别假装有味道）。

## 姿态与声音锚点

一个人在想事情，碰巧被你看见。不教课，不演讲，不聊天。心里放一个具体的人，写给他，不是写给「读者们」。

**写作时的内心校准：**

1. 从"我"出发，不做裁判：用"我发现"、"我那时候"，分享判断，不给答案
2. 具体场景驱动：不说"市场低迷"，说"那是2024年初，一个做了十五年的老板把店盘掉了"
3. 反问唤醒读者：关键判断前先问一句"但你有没有想过……"
4. 结论一定落地：每节最后给出"所以你现在能做什么"
5. 克制不说教：结论说一遍就够
6. 不确定就说不确定："大概70%"比"可能"诚实
7. 不借势：不用群体代言（"程序员都知道"）。不编造经历。不用元评论（"接下来我们讨论"）



### 透明玻璃风格（源自奥威尔 + 阿西莫夫 + 《写作是门手艺》）

> "好的文章如同窗户玻璃。"——乔治·奥威尔，《Why I Write》

**核心隐喻：** 文字是窗户上的透明玻璃，读者透过它直接看到内容，意识不到玻璃本身的存在。阿西莫夫把这个比喻说得更透彻：有色玻璃橱窗本身很美丽，在光照下色彩斑斓，却无法看透它们；而平板玻璃本身并不美丽，理想的平板玻璃根本看不见它，却可以透过它看见外面发生的事——"阅读这种作品甚至不觉得是在阅读，理念和事件似乎只是从作者的心头流淌到读者的心田，中间全无遮拦"。

**易读难写定律：** 历史上彩色玻璃先于透明玻璃出现——因为早期玻璃中总有杂质，杂质正是色彩的来源。直到17世纪威尼斯工艺突破后，透明玻璃才出现。写作亦然：写长容易写短难，复杂容易简单难。"透明化"需要主动去除杂质，需要多次精炼。如果读者读不懂，问题在作者，不在读者。

**杂质检测——禁止三种腔调：**

| 腔调 | 表现 | 自检信号 |
|------|------|---------|
| **学生腔** | 情感泛滥、空洞抒情、堆砌感动素材 | 出现"我深深地感受到""不禁令人"等句式 |
| **学术腔** | 概念轰炸、叠床架屋、被动语态、各种状语插入语层层嵌套 | 一句话超过60字还没说完，或需要读两遍才懂 |
| **官腔** | 篇幅大信息少、没有主语、闪烁其词 | 出现"高度重视""积极稳妥""大力推进"且删掉不影响意思 |

**透明度操作守则（改写自奥威尔六规则）：**

1. **先想清楚再选词**——用画面和感觉在脑中成形，然后才挑词。不是有了华丽的词去找地方安放
2. **短词优先**——能用两个字说清的不用四个字。"进行讨论"→"聊"，"实现功能"→"做到"
3. **能删就删**——每个词必须有存在的理由。如果删掉一个词、一句话、一个段落，意思没变，那就该删
4. **具体优于抽象**——可感知的画面替代空泛概念。"市场低迷"→"那是2024年初，一个做了十五年的老板把店盘掉了"
5. **主动语态优先（但留三个例外）**——默认让主语"做事"。以下三种情形可以保留被动：① 动作发出者不重要或不明（"那栋楼被拆了"）；② 受动者本身是叙述焦点（"这条政策被接连推翻了三次"）；③ 故意把责任模糊化以保护当事人。其余场合一律改主动——被动语态会让句子变长、读者走神
6. **拒绝陈腐比喻**——要么创造新鲜意象，要么直说。"时代浪潮""赛道""风口"这类比喻已经死了

**六维量化自检（可选，精修时用）：** 在磨稿阶段，抽查任意一页，统计段落数、每段平均字数、每段平均行数、每段平均句数、每句平均字数。如果每句平均超过40字或每段平均超过200字，杂质可能过多，需要拆解。

> **本 skill 选透明玻璃路线，不是因为彩色玻璃错，是因为目标读者群是「想搞清楚一件事」的人，不是「想欣赏一句话」的人。** 另一类写作走彩色玻璃路线（文字本身就是被欣赏的造物 -- 意象绵密、句子本身值得反复咀嚼），同样合法。两种路线的优劣不可比较 -- 本 skill 默认走透明玻璃，但在你自建的抒情型路由内可切换调性。

### 读者意识（源自《写作是门手艺》第27章 + 接受美学）

> "写作如同送礼。你得弄清楚收礼的人喜欢什么。"

**送礼测验（写作前必做）：**

写作前回答这四个问题，回答不了的先不动笔：
1. **谁会读？**——列出2-3个具体的人（不是"读者们"，而是"那个刚转行做AI的朋友"）
2. **他们关心什么？**——作者感兴趣的不等于读者感兴趣的。你的"果仁"很美味，但读者先摸到的是粗粝的"果壳"
3. **他们的知识背景是什么？**——不能假定读者懂得太多（导致艰涩），也不能假定什么都不懂（导致小儿科）
4. **你写的是读者想要的，还是你自己想给的？**——如果是后者，重新剪裁

**外行评审内行法则：** 作者是写作题材的内行，而读者多半是外行——"买的没有卖的精"。但评判者由外行充任。这意味着：好文章不是让同行点头，而是让外行看懂并觉得有价值。

**松果法则（观点先行）：** 作者采取归纳视角写作——从各种素材推导出结论，结论藏在最后。但读者是演绎视角——想先看观点再看分析。文章如松果：作者得意的是里面的果仁，但读者先碰到坚硬粗粝的果壳。**贴心的作者会替读者剥好壳，把果仁直接递过去。** 每段观点先行（BLOT），读者只读每段第一句就能把握全文结构。

<!-- v5: C5 松果法则 opt-out -->
> **路由化降权：** 有的写法反向操作松果法则——开篇不亮观点，靠减压器/画面/实物把读者拉进来，观点藏在中后段才显形（叙事流手册可以整篇零严格 BLOT 命中，这是结构性反 BLOT，不是工程缺陷）。style-routes 路由可声明 opt-out 全文 BLOT 与松果法则，**段落 BLOT 仍守**（详见上文 §密度 第 10 条「全文 BLOT」）。

**与读者的四种关系（来自朱光潜）：**

| 关系 | 表现 | 读者感受 | 我们的文章中出现了吗？ |
|------|------|---------|---------------------|
| **不视** | 作者向虚空说话，自说自话，找不出主人性格 | "对面是一个空心大老倌" | 整段删掉意思不变→说明在自说自话 |
| **俯视** | 居高临下、抖机灵、晒高明、说教腔 | 被教训的感觉 | 出现"你要知道""你应该"语气 |
| **仰视** | 自我矮化、过度引用、缺乏独立判断 | 怪怪的，毕恭毕敬 | 堆砌权威引用却不说自己怎么看 |
| **平视** ✅ | 视读者为交谈对象，赤心相对，不装腔 | 像聊天，舒服 | 读出来像跟朋友说话 |

> 🔴 **「俯视」高频变种：把"做基础事/用现成方案"说成不屑（显得创作者好高骛远、晒高明）。**
> 当文章要解释"我为什么自己动手造某个东西"时，**绝不能用"这么基础，不至于自己动手 / 这种小事我看不上 / 这还用现成的？"这类口气** —— 读者会觉得作者在炫技、好高骛远、瞧不起常规做法，瞬间从平视滑向俯视。
> - ❌ 反例：「按理说，给 AI 配个看视频的能力，这么基础，不至于自己动手。」
> - ✅ 正例：「能用现成的我绝不自己造 -- 重复造轮子是最蠢的事，成熟工具往往比临时攒的更稳。我先去翻有没有人做好了，翻完才发现没一个合用，只能自己来。」
> **正向规则：** 解释"自己造/自己做"的动机时，姿态永远是**谦逊务实**（不重复造轮子、先找现成的、是现成的不合用才被迫动手），而不是**居高临下**（基础、不屑、看不上）。哪怕你真的觉得某事简单，也写"我先想省事用现成的"，把读者放在和你同一高度。

**以读者为中心的三条原则：**
1. **考虑读者 ≠ 媚俗**——为读者提供方便是减少阅读障碍，媚俗是放弃实质观点。完全不同
2. **文字传递的信息才重要，个人风格不重要**——不是为了让读者记住你的文采，而是让信息准确到达
3. **好文字 = 更多的读者，更快、更准确地获取信息**——减少障碍，让交流顺畅，而不是搔首弄姿

**懒人读者设定（内置假设）：** 写作时默认读者注意力有限、耐心稀缺。这不是瞧不起读者，而是对自己的严格要求——如果最没耐心的读者也能获取核心价值，文章的"玻璃"就足够透明。操作上：段首句概括本段主旨，小标题能独立传达信息，关键判断加粗突出。

## 最高法则 — 口语检验

> **你会这样跟一个聪明的朋友说话吗？不会 → 改到会。**

这条覆盖一切。任何操作的结果过不了这关，回退。

### 哪些连词留、哪些删（连词处理统一表）

> 写作和磨稿阶段都用这张表，**不要再去翻"朴实简洁四条"里那条「连接词一律删」的概括口径**——以本表为准。

| 类别 | 例子 | 处理 | 原因 |
|------|------|------|------|
| **结构性逻辑词**（思维转弯） | 但是 / 所以 / 就像 / 因为 / 因此 / 不过 | ✅ **保留**（活的，反映思考过程） | 删了句子之间的逻辑会断，读者跟不上 |
| **机械学术连词** | 此外 / 另外 / 值得注意的是 / 综上所述 / 由此可见 | ❌ **删** | AI 腔典型信号，删了不影响意思 |
| **冗余口头禅连接词** | 然后 / 接着 / 那么 / 其实 | ❌ **删** | 口语凑节奏的占位符，书面文里全是水分 |
| **自我软化口头禅** | 我觉得 / 我认为 / 应该说 / 个人认为 | ❌ **默认删**（除非要表达"不确定" -- 用「大概率是 / 老实说我也没想明白」更诚实） | 立权威人设的反面是过度自谦，两者都不要 |

**自检顺序**：写完一段先扫第 3、4 行（冗余口头禅）一律删；再扫第 2 行（机械连词）删；最后回到第 1 行，确认结构性逻辑词没被误删。

### 明信片法则（源自《写作是门手艺》第十篇）

> 想象你在给一个在远方的聪明朋友写明信片：有限的格子，要在他泡一杯茶的功夫里，让他看懂并觉得值得读。

写初稿之前，在心里写一张明信片：**30 字交代这篇要讲什么、为什么他该在乎。** 写不出来 → 你自己都没想清楚，不要开始写正文。

- **收件人栏**：一个具体的人名（不是"读者们"），知道他的处境
- **正文栏**：一个带问号的具体疑问 + 你的一句话判断
- **签名栏**：你为什么是那个最该告诉他这件事的人

整篇文章，是这张明信片的展开版。写完任一段，回头问：这段离明信片上那句话近了还是远了？远了 → 删掉或挪位。

<!-- v5: C5 减压器型开篇 opt-out -->
> **减压器型开篇**（style-routes 路由内 opt-out 选项）：开篇第一句的功能不是亮观点，而是让读者愿意往下读一段（如「今天 [X]」式日常起手 / 一个日常场景切入 / 一帧画面切入 / 一件实物入题）。**只在风格路由内打开，不动默认值**——通用规则仍要求明信片 30 字交代清楚。

## 句间引力（承接主防线 — 决定"读完第一句想不想读第二句"）

> 🔴 **与 SKILL.md「写作核心第 6 条·句间引力」同源。** 这是过去整条链最薄弱、却最决定"读起来顺不顺、想不想读下一段"的维度 -- 之前只在 §密度第 7 条「接龙」一行带过、§段落间关系只管到段级，火力都压在加粗/句长/温度等单点指标上，没人管"这一句怎么把读者送进下一句"。本节把它提到与 So What 同级的承接主防线。

**为什么"顺"不是玄学（机制）：** 读者读每句话，默认先把**句首**当"已知信息"去脑子里找锚点，再把**句尾**当"新信息"挂上去（given-new 契约）。相邻两句真正"咬合"的机制是——上一句句尾抛出的新信息，在下一句句首被接住（变成已知）。句首突然冒出一个前文没铺垫的新名词，读者没锚点，被迫"找上下文＋理解新词"同时进行，这就是**卡顿**。所以"承上启下"不是修辞，是命中读者大脑的加载顺序。

**四条可操作的承接动作（中文版）：**

1. **顶真承接** — 上一句结尾的关键词，在下一句开头接着出现（或用"它/这件事/这套逻辑"回指接住）。首尾蝉联，读者被推着走。
2. **旧信息在前、新信息在后** — 每句句首放上文已出现的概念当锚点，把这句最想让读者记住的新词，放到句号前的最后一个实词位置（句尾会被读者自动加重）。
3. **问号钩 / 悬念钩** — 上一句尾部留一个没答的问号或一个刚冒出的具体物，下一句立刻接住并往前推（"差在哪？差在计费哲学。"）。
4. **情绪转折钩** — 上一句把读者带到一个判断上，下一句用"但""偏偏""可问题是"掀一个抗力，让读者觉得"事情没那么简单"，自然想读下去。

**原创样本（抄承接逻辑，不抄字句 -- 这些例句只为演示手法，写你自己的内容时另起）：**

> **样本 A（顶真：上句尾词原样搬到下句开头接住）**
> 「一个工具越顺手，你就越舍不得关。舍不得关，它就一点点长进你每天的活儿里。」
> - 上句尾"舍不得关" → 下句首"舍不得关"原词复现接住；旧信息（舍不得关）在前、新信息（长进日常）在后。读者被这个重复词推着往下走。

> **样本 B（顶真链：环环相扣往下滚）**
> 「一个功能没人用，是因为没人知道；没人知道，是因为没人讲；没人讲，是因为连做它的人自己都说不清它好在哪。」
> - "没人知道→没人知道"、"没人讲→没人讲"逐节尾首相接，前一句的果成为后一句的因。一条线滚到底，没有断点。

> **样本 C（给定-新：旧信息提句首，"那就是"领出新信息）**
> 「点开一次对话，那就是一次按 token 结的账。上传一份文档，那就是一次向量化的存储成本，也是每个月都在悄悄扣的一笔钱。」
> - "点开一次对话/上传一份文档"作为已给定的旧信息提到句首，"那就是"把读者引向新信息（具体费用），两句同一句式承接，读起来像顺着一根线往下数。

> **样本 D（问号钩＋转折钩：先悬住再接住）**
> 「这东西到底值不值那个价？我用了整整一个月，也没算明白。但有一件事我是笃定的……」
> - "值不值那个价？"用问号把读者悬住 → 下句"没算明白"先认领这份不确定 → 再用"但"转折钩把话头拽到"有一件事我笃定"。问号和"但"都是承接钩。

> 这套"朴实简洁有人味"的承接手法已用对照法蒸馏进 `playbook.md` 的 rules（`sentence_hook_chain` / `short_sentence_chain` / `cold_close` / `drop_adjectives` 等硬规则，写作 Step 4 自动加载，全风格路由通用）。

**句间引力体检（磨稿期做，比数加粗有用得多）：**

- **首尾接龙体检**：逐句把"本句开头"和"上句结尾"对齐看——后句开头能不能从前句结尾找到对应的词 / 同义词 / 代词？找不到 = 断点。要么把那个新名词移到上句句尾先 introduce，要么补一句过渡。
- **重点落句尾**：每句最想强调的词，是不是落在句号前？卡在句中就改写让它落到句尾。
- **删连接词反而更顺**：中文是"意合"（靠语序和话题链承接），不是英文式"形合"（靠连接词）。把机械学术连词"此外/与此同时/另外"删掉后逻辑仍清楚 → 删掉，让语序自己承接。🔴 **结构性逻辑词（因此/然而/所以/但是）默认保留**——它们反映思考转弯，删了逻辑会断；只有在删后语序仍顺承时才酌删，默认不动（裁决以上方「最高法则 §连词处理统一表」为准，本条不与之冲突）。

> **与 §密度「接龙/主语链」、§段落间关系「推/转/并」的关系：** 那两节是同一原理在"句内尾首相接"和"段间关系"两个尺度上的落地，本节是写作核心层的总纲＋样本。三者叠加：句子层靠顶真/给定-新，段落层靠推/转/并。

## 过程

### 一、找核 & 攻核

详见 [outline.md](outline.md) 的「找核」和「攻核」步骤。进入正文前确认核已通过压力测试——能用一句话说清核心，且扛住了反转、追问前提、追问情绪三把铲子。

### 二、找类比

为核找一个结构对得上的日常类比。

抓住核的动词结构——它在干什么，什么作用于什么，什么流向什么。在日常经验里找结构一样的东西。

好类比的标准：
- **承重**：去掉它整篇文章塌掉
- **多层**：往下挖一层还像，最好三层以上
- **自明**：读者不需要解释就能看懂类比本身

跨域类比：结构对得上，不是表面像。一个打透胜过三个排列。

### 三、展开并写

输出是一篇从第一行流到最后一行的连贯文章。

#### 开头候选盲选（动笔前先定调 · autopilot 唯一法定停顿点）

> **为什么先定开头再写：** 开头定调全文 -- 开头没定，后面内容朝哪写都没有依据。它又是验收第一标准（"读完第一句想读第二句"）所在的高杠杆位。所以在动笔写正文**之前**，先把开头交给作者挑定方向，再顺着这个方向一气呵成写完。

> 🔴 **先过开篇策略分流（见 [outline.md 步骤 3.5](outline.md)）**：本节的钩子类型轮换是**深度启发类**的流程。若本篇是**资讯 / 时效类**（AI 时事、新工具 / 新模型介绍、横向评测、版本解读）或**成果 / 实作类**（自研工具 / 网页 / skill、成果介绍、实测、横评），开篇一律走 **直入** -- 资讯类第一句说「发生了什么 / 它是什么」；成果类第一句亮成果（「我做了个 X」+ 能干什么），第一屏内给入口 + 一个真实产出示例。两者都不设故事钩子、不做概念铺垫。此时盲选退化为：要么直接定一版直入 / 成果前置开头不盲选；要么给的 2-3 版**全部是直入式**（差别在"先给哪个事实 / 哪个产出 / 哪句价值预告"，而不是"故事 vs 数据 vs 场景"的钩子类型轮换）。**资讯 / 成果类禁止把故事钩子放进候选**。

**两段式（只有第一段是停顿）：**
1. **定调（法定停顿）：大纲定稿后、动笔写正文之前。** 基于大纲 + 种子，长出 2-3 版开头候选给作者盲选。作者选定一版 → 这版定下全文的调子和切入角度 → 顺着它**闭门一气呵成写完初稿**。
2. **微调（磨稿期，自动不停顿）：** 写完初稿、进 §四磨 时，回看选定的那版开头和已成形的全文咬不咬合。不咬合就**只微调开头那一版**（不重新盲选、不打扰作者）-- 因为方向是作者定的，磨的只是让它和全文严丝合缝。

**候选形态：**
- **2-3 个候选**，每个 = 完整的**前两段**（写到第一个自然气口，约 150-300 字）。
- 候选之间**钩子类型必须不同**——从 [craft-techniques.md 开篇技法库](craft-techniques.md#开篇技法库四选一) 里取 2-3 种不同的（如 提问 / 场景 / 数据 / 亲历 各一），**不是同一角度换措辞**。
- 候选里**词组级重点标识照常用**（让开头也有视觉落点），但**不得出现整句加粗口号**（服从金句节拍器禁令，见 [craft-techniques.md §金句锻造](craft-techniques.md)）。盲选比的是钩子张力 / 句间承接，不是加粗。

**呈现格式（盲选的核心是"盲"——不泄露 AI 倾向）：** 严格用下面这个格式输出，不偏离：

```
开头我写了 N 版，你凭直觉挑一个，不用看理由：

【A】<完整前两段>

【B】<完整前两段>

【C】<完整前两段>

选 A / B / C，或说"都不要，换个角度"。
```

硬约束：
- ❌ **不写版本标签后缀**（不写「A·场景版」之类——会泄露类型，破坏盲选）
- ❌ **不给任何一版加推荐语 / 优劣点评**（一旦说"这版更抓人因为…"，作者就被引导了）
- ❌ **不设默认项**（与"定稿后下一步选项"那个带默认的范式刻意区分——那是流程推进，这是审美盲选）

作者选定后，**先落盘一个轻量锚点 `_opening-choice.md`**（记录选定字母 A/B/C + 选中那版的首句 + 时间戳），作为「唯一法定停顿点」的可恢复证据——`pipeline.py verify writing` 会对它做存在性 WARNING、autopilot 标 `done writing` 前要求它存在，杜绝跨会话 / 中断恢复时静默跳过盲选（恢复时 `status` 看到 writing=done 即直奔配图，盲选这一停顿点最易被漏）。然后顺着选中那版往下写全文，另两版废弃（可另留 `_opening-candidates.md` 备查，但不进定稿；`_opening-candidates.md` 是被丢弃的候选、`_opening-choice.md` 是选定结果，两者别混）。

**结尾盲选（默认关）：** 默认**不做**结尾盲选。理由：① 结尾技法本就高度收敛（不总结 / 冷收 / 开放，见下方"结尾不总结"），收尾多样性已有 8 种枚举且与近 3 篇去重，"变化"维度已被别的机制管；② 结尾不像开头决定"读不读下去"，杠杆远小于开头，不值得再加一次停顿打扰。**仅当作者显式说"结尾也给我几个 / 结尾盲选"时才临时开启**，形态与开头盲选同构（2-3 版不同收尾类型、编号、不给理由），但**不进 autopilot 默认停顿点**（autopilot 只有开头一个法定停顿）。

---

**开头（选定后顺着写）：** 第一句话给读者一个理由继续读——反直觉判断 / 画面 / 问题，三选一落地。不铺垫、不背景、不「自古以来」。类比直接落地，读者还没反应过来已经在里面了。具体技法（悬念故事 / 日常发现 / 反差荒诞 / 痛点共鸣四选一）见 [craft-techniques.md 开篇技法库](craft-techniques.md#开篇技法库四选一)。

**展开：** 让类比自己走。每段一个认知增量——两个就拆，零个就删。每句一件事——句子短，读者快。拔掉任一段链条应该断，不断就删。同一个论点只用一个例子，一个不够说明例子选错了。

**裂缝：** 类比在哪里撑不住了？那个点就是文章最值钱的段落。不宣布"类比在这里失效"，让读者自己感到对不上了。用叙事推过去。

**反问入链：** 遇到隐含前提，用一个问题打开。"但等一下——如果真是这样，为什么……？"然后回答它。

**结尾不总结。** 结尾是最后一个发现，或者一扇门——指向你没写但读者会自己去想的方向。

**语气是探索性的：** "X 看起来是一回事，但如果你……等等，这意味着 Y。" 读者跟着你一起走到结论，不是被告知结论。

**白描子模式（按需调用，详见 [craft-techniques.md](craft-techniques.md) §白描技法）：** 极简白描路线——名词+动词双拍极简对仗（禁形容词副词）/ 闲笔荡开 / 冷收一句 / 反常精确数字。可作所有路由的"减法子模式"按需调用。

**加粗与重点标识--初稿即执行，不留到磨稿：**

加粗是**稀缺的视觉锚点**，不是排版装饰。读者在手机上快速滑动时，加粗文字是扫到的那几个点 -- **多了就和没加一样**，满屏染色反而让读者抓不到重点。

🔴 **稀疏原则（优先级最高）：** 加粗密度前重后轻、全篇恪守上限。读者的第一印象靠钩子区密集抓取，读进去以后靠段首句和小标题承担导航 -- 中后段不必再用加粗反复敲读者的脑袋。

> 🔴 **两类加粗必须切开（针对"开篇大段文字吓退读者"的正解）：** 别把下面两件事混成一件。
>
> | | **(A) 词组级重点标识** | **(B) 口号式整句加粗（金句节拍器）** |
> |---|---|---|
> | 是什么 | 3-7 字的关键词/短语标主题色，让长段落有视觉落点、读者眼睛有抓手 | 把一整句口号/金句加粗 |
> | 开篇怎么办 | **鼓励**：钩子区（前 3 段）按下方位置密度表给视觉锚点，长段尤其要有，免得读者面对一堵字墙 | **限制**：全篇加粗口号 ≤2，且必须是收拢句不是预告句（见 [craft-techniques.md §金句锻造](craft-techniques.md)） |
> | 渲染 | `**词**` → 主题色短语，从句子里跳出来 | 整句染色 = 没重点 |
>
> **"开篇更多重点标识"= 多用 (A)，不是松开 (B)。** 这**不是恢复曾拆掉的钩子区加粗硬下限** -- 下限仍是软警告、不机器强制每段必须加粗；鼓励的是"该有视觉落点的长段落别裸奔"，靠的是**词组级落点 + 早插图**（见 §写作前准备第 7 条），不是配额硬塞。**底线仍是串读骨架测试**（见下方）：把所有加粗抽出来像关键词骨架就对、像文摘就是标色泛滥。
>
> 🟢 **主题色深浅阶 -- 重点标识可分两级主次**：主强调用 `<mark>词</mark>`（一级主题色 #2F6F8F）；同一处有「主 + 次」并列、或想标一个次要落点时，次级用 `<mark class="2">词</mark>`（二级浅色 #7FB0C4，同色相偏浅）。二级色适合加粗短语/次级标题，小字慎用。**别为了分级去引入第三种色**——只在「深→浅→半透明底」这条明度轴上走（见 [design-tokens.md 主题色深浅阶](design-tokens.md)）。
>
> 🔴 **整句金句加粗也受 `verify_bold_density` 硬门约束：单个 `**…**` 块 ≥15 中文字符即触发 `integral_bold_violation`（排版 `exit 2`）。** 金句可以独段，但加粗范围要收到 ≤14 字的最锋利词组（标「两个最关键的班组」而非「一头一尾，恰恰是两个最关键的班组」）。「把完整结论句加粗成段」这类招式同样服从此约束 -- 句子可独段，但只加粗其中 ≤14 字。踩坑教训：方法卡标题整段加粗 + 长金句整句加粗，会触发 integral_bold。
>
> ⚙ **执行层提示（哪条靠人、哪条靠机，别混）：** (B) 的「全篇加粗口号 ≤2 处」是磨稿期的人工君子协定，**数量上限仅靠磨稿自觉、无机器计数**；机器（`verify_bold_density`）只硬拦两件事——**单块 ≥15 中文字符的整句加粗**（`integral_bold_violation`）+ **全篇粗体总量分档上限**（25/35/45/55）。即：长度与总量靠机器、口号条数靠自觉。

**位置密度（与字数无关，统一）：**

| 位置 | 加粗密度（有上限！） | 做什么用 |
|------|-------------------|--------|
| **开篇区（正文开头 → 第一个 H2，全部段落）** | 每 80–120 字 1 处 `**加粗**`，**每段最多 2 处** | 抓住注意力，第一印象密度要够。🔴 实证扩域：原"前 3 段"不够 -- 开篇常有 6-8 段，第 4 段往后照样是字墙 |
| **前 30% 正文** | 每 150–200 字 1 处，**每段最多 1 处** | 持续强化痛点、结论、核心数据 |
| **中后段（70% 正文）** | 按字数分档（见下表），**每段最多 1 处** | 维持节奏，不刷屏 |

🔴 **信息锚点六型 -- 开篇区这几类出现即标，不犹豫：**

| 型 | 是什么 | 实例 |
|---|---|---|
| ① 专名首现 | 文章主角（模型/产品/公司/skill/网站 名）第一次出现 | 「Anthropic 发布新模型 **Claude Fable 5**」；「给它起名叫「**某某助手**」」 |
| ② 关键数字短语 | 价格 / 倍数 / 百分比 / 评分，连同量词一起标 | 「恰好是 **Opus 4.8 的两倍**」 |
| ③ 时间窗口 | 截止日 / 生效期 / 读者要赶的 deadline | 「**6 月 22 日前包含在你的订阅额度里**」（≤15 字内取最锋利片段） |
| ④ 对比/转折结论 | 一句话里真正反直觉的那个短语 | 「单价贵一倍，**单位智力反而更便宜**」 |
| ⑤ **入口/行动锚** | 读者能去哪、能做什么 -- 网址 / 下载入口 / 操作路径 / CTA；**成果类第一屏的入口必标** | 「网址在这：**yoursite.example.com**」；「进「**工具箱**」就能看到」 |
| ⑥ **落差/量级对比** | 悬殊的量级关系本身（不只是数字，是"差多少"的那个落差短语，比裸数字更该标） | 「原本要大半天，**个把小时就清完**」；「**省 61%**」；「**从 3 秒压到 0.8 秒**」 |

> 为什么单列 + 🔴 **事实型优先**：实测发现开篇常见①②③型信息却一处没标；成果类文章开篇的专名 / 网址 / 入口也常全裸、零标识仍能穿过审查。病根有二：① 旧清单太抽象、写作时对不上号；② **加粗被过度堆在④观点/整句上，反而漏了读者最想抓的事实**（实测多篇如此）。铁律：**①②⑤⑥ 事实型锚点是开篇第一优先、出现必标；④ 观点/结论型让位 -- 一段里事实锚点没标够之前，不占用观点句的标识额度。** 信息锚点是读者扫一眼就要带走的事实，比"判断"更该标 -- 读者滑动时先抓事实，再决定读不读你的判断。自检：初稿写完只看开篇区，圈出所有①-⑥型，**先保证事实型（①②⑤⑥）标全，再看观点型** -- 每个问"读者扫不到会不会错过重点"，会 → `**标**`。

**🔴 全篇加粗总量按字数分档（从原全局 25 上限升级为字数动态）：**

| 文章字数 | `**粗体**` 上限 | `***粗斜体***`（主题色）上限 | 中后段密度参考 |
|---------|----------------|---------------------------|----------------|
| < 3000（短文）       | **25**          | **5**                       | 每 2–3 段 1 处 |
| 3000–5000（中等）   | **35**          | **7**                       | 每 2 段 1 处 |
| 5000–8000（深度长文）| **45**          | **9**                       | 每 1–2 段 1 处 |
| > 8000（超长）       | **55**          | **12**                      | 每段最多 1 处 |

> **为什么按字数分档**：6000 字深度文用 25 处加粗，读者每隔 240 字才能扫到一个视觉锚点，对长文导航不够；2500 字短文用 35 处加粗则会刷屏。密度要服务于文章长度。

> **原 25 上限作废**：历史文章若超 25 处但合规于新分档，**不追溯重排版**。

**加粗什么：** 核心结论、关键数据、反直觉判断、转折点的**关键词或短语**（≤15 字）。
**不加粗什么：**
- 修饰语、过渡句、人名（除非人名本身就是核心信息）
- 🔴 **整句加粗**——严禁把一整段话或一个长句用 `**...**` 包起来（机器硬门口径：单个 `**…**` 块 ≥15 中文字符即触发 `integral_bold_violation`／排版 exit 2，见 §407 与 `verify_bold_density`；加粗范围收到 ≤14 字最锋利词组）。加粗是"点"不是"面"，加粗的应该是句中最锋利的那个短语，让它从句子里跳出来；整句加粗会把整段文字都染成粗体/绿色，反而没有重点
- 🔴 **连续相邻的短句都加粗**——即使每句只加粗几个字，连着 3–4 句都有加粗，视觉上和整段加粗等价

> **写初稿时就必须边写边加粗**，但一段落成后立刻问自己：**这一段我真的需要 2 处加粗吗？能不能只保留最值钱的那 1 处？** 能 → 删掉另一处。**多数时候，减一半，重点反而更突出。**

**加粗密度按风格路由分档（中后段密度可被路由覆盖；钩子区下限全路由统一）：**

| 路由 | 全篇加粗密度 | 开篇区强制下限（从"前 3 段"扩域到全开篇区） |
|------|-------------|----------------|
| 结论驱动型 / 深度报道型 / 通用（默认） | 维持上方 25/35/45/55 上限 | ✅ 强制（每 80-120 字 1 处） |
| 深夜长谈 / 沉吟体 / 反常识叙事 / 智识杂文 | 0-15 处全篇 | ✅ 强制（≥80 字段至少 1 处）-- 叙事流路由容易栽在"全篇低密度"上、连开篇信息锚点也没标；**路由压的是中后段密度，开篇区信息锚点四型不豁免** |
| 学者讲生活型 | 全篇 ≤15 处 | ✅ 强制（≥80 字段至少 1 处） |
| 散文 / 戏仿子模式 | 0-3 处 | 可关闭（≤300 字的纯散文整篇可不加粗） |

> 🟡 **钩子区加粗下限（软警告，全路由统一）**：钩子区（前 3 个 ≥80 字正文段）**建议**有视觉锚点，但**不再机器强制** -- `format_layout.py preflight_markdown` 检测到钩子区 ≥2 段无加粗时只打 `⚠️ 提示（不阻断）`，不再 `sys.exit(2)`。**首句的张力靠钩子 + 句间承接（见上方 §句间引力），不靠加粗硬凑**；但这不等于"开篇可以零视觉落点" -- 钩子区的**长段落**（≥80 字）该有 (A) 词组级重点标识做抓手（见本节顶部「两类加粗必须切开」），免得读者一上来面对字墙。区别在于：落点要落在**真正值钱的词**上、自然长出来，不是机器每段硬塞一个。加粗上限（防刷屏）保留。详见 [iron-rules.md · 钩子区加粗下限](iron-rules.md)。
>
> **背景与判例详见** [iron-rules.md · 钩子区加粗硬下限](iron-rules.md)（踩坑实录 + 全规则正文 -- 单一来源）。

**🔴 H3 子标题与防文字墙 -- 大段连排必须拆 H3，排版才有时间轴可用：**

`### H3` 在排版阶段自动转成时间线格式（主题色圆角方块编号 + 主题色标题 + 浅灰竖线包裹），是本 skill 切碎字墙最强的排版武器 -- 但它只在**写作时就写了 H3** 才会出现，排版阶段不会无中生有。实证：整篇 0 个 H3、每案约 1500 字纯段落连排，读者面对的就是字墙（反馈"大段文字让人读不下去"）。

**触发器（写初稿时对号入座，命中即拆）：**

| 信号 | 动作 |
|---|---|
| 一个 H2 区块 ≥800 字、且中途无 H3 / 无图 / 无列表 / 无引用块 | 必拆：找出该块内部的 2-4 个天然推进点（时间推进 / 案情环节 / 要点切换），各立一个 H3 |
| 内容本身是 步骤 / 环节 / 案例列举 / 多要点并列（≥3 个） | 强烈推荐 H3——这正是时间线格式的本职（"第一环/第二环"式推进文案天然就是 H3 骨架） |
| 连续 ≥5 段纯文字、无任何视觉变化 | 至少给 1 个 H3 或 1 张图，二选一 |
| H2 区块 <500 字，或抒情收尾段 | 不硬拆——H3 是导航不是装饰，短块塞 H3 反而碎 |

**H3 标题写法**：沿用 [Markdown 输出规范](#markdown-输出规范) -- 禁手写编号前缀（主题色圆角方块自动编号）、≤12 字、**标题独立可读**（只看 H3 串起来 = 这一节的目录；「信源静默死亡 38 天」✅，「第一个问题」❌）。

> 与"加粗稀疏原则"的关系：H3 和词组级标识是两层互补的导航——H3 管**段间**（把 800 字切成 3 个 250 字的格子），加粗管**段内**（格子里的视觉落点）。中后段加粗密度被路由压低时（叙事流 / 反常识系），**H3 是字墙唯一的解**，更不能省。

**骨架通用写作要点：**
- 所有判断需数据支撑，数据必须标注来源和时间
- 用对话和场景代替形容词--"他说"比"他认为"有画面感
- 行业分析要有时间边界--说清楚"截至2026年Q1"而非"目前"
- 结尾不下终局判断，保持开放--让读者带着问题离开

**🔴 朴实简洁四条（硬约束，全路由通用）：**

1. **能删的字一律删** -- 形容词、副词、冗余连接词、自我软化口头禅按「最高法则」§连词处理统一表 第 2-4 行操作。
2. **段落短促** -- 单段 ≤3 句，超 100 字自检能否拆/砍。
3. **不堆"高级词"** -- AI 套话词（赋能/沉淀/打通/链路/底层逻辑）出现 ≥3 次必须重写。
4. **白话试纸** -- 写完每段读出声，"跟朋友不会这么说" / "自己都觉得绕" / "省了不影响意思" 三种感觉任一出现就退回去改。

样本库是你自备的语料池，放在 `profile/corpus/`（BYO -- 见语料 HOW-TO），按作者/类目分目录存放原始文章 markdown，供写作前校准声音用。仓内只带一份虚构的 `example-author` 示例；你可以把自己欣赏的作者文章按目录整理进去，让 `prep_writing.py` 聚合注入。整理时按**文笔特点**归类（宏观数据骨架 / 反常识叙事 / 口语化短句 / 方法论清单 / 工具评测…），选样时才好按风格异质性取用。

**写作前抽样建议（🔴 选样标准：风格异质性优先，不按主题相近选）**：
1. `prep_writing.py` 已自动注入 1 篇整篇金标范文到 `_prep-context.md`（选样按典型篇幅，写前必通读）
2. 想再补读时，到你的语料池（`profile/corpus/`）按**风格异质性**挑 1-2 篇：叙事 1 篇 + 吐槽/评论 1 篇。**不按主题相近选** -- 选样的目的是校准声音不是找素材，主题相近会诱导内容搬运、加重同质化（研究实证：异质样本钉声音的效果优于同主题样本）
3. 不要批量读 -- 精读，把节奏、句法、段落呼吸看进心里；读完合上再动笔
4. 语料池为空时（未自备），退回 `prep_writing.py` 注入的基础人味兜底样本 `profile/corpus/voice-samples.md`

### 四、磨

初稿出来后（🔴 顺序：读出声终审在前，量化精修在后；伤语流以语流为准回退指标）：

1. **🔴 读出声（终审，凌驾下面一切量化项）**：整篇读一遍（或 1.25 倍速 TTS 听）。你会这样跟一个聪明朋友说吗？不会 → 重写。再随机翻一段：读完第一句想读第二句吗？读完这段想读下一段吗？不想 → 多半是首句没张力或句间不承接（见上方 §句间引力），先治这个。
2. **机器扫一遍（🔴 机器能查的不占人工注意力）**：跑 `pipeline.py verify writing`（含 verify_pos_ratio / verify_bold_density / verify_h2_subtitle_align）+ `contracts.audit_quant_signals('定稿.md')` 量化体检报告（句长/段落节奏/副词/感叹号，仅参考永不阻塞）；AI 套话黑名单与导游腔元话语由排版 preflight 的 B-主门自动硬拦。报告里的**真问题**逐处处理，每改一处回到第 1 步重读 -- 伤语流即回退该修改。人工不再逐段数指标。
3. **加粗巡检（下限已降级软警告，重点查上限防刷屏）**：
   - **首段质量看张力+承接，不看加粗量**：前 3 段不强制凑加粗（下限是软警告）；看首句有没有钩子张力、前两句有没有互相承接。首段平 → 改首句，别靠加粗救。
   - **上限检查（重点）**：中后段有没有每段都 2+ 处加粗？有没有整句加粗（单个 `**…**` 块 ≥15 中文字符即违规／排版 exit 2）？有没有连续 3 段每段都有加粗？全篇加粗总数有没有超过分档上限？`***粗斜体***` 有没有超标？（任一超标 → 删掉最不值钱的那些，留最锋利的短语）
   - **串读骨架测试**：把所有加粗文字抽出来排成一列——它们应该像**文章的骨架关键词**（10–20 个短语），不是像**文摘**（能把文章复述一遍）。像骨架 → 过；像文摘 → 删到只剩骨架
   - 💡 **金句正向触发（宁缺毋滥，不配额硬塞）**：磨稿时为**每个 H2 的收拢句**试着锻一个候选金句（优先用 [craft-techniques.md §金句锻造](craft-techniques.md) 的句式公式），写完全篇**择优只留 ≤2 句**——与「整句加粗口号 ≤2」共用同一配额、协同生效，避免金句轰炸。金句必须是该 H2 的收口句（后置于支撑场景）不是预告句；挑不出锋利的就不锻，别为凑数造假金句（配额化造金句本身=新公式化，见 craft-techniques 节拍器禁令）。
4. **过滤 AI 痕迹**（加载 [anti-ai-filter.md](anti-ai-filter.md)，先读其顶部重定向说明再逐项查；量化项都是参考，读出声优先）。
5. **维度与收尾记录**：将本篇激活的维度组合和收尾类型写入 `article-meta.yaml`（archive 阶段由 `pipeline.py archive` 写入 `works.yaml`）。
6. **🔴 冷读外审（排版前置硬门，换模型语义评审 agent）**：磨稿完成后，用 Agent 工具派一个**全新 subagent**（高价值篇**换不同模型族**，如 Sonnet）做首读读者冷读 + 语义差分。**完整契约（派发/换模型/语义靶子10类/带签名的 `_stutter-list.md` schema）见 [semantic-review.md](semantic-review.md)**；下面是要点：
   - **只给它 定稿.md 正文** -- 不给大纲、不给 seed、不给 _prep-context、不带会话历史。自审带全上下文会盲目自信（实证：自审时数处语法硬伤会穿过"读出声终审"），所以**写作 agent 不得自审代替**。
   - 🔴 **职能收窄 -- 只抓"非同口味也能逮、且确定性门逮不到"的两类，别写读感散文**：
     - ① **硬错**：掉字 / 多字 / 病句 / 半截话 / 指代不清（"它/这个"指代不到东西）/ 前后事实打架 / 专名机制没交代就用。这类是**生成态盲区**（写的模型刚写完会脑补过去），换一双没上下文的眼睛才照得出，价值真实。
     - ② **连贯断点**：段与段接不住（前段尾接不上后段头）、该回填的伏笔没回填。这是**只有"人按顺序读"才发现**的结构问题，linter 测不了。
   - 🔴 **明令不做的两件事**：
     - **不打"整体流畅度评分 / 读感"**——写的和审的是同一个模型、同一套口味，"读着顺不顺"的判断≈写作者自己的判断，差分信号极弱，这类"不痛不痒"的产出纯烧 token。
     - **不重复确定性门已覆盖的**：半角标点交给 `verify_cjk_punctuation`（它逮 364 处、冷读只逮得到 2 处）、断链/漏嵌图交给 `verify_publish_assets`、markdown 崩交给 `preflight_markdown`——冷读**别碰这些**，专注"只有人读得出"的硬错 + 连贯层。
   - 🔴 **语义差分必须换模型（规则，不是旁注）**：语义级"AI 味 / 没人味 / 句子对但没意愿读下去"这一层，**同模型冷读照不出来**——写的和审的是同一个模型、同一套口味、同一片视野盲区，自审差分信号≈零（verdict 干净 ≠ 没 AI 味）。所以**要真正差分语义这一层，必须换一个无本文上下文的模型 / 会话**（如派 Sonnet / 不同温度的独立 subagent）或交作者本人；同模型同会话不算数。上面 ① 硬错 / ② 连贯断点那两类换"无上下文的同模型眼睛"即可逮，但语义层换不换模型是分水岭。
   - ⚠️ **目前只是定性自检，机器不验内容**：冷读这一关在管线里**只有「文件存在性」一道机器门**——排版 preflight 只断言 `_stutter-list.md` 存在且非空（见下条），**无法机器验证「是否真换了无上下文模型 / 是否真做了语义差分 / 内容质量如何」**。换模型语义差分目前靠 agent 自觉执行（autopilot 高价值篇值得显式派异模型一轮），不是强制门。诚实记住这层落差，别把"过了存在性门"误读成"语义已把关"。
   - 产出写入工作目录 `_stutter-list.md`，格式=逐条"引原句 + 哪类问题 + 一句改法"。允许"全文无硬错、无断点"的空结论，但必须逐段过完、文件必须存在——排版 preflight 断言它存在且非空，缺失 exit 2；mtime 早于 定稿.md 会提示重派。
   - 按清单逐处修复；改动大就重派冷读一轮，改动小则修复处前后连读确认即可。

扫完后，确认无误再将你的心血之作写进最终文件，**千万别在这个阶段让用户给你列修改清单**，请你发挥智能体的责任，**自己改好**再上菜。

### 编辑锚点（写作阶段预埋）

写文章时，在 2-3 个关键位置插入编辑锚点：

```html
<!-- ✏️ 编辑建议：在这里加一句你自己的经历/看法 -->
```

**选择标准（按优先级）：**
1. **观点判断处**：你写了"我觉得..."或"我的判断是..."的地方——创作者替换为自己的真实判断
2. **案例衔接处**：你写了"我见过一个..."或"我认识的一个朋友..."——创作者替换为自己的真实经历
3. **情绪表达处**：犹豫、感慨、愤怒的段落——创作者加入自己的真实情绪

**为什么这很重要**：AI 检测工具检测的是 token 概率分布。创作者在锚点位置加入 3-5 句自己写的话，就能显著改变这些段落的统计特征。

### 内容增强（大纲后、写作前执行）

进入正文写作前，根据当前风格路由加载对应的增强策略。详见 [content-enhance.md](content-enhance.md)。增强策略的输出（角度/素材/细节/用户声音）作为正文写作的输入约束，与大纲一起传入写作环节。

## 密度

八法则：

1. **砍**：这句能删吗？能和上一句并吗？
2. **短**：能用两个字说的不用四个字。「进行讨论」→「聊」。「实现功能」→「做到」。大词不让你显得聪明，只让人读得累
3. **造**：一句话装两层——表面说 A，结构暗示 B
4. **选词**：每个动词是一次判断。"放在"和"搁在"和"摆在"不是一回事
5. **节奏**：说到要害，句子变短。展开时允许伸长。短句独段（≤15 字独立成段）🔴 改按长段配比：每 2-3 个 100+ 字的长段可配 1 处（原"整篇最多两处"与金标实测冲突 -- 叙事流作者单篇用 5-8 处当情绪铆钉）。短句独段只做三件事：冷陈述 / 反问 / 口语接茬——拿来装金句口号就成节拍器了
6. **反模板**：同一种句式结构相邻段落不机械重复。🔴 开一个例外：全文**唯一**情绪顶点处，**允许**（不是鼓励）一组有意为之的 3-6 连同构排比（原创示例，演示情绪顶点的同构排比：「顺风的时候，你是团队的核心。加班的时候，你是团队的顶梁柱。裁员的时候，你是团队的成本。」-- 三句同构、语义递进、一句比一句冷），全文限 1 次，排完必须用 ≤10 字短句收口泄掉势能。⚠️ **本条限的是「情绪顶点同构排比（递进式，全文限 1，收口泄势）」**；[反 AI 写作工具箱.md](反 AI 写作工具箱.md) C1 的「拐弯式三连节奏锤（第三句出反常具体细节，整篇 1-2 处）」是**另一族技法、配额各自独立**，勿混为一谈
7. **接龙**：上句尾词与下句首词语义相连，首尾相接推着读者往下走。旧信息在前、新信息在后（本条只是索引——**单一来源与展开见 [§句间引力](#句间引力承接主防线--决定读完第一句想不想读第二句)**，不在两处各改一份）
8. **主语链**：连续 3 句以上尽量共用或就近切换主语——主语跳得太频繁读者会失去重心。切换时用"它""他""这件事"等回指词衔接，让读者始终知道"现在在说谁"
<!-- v5: C2 段落 BLOT 拆为两条 -->
9. **段落 BLOT**（保留通用）：每段第一句话交代本段主旨（Bottom Line On Top），一段只说一个观点
10. **全文 BLOT**（路由 opt-out）：读者只读每段第一句串联起来就能把握全文结构。**散文/智识杂文/沉吟体/反常识叙事路由内豁免**——反常识叙事 / 深夜长谈 / 资深长评 / 沉吟体 / 散文路由声明 opt-out 后，全文层不强制段首串读成立（段落 BLOT 仍守）

## 抽象层级

每件事都有多个抽象层，解释的艺术在于选对层。

- 太高（"计算机就是处理信息的"）→ 正确但无用
- 太低（细枝末节淹死人）→ 失去全局感
- 刚好：往上能看见全貌，往下能感觉到机制在运转

一篇文章里可以跨层——但每次跨层像函数调用：跳下去，拿到东西，跳回来。

## 段落间关系（源自《写作是门手艺》第十一篇）

段落不是"差不多字数就换行"。两段之间必须是以下三种关系之一——说不出是哪一种，就是凑字数，合并或删掉。

| 关系 | 怎么衔接 | 示例信号词（不一定要出现，但气口要在） |
|------|---------|-----------------------------------|
| **推进** | 上一段的结论变成下一段的前提，把论述往前推一步 | "所以""由此""这意味着""顺着这个逻辑" |
| **转折** | 上一段建立一个判断，下一段引入一个抗力，让读者意识到事情没那么简单 | "但""不过""等一下""反过来看" |
| **并列** | 两段在同一层级展开另一个维度或另一个案例，共同支撑同一个核心 | "与此同时""另一头""类似的" |

**并列的特殊规矩：** 并列段落最多连续 3 段——超过 3 段的并列，读者会觉得"怎么还在罗列"，需要用一段推进或一段小结来打破节奏。

**自检法：** 初稿完成后，在每两段之间写下"推/转/并"三个字中的一个。写不下来 → 关系不成立 → 该段需要重写或合并。

## 声音

**生成器：** 用不对称的容器装正经的内容。技术语言说人间事，大白话切哲学问题。

**参考频率：** 你想写成什么调子？把它写进 `profile/context.md` 的「我怎么说话」一节 --
例如「对话感 + 反直觉切入」「一句话叠三层意思」「手术刀式的冷幽默」。
写下来是为了校准方向，**不是为了模仿任何一个人**。

思维的毛边可以露出来。"等等，这不对"、"有意思"——不是表演犹豫，是真的在想。

## 口语化推荐表达

以下表达经过验证，能有效提升文章的人味和对话感。不必刻意堆砌，自然出现即可：

| 场景 | 推荐表达 |
|------|---------|
| 翻译抽象概念 | "说白了就是……""翻译成人话就是……" |
| 引发共鸣 | "我那时候也这样""我也是后来才想明白" |
| 举例说明 | "举个例子""我当时的感受是……" |
| 转折 | "但问题来了""等等，这不对" |
| 总结判断 | "一句话：……""说到底，……" |
| 坦诚不确定 | "老实说我也没想明白""大概率是……但不敢打包票" |

> 🔴 **「群体代言」反例（禁止使用）**：上方「姿态」第 7 条已明确"不借势：不用群体代言"——以下句式属于反例，不要写进正文：
> - ❌ "你们有没有遇到过……" / "懂的都懂" / "程序员都知道" / "我们都……"
> - 原因：群体代言把读者当成"一群人"对话，与本 skill 默认的"心里放一个具体的人，写给他"姿态冲突；同时拉低朴实简洁四条要求的"白话试纸"得分。
> - 想表达共鸣，改用"我也是后来才想明白" / "我那时候也这样"这类**第一人称单数**句式（见上表「引发共鸣」行）。

## Markdown 输出规范

- 文章顶部：`> **导读：** ...`（导读栏由 format_layout.py 自动注入，无需手动占位符）
- 文章标题：`# 标题`（H1，全文仅一次）
- 各大模块（H2）：`## 模块标题`（排版阶段自动转为 PART 01 编号格式，无需手写编号）
  - 🔴 **H2 命名规则**：详见 `iron-rules.md` 「H2 标题铁律」（保留正文标题，不写 PART/Part 前缀，`format_layout.py` 的 `_clean_h2_text` 兜底剥离）。
  - 副标题（如"新国标拆解""现场观察"）写到 `article-meta.yaml` 的 `part_subtitles` 按序号对齐，**不**写在 MD 里。
  - 🔴 **`part_subtitles` 数量必须严格等于 H2 数量**——`format_layout.py --all` 跑 H2 处理前会做前置断言，不对齐直接 `sys.exit(3)` 退出排版。正文写作中增删 H2 时同步改 yaml，别等到排版阶段才发现错位。每条 ≤10 汉字核心词，不要复述 H2 原文。
- 子节点（H3）：`### 子节点标题`（排版阶段自动转为时间线格式：绿色编号圆角方块 + 浅灰竖线）
  - 🔴 **H3 严禁手写编号前缀**（一、/ 1. / ① / （一） 都不要写）：format_layout.py 会自动在左侧生成主题色圆角方块编号，手写前缀会和方块撞（踩坑教训）
  - ✅ 正确：`### 独立的侧边栏 UI`
  - ❌ 错误：`### 一、独立的侧边栏 UI` / `### 1. 独立的侧边栏 UI`
  - 🔴 **何时必须用 H3**：H2 区块 ≥800 字无视觉切分 / 步骤·环节·案例列举 ≥3 个 / 连续 ≥5 段纯文字 -- 命中即拆，详见本文 §H3 子标题与防文字墙（实证：整篇 0 个 H3 会致长段字墙）
- 标签小节：`#### CASE 01 · 描述`（H4，可选）
- 金句：`> 引用内容`（全文不超过 5 处）
- 加粗（`**粗体**`）：核心结论、关键判断、金句的**关键词或短语**（≤15 字，严禁整句加粗）。**开篇区（正文开头→第一个 H2）每 80–120 字 1 处**（每段最多 2 处；信息锚点四型——专名首现/关键数字/时间窗口/对比结论——出现即标），前 30% 正文每 150–200 字 1 处（每段最多 1 处），中后段按字数分档密度（详见本文「加粗与重点标识」）。**全篇按字数分档上限**：<3000→25 / 3000-5000→35 / 5000-8000→45 / >8000→55
- 重点标绿（🔴 一律用 `<mark>词</mark>` 标签）：最核心的概念或判断，排版阶段自动转为主题色。**按字数分档**：<3000→5 / 3000-5000→7 / 5000-8000→9 / >8000→12，用在最值得记住的那几句。⚠️ **禁用旧写法 `***粗斜体***`**：baoyu 转换器会把 CJK 粗斜体吃成空 `<em>`、标记的字整个消失（2026-07-11 实证），`<mark>` 是 HTML 直通、不过转换器，唯一安全写法
- 文末：`---` 后接互动引导
- 禁止：HTML 标签、代码块、连续空行
- 手机端优化：每段不超 4-5 行，善用单句成段
- 🔴 **破折号统一用 `--`（两个英文连字符），禁止全角 `——`**（硬规则）：
  - ✅ 正确：`下面这件事很重要 -- 你必须知道`
  - ❌ 错误：`下面这件事很重要——你必须知道`
  - 适用所有给读者看的文字（具体适用/不适用边界详见 [iron-rules.md 破折号章节](iron-rules.md)，此处不重复枚举——以 iron-rules.md 为单一来源）

### 视觉节奏标记（写作阶段嵌入，排版阶段转换）

读者注意力有限，大段文字容易划走。写作阶段应**主动规划视觉断点**，在 Markdown 中预埋标记，排版阶段由 AI 排版助手转换为对应组件。

#### 要点提炼块（划重点）

每个 H2 模块末尾（或长段论述之后），用引用块标记核心要点：

```markdown
> **划重点**
> - 要点一（≤30 字，一句话说清）
> - 要点二
> - 要点三
```

排版阶段转换为 `key-takeaway.html` 卡片组件（主题色左边线 + 浅绿底色）。

**使用频率**：每 800-1200 字一个，或每个 H2 模块末尾。不要在开篇钩子区域使用。

#### 数据图表标记

当文章中出现数据对比、趋势变化、多维度评测等内容时，**不要只用表格**，应主动标记为图表需求。在 Markdown 中这样写：

```markdown
<!-- chart: bar | 标题 -->
| 品牌 | 市场份额 |
|------|---------|
| 小米 | 35% |
| 华为 | 28% |
| 其他 | 37% |
```

图表类型关键词：`bar`（柱状图）、`line`（折线图）、`radar`（雷达图）、`pie`（饼图）、`compare`（对比图）。

排版阶段会用 `baoyu-image-gen` 生成品牌色图表图片替换。详见 layout.md 步骤 3d。

**使用时机**：
- 3 项以上的数据对比 → 柱状图/饼图
- 时间序列变化 → 折线图
- 多维度评分/评测 → 雷达图
- 两个方案 A vs B → 对比图

#### H2 格式选择

H2 固定为 **PART 编号格式**（`01 PART | 标题`），H3 固定为**时间线格式**（绿色编号圆角方块 + 竖线包裹内容）。无需额外标注，`format_layout.py --all` 自动处理。

## 技术解读文的干货-故事配比

> 📂 **技术解读类选题（AI / 模型 / 工具，本 skill 主力题材）适用**：详见 [writing-genres.md §技术解读文的干货-故事配比](writing-genres.md)（随文体专属规则抽出）。核心一句话：故事为壳信息为核，每个 H2 至少 1 个可带走信息块，滑读能复述 ≥3 条干货。

## 篇幅控制

> 🔴 **字数铁律（v5 加固，与 outline.md §字数铁律对齐）**：以下数值**仅供参考估算，不是硬卡**。让内容自然决定长度——内容多时不硬压删值钱段落，内容少时不硬撑加冗余。详见 [outline.md §字数](outline.md) 同源说明。

- 正文 2500-8000+ 字（鼓励深度，**不设硬上限**；完读率低一点没关系）
- 开篇 200-600 字（参考）
- 每个 H2 模块 400-1500 字（参考）
- 结尾 100-300 字（参考）

**字数只是形式，核心守则：**每一段都应该有具体信息和故事支撑，不填充虚词。文字越长，每一句的信息密度反而更要高，避免重复和冗余。

## 自检与验收

### 两轮自检

**第一轮 · 逐模块精读：**

内容层（🔴 去重：加粗类 checkbox 收敛到 §磨 第 3 步加粗巡检单一来源，此处不再重复打钩）：
- [ ] **开头达标（按 [outline.md 步骤 3.5](outline.md) 分流双格判）**：深度启发类 = 开头两段有具体场景 / 首句钩子张力；资讯类 = 第一句即核心事实、无铺垫；成果 / 实作类 = 第一屏交付「成果是什么 + 能干什么 + 入口 + 真实产出示例」四件？
- [ ] 每个 H2 的核心结论一句话能复述？（**不要求加粗**——加粗口号全篇 ≤2，金句是收拢句不是预告句，见 [craft-techniques.md §金句锻造](craft-techniques.md)）
- [ ] **明信片复述**：能用 30 字把"这篇讲了什么、读者为什么该在乎"说出来？说不出来 → 核丢了
- [ ] **段落关系成立**：每两段之间关系明确是"推/转/并"三种之一？写不下来的衔接需要重写或合并
- [ ] 第一人称故事来自创作者素材？（seed 原话所在句还在、没被磨成书面语？）
- [ ] 数据标注来源和时间？
- [ ] 结尾落地且冷收？（不升华、不三段式互动——互动问题在排版层导读栏/留言位）**尾部升华 / 动员 / 展望段 ≤1 段（约 150 字）**：连续 ≥2 段无新信息的劝进 / 感慨砍到 1 段或删（🔴 典型冗余：结尾用近千字"动员下水"、或大段"我真正想说的是…"升华）。

去AI味层（🔴 去重：禁用词/元话语/量化项已由机器门与 audit_quant_signals 接管，人工只判语义）：
- [ ] 读出声终审过了？（[anti-ai-filter.md §7 终审门](anti-ai-filter.md) 两关）
- [ ] 无 AI 痕迹？（填充词、公式化排比、译感搭配——机器拦不住的语义类）

**第二轮 · 修复复查：** 针对第一轮修复的位置再读一遍，确认修复有效且未引入新问题。

### 自问自答意外检验（发布前守门员）

> 在自动写完这篇文章的瞬间，问你自己一次：你发现了什么之前没想到的增量信息？
> 有 → 确保它在文中够吸引眼球。没有 → 立刻滚回重写深层逻辑。不要拿水货糊弄用户！

### 验收四标准

1. 🔴 **想读完（第一标准 / 终审）**：每一段都让人想读下一段；读完第一句想读第二句。这是用户原始痛点的正解，凌驾于其他三条 -- 读不下去，其余三条都是空的。判据：随机翻段读首句，有没有被推着往下读？
2. **Grok**：读者能用自己的话复述核心
3. **零术语**：没有未解释的专业词
4. **记得住**：读完一小时后还能回忆起至少一个画面或判断

### 发布前素材门

> 🔴 进入 `format_layout.py --all` 之前的硬门 -- 由 `contracts.verify_publish_assets()` + `verify_article_meta_lead()` 强制执行。任一阻塞错误 → format_layout 直接 exit 2。

**verify_publish_assets**（6 项，阻塞）：

- 素材/*.png 全部在 定稿.md 中嵌入（自动排除 cover/hero/logo/bgm_cover 等不在正文嵌入的图）

## 定稿交付后的下一步建议（自动出现，让创作者选）

> 写完 `定稿.md` 后，**主动**输出 3-5 个具体下一步选项。不要写完就停手——给创作者明确的选择路径。

按当前定稿状态，从下面这组选项里挑 3-5 条贴合的：

- **进入排版**（→ baoyu-markdown-to-html 转 `定稿.html` → `format_layout.py --all` 一键品牌化处理 → 走 [layout.md](layout.md)）
- **再磨一轮**（针对你不满意的某个 H2 模块或某段 — 读 [anti-ai-filter.md](anti-ai-filter.md) 的对应层做精修，不重写整篇）
- **先磨标题**（→ references/title.md，5 个候选 + 排序 -- 标题选定后再排版，封面图与导读栏要用最终标题）
- **生成封面**（→ 封面已锁定 `montage-evidence` 单风格，无需选风格、无近 3 篇回避；按 [cover-styles.md](cover-styles.md) montage-evidence 模板直接生成）
- **暂存定稿，下次再排版**（更新 `.state.json` 把 `writing=done` + `layout=pending`，下次进目录 `pipeline.py status` 接续）
- **学习我的修改**（如果你已经手改了一遍 `定稿.md`：→ [learn-edits.md](learn-edits.md)，用 `learn_edits.py` 提取 diff pattern 写入 `playbook.md`，下一篇用上）

**给选项的写法范例：**

> 定稿已经写完，{字数} 字。下一步你想——
> 1. 直接进入排版（自动跑 format_layout.py 全套品牌化）
> 2. PART 03 我自己也觉得有点干，要不你就这一段精修一下
> 3. 先读 references/title.md 把标题敲定（封面图和导读栏要用最终标题）
> 4. 暂存，下次再说
>
> 默认走 1。

**为什么必要：** 写作 → 排版 → 配图 → 发布是一条链，但**每一步都不必立刻接下一步**。给创作者具体选项 = 给创作者节奏控制权。
