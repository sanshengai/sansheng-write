# 标题锻造（内联）

> 「写 标题」阶段由当前写作模型直接锻造，不调用外部标题 skill。理由：套路化的「戏剧化悬念」标题与本 skill「靠洞察不靠噱头」的调性不合。本文件 = 起标题方法 + 品牌校准，标题逻辑收在本 skill 内部。

## 🔴 标题偏好（凌驾下方一切「悬疑/钩子」倾向）

本 skill 的标题走 **直球 + 关键词前置**，不走悬念钩子。这是明确的品牌策略，理由：

1. **直白告知核心 + 价值**：快信息时代，读者没时间看无意义内容。标题要让人一眼知道「这篇讲什么、能给我带来什么用」。
2. **关键词前置（工具 / 产品 / 主角专名）**：罗列读者可能关注的工具名（Claude Code / Codex / 反重力 / 某模型……）。原因：① 算法（尤其短视频 / 推荐流）优先推「有用工具相关」内容，关键词 = 流量入口；② 观众看到熟悉的工具名，有**亲切感、实用感**，而不是面对一句无意义的调侃。
3. **反钩子审美疲劳**：多自媒体时代，「悬念 / 留白 / 调侃 / 卖关子」式丢钩子标题已让人审美疲劳。本 skill 偏直球，不玩悬疑套路。

> 落地：出标题时**默认走「直击核心 + 关键词前置」**；问句 / 悬疑 / 冲突类只在「悬念真能服务那个反常识洞察」时偶尔用，**不作默认、不硬塞**。候选里直球版排前面，**不硬劝换钩子标题**（品牌已定调走直球）。

## 角色

当前写作模型拿到内容后直接给标题。不是套模板凑名字 -- 是让读者在信息流里一眼认出「这跟我有关、有用」。标题是高速路旁的广告牌：一扫而过，**说清楚「是什么、有什么用」的，比卖关子的，更留得住人**。

## 两条秩（方法论地基）

1. **一语道破核心 + 价值** -- 读者一眼知道「讲什么、对我有什么用」，不用读第二遍。短 > 长，直接 > 间接，具体 > 抽象。⚠️ 区分清楚：劝退的是**抽象专业术语 / 泛泛组合词**（涌现 / 范式 / 赋能 / 新生态）；读者认得的**工具 / 产品 / 主角专名**（Claude Code / Codex / 某模型）不是毁标题的词，反而要前置。
2. **关键词前置，直球告知**（替代旧版「悬疑勾人」）-- 把读者可能搜 / 关注的工具 / 产品 / 主角名放标题最前，让人第一眼认出「跟我有关、有用」。本 skill 不靠悬疑钩子拉黏度（那套已审美疲劳）；黏度来自「直白说清有用的事」+「熟悉关键词带来的实用感」。详见顶部 🔴 标题偏好。

## 🟢 品牌校准（与通用起标题最不同的地方，也是过去不满意的修正方向）

本 skill 调性 = 真实、务实、靠洞察吸引，不靠噱头。所以：

- **洞察 > 戏剧**：标题的钩子来自「文章里那个最反常识的真实发现」，不是套路化悬疑句式。先问自己「这篇最反常识的一句话是什么」，把它做成标题；不要硬套「为什么…」「这背后…」「真相是…」的空壳。
- **具体 > 聪明**：宁可朴素说清一件具体的事，也不要为了显文采而绕。一个具体的人 / 数字 / 动作 / 画面 > 一个漂亮的抽象概括。
- **不标题党**：标题承诺的，正文必须兑现。以偏概全不可避免（标题只引介、不概括全文），但不能引介一个文章里根本没有的东西。
- **关键词前置**：如果文章核心是「读者一眼就该认出的事」（某新模型发布 / 某平台改版 / 某事件），把那个关键词（模型名 / 平台名 / 主角）放在标题最前面，让读者第一眼知道这篇在说什么，再用后半句给差异化钩子。

## 安·兰德权重

90% 恰当（appropriateness）× 5% 清晰（clarity）× 5% 戏剧性（drama）。恰当是地基，戏剧是装饰。**本 skill 尤其要把「恰当」吃满 -- 宁可不够戏剧，不可不恰当。**

## 🔴 第一步：定分类标签前缀（出候选前先做，5 个候选统统带前缀）

本 skill 的对外文章外标题**一律带 2 字分类标签前缀**，格式 `标签 | 正文标题`（半角竖杠 ` | `，两侧各留一空格；如「精选 | 三款工具横向对比」）。它是读者在信息流里一眼归类的可见信号，也与网站 / RSS 的对外分类同源。

> 🔴 **必须在「出候选」这一步就锻进每个候选，不是发布时才补**。根因教训：标签过去只写在发布 / 归档阶段的 `outward_category` 字段（一句注释、无执行点、且晚于标题盲选），导致盲选交给作者的全是**裸标题**，选定后标签就丢了 -- 近期只有个别文章偶然补上。把「定标签」提到出标题第一步，前缀随候选一起盲选，才不会漏。

**定标签：7 选 1，走裁决链**（自上而下首个命中即定，与 `templates/article-meta.template.yaml` 的 `outward_category` 同源，保唯一归类）：

| 标签 | outward_category | 命中条件 |
|---|---|---|
| 教程 | tutorial | **面向新手的系统性教学**（手把手、从零、系统课）——工具安利 / 成果展示不算，归「分享」 |
| 精选 | picks | 多个（≥3）横向合集 / 清单 / 榜单 |
| 分享 | share | 自创成果（工具 / skill / 网站新功能）、亲测好物安利、珍藏书籍推荐——「我做了 / 我在用 / 我觉得好」 |
| 行业 | industry | 主体是某垂直行业本身（地产 / 工程…） |
| 资讯 | news | 刚发布 / 新品 / 大事件（新闻播报视角，无亲测背书） |
| 洞察 | insight | 对 AI / 行业的趋势判断 · 观点 |
| 随笔 | essay | 个人成长 / 生活（兜底） |

裁决链顺序：**教程 > 精选 > 分享 > 行业 > 资讯 > 洞察 > 随笔**。「分享」与「资讯」的分界 = 有没有作者亲测 / 自创背书（分享是"我用过 / 我做的"，资讯是"它发布了"）。定完标签后：

1. 下面 5 个候选**每个都带同一个 `标签 | ` 前缀**（同篇标签唯一，5 个候选前缀相同，变化的只是竖杠后的正文标题）；
2. 把定的 `outward_category` **立即回填 `article-meta.yaml` 的 `outward_category` 字段** -- 发布 / 归档（`pipeline.py archive/finalize`）直接复用它，保证标题里的标签与网站 / RSS 完全一致，archive 不再二次判类。

## 执行：出 5 个候选，覆盖 5 种策略

| # | 策略 | 说明 |
|---|------|------|
| 1 | 直击核心 + 价值 | 一语道破「讲什么、有什么用」（🟢 默认首选） |
| 2 | 关键词前置 | 工具 / 产品 / 主角名打头，算法友好 + 给读者实用感（🟢 默认首选） |
| 3 | 具象 | 用具体数字 / 动作 / 画面替抽象概念 |
| 4 | 问句 / 冲突悬疑 | ⚠️ 非默认、少用：仅当悬念真能服务那个反常识洞察时才用 |
| 5 | 自由 | 以上策略的组合或其他创意路径 |

5 个候选里，**策略 1 / 2（直球 + 关键词）的版本排前面**。每个标题附一句话：为什么读者一眼能认出它有用。**每个候选前统一带第一步定好的 `标签 | ` 前缀**（前缀不占策略差异，变化只在竖杠后的正文标题）。

## 排序 + 推荐

按安·兰德权重排序，标注推荐第一名。本场景下「恰当度」实际权重最高 -- **一遍读懂 + 想点进去 + 不标题党，三者都过的排前面**。

## 品牌硬约束（出标题前逐条过）

- 🔴 破折号一律用两个英文连字符 `--`，禁止全角 `——`
- 长度：对外标题（封面 / 简介 / 小红书）≤ 20 字为佳，微信正文标题 ≤ 30 字为上限，超了就砍。**长度计入分类标签前缀**（`标签 | ` 约占 4 字），超限先砍竖杠后的正文标题、不砍标签。小红书算法计字：中文 / emoji 计 1 字、英数计 0.5 字、空格不计
- 模型版本号 / 价格 / 日期等具体数字必须已核实，不确定先查再写
- 标题含对外期数 / 版本号时从 v1 起算（不照搬内部 git 版本号）
- 🔴 **封面标题 ≠ 外标题**：本文锻造的是「外标题」（卖"为什么点开"）；封面主标题是另一层（卖"里面讲什么核心"），走 [cover-styles.md 封面文案四招](cover-styles.md) -- **封面不复述外标题核心关键词**，别让两处一个意思。**blueprint 蓝图闸启用时**，每个外标题候选须当场配好这套封面文案（L1/L2，风格含 ghost 层的一并给 3 词），组成「标题+封面」配套视觉方案一包交付作者选定（见 [outline.md 步骤 8](outline.md)）。

## 5 步质检（逐条过，不达标就地换）

1. **一遍即懂**：读一遍就知道在说什么？要读两遍 → 改
2. **黏性（直球版）**：读者一眼能不能认出「跟我有关、有用」？无感 → 不是去加悬念钩子，而是把核心价值 / 关键词说得更直白、更醒目
3. **长度**：超 20 / 30 字 → 砍
4. **恰当**：标题和正文匹配吗？标题党 → 回到恰当
5. **人味**：像人起的还是机器生成的？

## 🔴 定稿标题后：同时锻造「封面三件套」

外标题定下来后**不要停** -- 封面上的字是另一套文案，必须在这一步一并定死，
不能留到生图时让模型现挑。产物写进 `article-meta.yaml:lead`：

| 字段 | 是什么 | 硬约束 |
|---|---|---|
| `lead.line1` | 封面 **L1 主标题** | **4--7 个汉字位**（数字/半角按 0.5 折算），硬上限 8 |
| `lead.line2` | 封面 **L2 副标题** | **≤ 12 个汉字位**，单行 |
| `lead.accent` | L2 里染主题色的**落点词** | **2--5 个字**，且必须是 line2 的**结尾**子串 |
| `lead.subtitle` | 底部品牌胶囊的标签 | 写成 **YAML 列表 = 2--4 个短标签**；写成字符串则只渲一条 |

**上限为什么是硬的**：L1 要占画布高 12%--14% 才能成为视觉主体，反推左区
只放得下约 8 个汉字。**超一个字，模型就只能缩字号**，封面规范再严也压不住 --
第 81 篇封面翻车正是这么来的（详见 `cover-styles.md` 的字号层级节）。

**下限没有硬约束，别为了凑字数注水**：sandy 2026-07-28 原话 --
「四个字也挺好……如果有一些文章，四个字五个字能说清楚的，我觉得也够了，没关系。」
第 80 篇「生意变了」正是四字范例。**能四个字说清就四个字**，
6--7 字是舒适上沿，8 字是不可越的硬顶。

**`lead.subtitle` 写成列表的例子**（第 76 篇那种三标签胶囊）：

```yaml
lead:
  subtitle:
    - "5h/7d 额度"
    - "触顶预警"
    - "免费全中文"
```

用列表而不是拿 `/` 切一个长字符串 -- 标签自身就可能含 `/`（「5h/7d 额度」），切了必错。

**落点词怎么挑**：选那句话的**语义落点**，也就是读者读完最该记住的动作或结论。
好例：「从抢年轻人，到**抢老人**」/「两端装上，一直**看得见**」/「排进**一张日历**」。
坏例：染开头、染虚词、染满整行。**L1 一个字都不染**。

**和外标题的关系**：外标题是给列表页和朋友圈看的完整句，封面文案是给缩略图看的
短句 -- **不要把外标题原样塞进封面**。外标题可以长、可以带「分享 |」前缀；封面必须短、
必须一眼读完。

输出时把三件套一起给出，例如：

```
封面三件套（已回填 article-meta.yaml:lead）
  L1  54 次额度重置        （7 字位 ✓）
  L2  排进一张日历          （6 字位 ✓）
  染  一张日历              （4 字，line2 结尾 ✓）
```

## 输出格式

直接在对话中输出，不写文件、不生成时间戳：

```
分类标签：洞察（outward_category: insight） -- 已回填 article-meta.yaml

[推荐] 1. 洞察 | 标题文本
       -- 一句话说明

2. 洞察 | 标题文本
   -- 一句话说明
...
```

（首行先亮标签+已回填 meta，5 个候选统一带 `标签 | ` 前缀。）用户要更多就继续迭代生成候选。
