# 小红书轮播图文剧本

> 低频、按篇显式触发。用户说「转小红书」「小红书图文」「拆图文」「做卡片」时使用；
> 日常公众号发布不自动加载。渠道文案、比例、链接与派发规则同时服从
> [distribute.md](distribute.md)。

## 定位与产物

本模块把一篇已定稿文章重新讲成 6--10 张 3:4 轮播卡片，不按原文段落切片，也不试图把
全文塞进图片。它负责选择传播命题、页序、逐页文字与视觉结构；像素生成统一交给
`baoyu-image-gen`。

产物全部放在源文章目录：

```text
dist/xhs/
├── xhs-outline.md
├── prompts/
└── images/
    ├── 01-cover.png
    └── ...
```

推荐 1242×1660；脚本按 3:4 比例验收。中间提示词、批处理清单与生成凭证也留在
`dist/xhs/`，不得写到全局目录或另一篇文章下。

## 1. 先选唯一传播命题

通读 `定稿.md` 后先输出四项：

- 一句话传播命题：这组图只讲什么。
- 目标读者：谁会因它停下来。
- 读者收益：滑完具体得到什么。
- 证据清单：原文里的机制、数据、对比、案例、流程或结果。

选择标准不是「原文写得最多」，而是「最有用、最反直觉、最能被证实」。一套图只有一条
主线；与主线无关的精彩段落也要舍弃。

产品 / 工具 / Skill 类文章先讲结果，再讲机制：

| 页 | 作用 | 内容合同 |
|---|---|---|
| P1 | 成果亮相 | 一句话说明它替读者完成什么 |
| P2 | 痛点 | 旧方法最具体的时间、质量或协作损耗 |
| P3 | 解法 | 新方法的核心机制，不写空泛形容词 |
| P4--P6 | 核心卖点 | 每页一个功能 + 工作方式 + 结果 |
| P7 | 工作流 / 示例 | 输入 -- 处理 -- 交付 |
| P8 | 适用人群 / 获取 | 谁适用，项目公开在哪里 |
| P9 | 收束 | 一句可信承诺 + 站内互动 |

观点 / 资讯类文章改用「结论 -- 问题 -- 证据 -- 反转 -- 方法 -- 行动」；不强套产品骨架。

## 2. 每页只做一件事

每一页都必须写明：

```yaml
page: 4
role: proof                 # cover | pain | mechanism | proof | flow | action | ending
layout: comparison          # sparse | balanced | dense | list | comparison | flow
claim: "一句完整、可判断真假的核心结论"
title: "读者在缩略图里也能读懂的标题"
support:
  - "支撑点一"
  - "支撑点二"
visual: "一个具体物象或信息结构"
swipe_hook: "只在确有下一层信息时使用"
```

硬标准：

- 标题必须是结论，不用「亮点一」「还有更多」「功能介绍」等占位词。
- 支撑点必须回答「怎么做到 / 有什么证据 / 带来什么结果」之一。
- 每页 1--3 个支撑点；只有确需清单或数据表时才增加密度。
- 单页独立有价值；相邻页之间有因果、对比或递进。
- 同义改写、重复图标与重复流程都算重复页。
- 数据与能力边界忠实于原文和已验证材料，不能为了宣传新增事实。

## 3. 布局随内容变化

不固定整套布局，但至少使用三种信息结构：

- `sparse`：封面、强结论、收束。
- `comparison`：旧方法 / 新方法、误区 / 真相。
- `flow`：流程、步骤、输入到交付。
- `list`：功能、检查项、适用人群。
- `dense`：确有 4--6 个同级事实的数据页。
- `balanced`：故事、背景、机制说明。

布局由信息关系决定，不能为了「丰富」随机换模板。整套共享统一色板、字体气质、插画语言与
logo 安全区；页面构图可变。

默认视觉基线为低饱和编辑设计：米白底、灰蓝 / 棕红强调、深色正文。用户指定 retro 时采用
纸张、印刷线条与复古图标语言，但压低饱和度，避免高纯度橙黄铺满画面。

## 4. 编译原生生图提示词

每页 prompt 以 `xhs-outline.md` 为单一真源，至少包含：

1. 画布为 3:4 竖版信息卡。
2. 本页全部可见中文，逐字列出。
3. 信息层级与布局关系。
4. 具体物象、图表或流程节点。
5. 全套色板、字体气质与纹理。
6. logo 参考图及固定位置；未提供 logo 时不凭空生成品牌字样。
7. 禁止出现未列出的随机文字、网址、二维码或联系方式。

文字、视觉与可选 logo 必须在同一次 `baoyu-image-gen` 请求中原生生成。禁止：

- 先做无字底图，再用 SVG / HTML / Canvas / Pillow 或其他模型补字。
- 从另一张图裁切、拼贴或套模板来修正文案。
- 用封面当后续每一页的结构参考，导致九张图构图雷同。
- 生图错字后手工覆盖；正确做法是修 canonical prompt 后整张重渲。

先单独渲染 P1 试片。试片通过后，若总图数 ≥4 且当前 provider 支持 batch，就把全部独立
prompts 一次批量提交；不支持 batch 时才串行。批量模式不改变逐页独立 prompt 与逐页 QA。

## 5. 逐页验收

每张图都要以原图和缩略图两种尺度检查：

- 可见中文逐字正确，未漏字、重复字或新增随机字。
- 核心结论 2 秒内可识别，正文在手机宽度可读。
- 视觉确实表达本页观点，不是通用装饰。
- 比例为 3:4，重要文字不贴边。
- logo 位置、尺寸、留白一致，且不遮挡内容。
- 与前后页没有同义重复，页序可连续阅读。
- 原文观点、数据、功能边界没有被夸张或捏造。

任何一项失败都修改本页 prompt 并整张重渲。没有「无字版 + 后期配字」「先交付再补」或人工
豁免路径。

## 6. `xhs-outline.md` 最小头部

```yaml
---
source: 定稿.md
thesis: "这套图唯一要说清的传播命题"
audience: "目标读者"
reader_gain: "滑完获得的具体价值"
image_count: 9
aspect: "3:4"
style: "muted-retro"
layouts_used: [sparse, comparison, flow, list]
logo_position: "top-left"
---
```

页数按主线所需信息决定，不按原文字数机械增长。通常 8--9 张最容易形成完整故事；内容不足时
宁可 6 张讲透，也不做 10 张空卡。

## 7. 最终检查

- [ ] 一句话传播命题明确，全套没有第二条主线。
- [ ] P1 给结果或反差，不只是文章标题。
- [ ] 产品页回答功能、机制、结果，而不是堆「智能 / 高效 / 专业」。
- [ ] 每页一个结论，删除任何重复页。
- [ ] 至少三种布局，布局与信息关系匹配。
- [ ] 全部图片来自同一原生生成链，文字与 logo 没有后期叠加。
- [ ] 逐页文字、事实、比例、缩略图与页间一致性通过。
- [ ] 正文与图片互补，且符合小红书站内规则。
