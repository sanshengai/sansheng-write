# 执行卡：教程

> 写教程前只读这一张；出处是查阅入口，与原文不一致时以原文为准。下文 `pipeline.py` 指 `python "$SKILL/scripts/pipeline.py"`，在文章目录运行。

## 一、适用范围

- **教程 = 面向新手的系统性教学**（手把手、从零、系统课），对外分类 `tutorial`，标题标签「教程」。工具安利、成果展示（「我做了 / 我在用 / 我觉得好」）不算，归「分享」，不用本卡。（出处：title.md §定分类标签前缀）
- 新篇用 `pipeline.py new "<选题名>" --genre tutorial` 建目录，预填 `genre: 教程文`、分类 `TUT` / `tutorial`、开篇策略 `直入`、逻辑骨架 `ASC`；不复制上一篇的 article-meta。（出处：autopilot.md §主流程）

## 二、写前准备

1. 先跑 `prep_writing.py` 生成 `_prep-context.md` 再动笔，跳过它排版门会拦。（出处：writing.md §写作前第一步）
2. **读者起点**：别高估也别低估读者，入门读者要白话和类比，术语当场翻译。照着做要备齐的设备、账号、费用列清楚。（出处：outline.md §受众分析；writing.md §读者意识）
3. **版本、价格、界面锁日期**：动笔前现场核官网，写「截至某年某月某日」，不写「目前」；查不到的额度、价格不硬给，改模糊表述或删。（出处：fact-check.md §怎么核；writing.md §展开并写）
4. **每一步亲手走到底再写**：中途报错先排查走完，再下「能行 / 不行」的结论，没走到底只能写成推断、交代不确定。「我照做了」只写作者真走过的。（出处：material-integrity.md §来源类型；material-integrity.md §细节真实性）
5. **截图边走边截**：作者截图保留原图，放 `素材/作者素材/` 或用 `shot-` 前缀；`素材/` 第一层的 png 都要在正文引用，否则素材门会拦。（出处：image-routing.md §先判断是否应当生图；release-runtime.md §视觉任务单；writing.md §发布前素材门）
6. 正文引用的作者截图 ≥4 张时，在 article-meta 写 `infographic_mode: "author-shots"`（tutorial 预设不开），截图替代信息图：`visual-plan.json` 的 infographics 留空，封面、Hero 照常。（出处：iron-rules.md §发布主链；image-routing.md §固定视觉集合）

## 三、结构

1. **标题**：`教程 | 关键词锚点：一句由正文主干兑现的话`。锚点是读者会搜的工具名，属性不自明就补（「X 入门」）；冒号后按原话型 > 具象型 > 处境型选，每个候选写明兑现在正文哪一节。禁揭穿式反差、悬念、内部编号、标题党词。（出处：title.md §唯一公式；iron-rules.md §内容与归档）
2. **开篇先让读者看到做完是什么样**。「X 怎么用」走直入，第一句说它是什么、能干什么；作者亲手做成的走成果前置，第一屏给成果、用途、入口和一个真实产出。不讲故事钩子、不做概念铺垫，个人经历最多一句、放在事实之后。开头候选只出直入式，和大纲、标题一起交作者拍板。（出处：writing-genres.md §教程文特殊规则；outline.md §开篇策略分流；writing.md §开头候选盲选；autopilot.md §主流程）
3. **骨架**：先看结果 → 核心概念（一句话 + 类比 + 表格）→ 怎么做（分步骤 + 截图）→ 实战演示（完整走一遍真实场景）→ 拿走即用（入口 + 速查表）。长度跟着材料走，不预设。（出处：outline.md §交付给主笔；outline.md §文体识别）
4. **步骤**：
   - 一组步骤先说做完能得到什么，再列一二三。（出处：writing.md §三条直球守则）
   - 步骤、环节 ≥3 个宜拆 H3，一个 H2 连排 ≥800 字必拆（排版自动编号，不手写「一、/ 1. / ①」）；H3 里的细操作用有序列表 `1.`。（出处：writing.md §展开并写；writing.md §Markdown 输出规范；polish-whitelist.md §序数词当小标题）
   - 一步一个动作（「每句一件事」落到步骤上）。要对照界面的步骤配截图，写作期可先留 `[截图：描述]`，定稿前全换成真实图片。（出处：writing.md §展开并写；writing-genres.md §教程文特殊规则）
   - **出错怎么办写进正文**：真走时的报错、被拦的操作、怎么退回原状，当避坑提示写；做不了的情况（适用边界、反面案例）也写。（出处：writing-genres.md §干货-故事配比；material-integrity.md §材料与推理分账）
   - 每段 1-3 句；表格优先于段落（源规则至少 3 张）。（出处：writing-genres.md §教程文特殊规则）
5. **结尾**不总结、不升维，落在读者下一步动作上（先试哪一步、哪些别做），说完就停。profile 配了收尾白名单或禁问句收尾时，preflight「结尾落点」会查，`closing_type` 从白名单里选；没配就先做删除测试，再从收尾菜单选。（出处：writing-genres.md §教程文特殊规则；writing.md §三条直球守则；anti-ai-filter.md §1.5 收尾菜单）

## 四、逐段写法

1. **三条直球守则**：删了意思不变就删；不设悬念、不埋倒钩；每个 H2 先给本节结论。（出处：writing.md §三条直球守则）
2. **材料先承重**：每个核心 H2 对上一条真实材料（亲测、官方文档、可重现步骤）；不够先补搜，再收窄或合并 H2，不拿解释和类比撑篇幅。（出处：material-integrity.md §材料闸门）
3. **来源不过界**：官网和亲测是直接核验事实，厂商宣传、开发者自报、没复现的第三方测试写「其称」，推断写「我判断」并交代依据；先后不等于因果。引用开发者原话，交代他在卖什么。（出处：material-integrity.md §来源类型；anti-ai-filter.md §8.2 Prove It）
4. **逐段有新增**：每段推进一项事实、动作、例子、区分或后果。读者看完一节能不能 5 分钟内动手？不能就补步骤、工具名、参数、命令。（出处：material-integrity.md §逐段信息账本；content-enhance.md §密度强化）
5. **句间引力**：上句尾的新信息，下句开头接住（顶真，旧在前新在后）；句尾留的问号，下一句立刻答。（出处：writing.md §句间引力）
6. **术语落地**：非技术读者看不懂的词（API、token 之类）首次出现就补一句人话。（出处：semantic-review.md §找什么）
7. **命令、按钮、路径**：按钮名、菜单路径照界面原文写；命令、配置、路径、参数放行内代码或代码块，能直接复制，这是通用「禁代码块」的文体例外。（出处：writing-genres.md §教程文特殊规则；outline.md §文体识别；writing.md §Markdown 输出规范）
8. **符号与链接**：破折号一律 `--`（代码、URL 除外）；中文与英文、数字之间留半角空格；中文旁的标点用全角，半角标点硬门会拦（代码区不扫）。要读者打开的网址单条走 link-card、多条放文末 DEEP READ，不裸贴。（出处：writing.md §Markdown 输出规范；transcribe.md §引用分档；writing.md §发布前素材门；layout-reference.md §链接卡）

## 五、写后必做（按顺序）

1. 写完正文立刻 `pipeline.py preflight`，把静态问题（标题公式、H2 与 `part_subtitles` 对齐、开篇标识、文末模块、裸 URL）一次清完。（出处：autopilot.md §主流程）
2. **磨稿**：读出声 → 白名单减法（步骤清单的同构句不动）→ `pipeline.py verify writing` + `audit_quant_signals` → anti-ai-filter 语义层。每处改动先过「过度矫正三问」。（出处：autopilot.md §主流程；polish-whitelist.md §相邻句结构同款；anti-ai-filter.md §8.4 过度矫正三问）
3. **事实复核 + 语义冷读**同窗口并行，都派无上下文 subagent，都审当前定稿（出处：autopilot.md §并行）：
   - 事实复核：便宜档检索、强档裁决，产 `_fact-check.md`，每条 `- [✓] <原句> -- <证据>`，标记只用 ✓ △ ✗ ⚠️ 待核实。教程重点核版本号、价格与额度、日期和专名拼写；步骤能否复现以作者亲测为准。✗ 改完复跑，待核实项改模糊或删并列给作者。（出处：fact-check.md §谁来跑；fact-check.md §核什么；fact-check.md §条目格式）
   - 语义冷读：换模型族，产带签名的 `_stutter-list.md`，靶子含术语落地、时间线自洽。换族不可用只降到全新会话同族，不许同会话自审；冷读后又成段改稿就重派。（出处：semantic-review.md §怎么派；semantic-review.md §找什么）
4. **文末**：正文 → DEEP READ（最多 1 篇强相关旧文 + 自有阵地）→ SOURCES（正文实际用过的来源），用标准模板，不拿 H2 或裸 URL 冒充。（出处：layout.md §文末双模块合同）
5. **作者说过之后**：`pipeline.py approve draft --source-mode author-provided-final --words "<作者原话>"`，再 `pipeline.py adopt-final --final 定稿.md --meta article-meta.yaml`，之后只按 release-runtime.md 走；不代签，不手写审批文件。（出处：release-runtime.md §接管作者定稿；iron-rules.md §发布主链）

## 六、常见返工点

- **步骤没亲测**就下结论 → 回去走通，没走通写成推断。（出处：material-integrity.md §来源类型）
- **截图与文字对不上** → 截图是一手事实，改正文。（出处：writing.md §两轮自检）
- **版本、价格过期** → 核官网，写核实日期。（出处：fact-check.md §核什么）
- **术语没解释** → 首次出现补一句人话。（出处：semantic-review.md §找什么）
- **工具安利写成教程** → 改归「分享」。（出处：title.md §定分类标签前缀）
- **结构照抄上一篇** → 用 `new --genre tutorial` 重建，H2 按本篇材料对账。（出处：autopilot.md §主流程；material-integrity.md §材料闸门）
