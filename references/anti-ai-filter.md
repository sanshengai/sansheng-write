# 去 AI 味过滤清单

> **定位**：磨稿阶段专用检查清单。写作阶段不需要加载此文件——完成初稿后，在「磨」阶段逐项检查。
> 
> **总原则**：不是"写完再修"，而是"从第一句话开始就像人在写"。AI 检测工具分析的不是个别词汇，而是**整篇文章的统计指纹**：token 概率分布、突发性、句长方差、情绪极性、词汇丰富度。

> 🔴 **重定向（写作引擎"顺但没味道"诊断）-- 读本清单前必读：**
>
> 1. **优化目标是"一个人读得顺"，不是"骗过检测器"。** 把人味拆成几十个可量化代理（句长方差≥15 / 温度带占比 / 情绪极性≥20% / 副词密度…）去刷，会刷满代理却丢了本体——这正是 Goodhart 陷阱（指标一旦成为目标就不再是好指标）。**每项都打钩的文章完全可以读起来僵硬，因为"流畅"不是任何单项指标的和，是整体涌现属性。**
> 2. **全部量化数值已从正文物理删除** -- 只贴"降级为参考"的标签被实证无效（"给数字但说别当真"≈"当真"）。数值体检统一收口到 `contracts.audit_quant_signals`，磨稿后跑一次出纯参考报告。为达标而人为插入的短句/方言词/类比，往往跟前后语义不承接，造成"跳但不连"的割裂——配额化的多样性是一种新的公式化。
> 3. **「读出声 / 想不想读下一句」是凌驾一切量化指标的终审变量。** 任一指标修改若伤了语流或句间承接（见 [writing.md §句间引力](writing.md)），**以语流为准、回退该指标**。
> 4. **磨稿顺序：先一气呵成出连贯初稿（只管思路连贯与人味）→ 整篇读出声（终审）→ 最后才做指标级精修，且精修后必须再读一遍整篇确认没把语流磨碎。** 不要边写边切块各自刷指标——那会让承接变成事后拼接、把初稿毛边提前磨平。
> 5. **稳定的文风（同一个人在说话）是品牌资产，不是缺陷。** 凡是为"反跨文章指纹"而要求"刻意制造差异/漂移/随机"的条款（§1.6 风格漂移、维度随机化等），一律服从"全篇是同一个人在稳定地说话"，变化服从内容、不服从抽签。
> 6. **🔴 信息密度与语流同级：去 AI 味的本体是「内容精炼、干货充足、不绕弯子」，不是句式伪装。** 磨稿终审在「读出声」之外**增设信息增量查**——逐段问「删掉这段，读者损失什么」，答不上来就删。句式再像人、没有干货也是 AI 文；充分用 AI 的搜索优势把每个论断喂上数据 / 实例，比雕琢句子更去 AI 味。下文所有"句式伪装"类技法（破句 / 意外用词 / 自嘲 / 喻体 / 设问 / 闲笔）一律服从这一条：**只在有真实素材、真能增信息时才用，绝不为凑"人味特征"而硬插空转句。**

## 一、统计层（节奏与分布）

> 现象：AI 文本的节奏均匀、可预测、低方差；人写的东西不均匀、有起伏。让节奏跟着内容走自然就有起伏（不是为"反检测"而抖动，见顶部重定向第 1 条）。

> 🔴 **物理降级说明（§1.1-§1.4 / §2.2-§2.3 / §3.1-§3.2 适用）**：本章原有的全部数值配额（句长标准差 ≥15 / 四温度带占比表 / 每 500 字配额 / 负面情绪百分比 / 每 100 字副词数…）已从正文**物理删除** -- "给数字但说别当真"被两次实证等于"当真"。数值体检移入 `contracts.audit_quant_signals(article_path)`，磨稿后跑一次出**纯参考报告**（永不阻塞）。每节只保留一段机制描述：知道 AI 的病长什么样，写的时候自然避开，不对着数字写。

### 1.1 句长节奏（机制描述）

AI 的句子长度趋于均匀，人类长短交替剧烈——该长则长，说到要害就断。自然写就有落差；**为凑落差而插入的短句若与前后语义不承接，是更重的 AI 味**。

### 1.2 词汇温度（机制描述）

AI 倾向窄词汇、高频词；真人会在**同一段内**自然混搭书面语和口语（"从边际效应的角度看，这事儿真挺不靠谱的"）。让用词跟着内容走：讲概念时收、讲体感时松。不再有占比表 -- 配额化选词是新的公式化；词汇黑名单由机器 grep 兜底（B-主门），`profile/corpus/vocab-pool.md` 留作离线参考。

### 1.3 段落节奏（机制描述）

人类的段落有长有短：长段铺开一件事，一句话的短段用来强调、转折、吐槽。手机端一段别压太多件事。短段是武器不是装饰——用在真有东西要钉住的地方（用法详见 [writing.md §密度法则 5](writing.md)）。

### 1.4 情绪真实（机制描述）

情绪过于中性是 AI 中文文本的显著特征；真人有真情绪——不满就说不满，失望就说失望，情绪弧线随内容自然起伏（开头克制 → 中间爆发 → 允许犹豫 → 结尾不工整）。不再设负面占比百分数；白描段落天然低情绪是正常的（白描技法见 [craft-techniques.md](craft-techniques.md)）。

**仍要避免的模式化（定性，不是配额）：**
- 全文同一种情绪强度平铺直叙
- 每段末尾都用反问句（另一种模式化）
- 口语词匀速分布（每 200 字准时一个"讲真"）
- 总结性收尾（"让我们拭目以待"/"未来可期"）/ 连续文章相同收尾结构

<!-- 「克制悲悯」适用路由校准：此基调只授权「沉吟体」路由，别把它挂到不含此子模式的其他路由上、制造幻影路由。outline.md 第 6 种基调同此口径。 -->
**六种情绪基调（按内容任选其一，整篇内部允许微调但不大跳）：**
热血激昂 / 沉静理性 / 戏谑反讽 / 温情怀旧 / 焦虑担忧 / 克制悲悯（**仅沉吟体路由**，全程书面感负面词、不爆发不抒情；其他不含此子模式的路由不授权）

### 1.5 收尾多样性 → 对抗跨文章模式固化

先做**删除测试**：删掉最后 1-2 段，如果没少一个新发现、必要后果、动作或画面，就直接删。确实需要结尾时，再根据内容和情绪弧线选择最自然的方式；检查 `profile_config.py::works_file()` 解析出的作品库近 3 篇已发布的 `closing_type`，避免重复。`scene_callback` 只在开头意象经过全文后意义发生变化时使用，不为形式闭环硬回扣。

<!-- meta-audit C6：收尾多样性 6→8 种，加第 9 种 expectant_blessing -->

| 模式 | 特征 | 适合场景 |
|------|------|---------| 
| `natural_break` 自然断流 | 像聊天说到一半停了（"我先睡了"/"就这样吧"） | 朴实随笔型 |
| `unanswered_question` 未答之问 | 以问题结尾，不给答案 | 争议话题、引发思考 |
| `scene_callback` 场景回扣 | 回到开头的意象/场景 | 叙事类、故事驱动 |
| `hard_cut` 硬切 | 最后一个论点说完直接结束，无收束语 | 评论观点类 |
| `anti_conclusion` 反结论 | 明确拒绝给结论（"我也不知道"/"答案可能不存在"） | 复杂议题、探索性 |
| `frozen_frame` 画面定格 | 用一个视觉画面收束 | 情感人物类 |
| `hook_question` **互动钩**（新增） | 最后一行只放一个问题，专为评论区设计；可本土化为温暖版「你家有这种情况吗？留言区聊聊」 | 互动型公众号、家居/生活类 |
| `self_deprecating` **自轻消解 / 甩锅**（新增） | "我这套也就图一乐，你别太当真" / "说到底我也就个写字的" / "你别听我瞎掰" 式批判前自降级 | 智识杂文型、反 PUA |
| `expectant_blessing` **期许托付式**（第 9 种 / **跨篇频率上限 1/3 篇**） | 温暖期许式收尾，如「希望今天这些能给你一点启发」/「愿你...」 | 方法论清单文（注意频控） |

> **频控规则**：`expectant_blessing` 跨篇上限 1/3 篇--读 `works_file()` 解析出的作品库近 3 篇 `closing_type`，若 ≥1 篇是 expectant_blessing，本篇必须换其他 8 种之一。

### 1.6 段落间·稳定语气（🔴 从"强制风格漂移"改为"稳定的人在说话"）

> **原条款"不同 H2 正式度要有差异/强制风格漂移"已删除。** 它是为"反跨文章一致性检测"设的，但对单篇的"味道"有害——一个真人写一篇文章，语气是连续的；刻意在 H2 间漂移正式度，会让读者觉得每节像不同人写的，正是"没有一个稳定的人在说话"的来源。

**现行标准：**
- **全篇保持同一个人在说话的稳定语气。** 段落间的细微变化应当是**内容自然带来的**（讲数据时收一点、讲体感时松一点），不是为反检测**刻意制造**的差异或抽签强加的。
- **避免的是"机械重复同一句式"**（连着几段都用相同的句法骨架），不是"必须把正式度调来调去"。同一种句式结构别在相邻段落反复用 —— 这是为了不单调，不是为了漂移。
- 跨文章别撞指纹靠 `works_file()` 解析出的作品库记录 dimensions/closing_type 去重即可，**单篇内部不必为凑指纹牺牲"同一个人在稳定说话"的连贯感**。

### 1.7 文字密度天花板与文笔检验

**密度上限参照（极高密度散文体）：**
- 一句话装三件事 + 古今中外一句之内跳三个时空 + 20-30 字格言写出散文式深度
- 本 skill **默认不追求**这种密度——公众号手机端会过载
- 但生成内容如果**完全相反**（一句话只装一件事且都是常识），则提示「密度过低」

**I31 形/副词 vs 名/动词比例检验（极简白描标杆）：**
- 抽 300 字段落算比例（形容词+副词 : 名词+动词）：
  - `>1:3` → **文笔可疑**（形/副词太多，AI 味重）
  - `<1:5` → **接近极简白描**（形/副词几乎为零）
  - `1:4 ~ 1:5` → **本 skill 推荐区间**（白描+判断的平衡）
- 极简白描示范（原创）：「天没亮。他起身烧水，锅里的米昨夜就泡上了。开门取报纸，台阶上落了霜。」（≈30 字，名词+动词主导，形/副词 0）

## 二、语言层（用词与句式）

> 现象：AI 的语法太正确、结构太完整、用词太规范。像人说话 = 该省则省、该断则断，但服从语意自然（不为"反检测"硬造病句，见顶部重定向第 1 条 + §2.2）。

### 2.1 禁用词分级（三层）

<!-- meta-audit C4 + 7.4：禁用词拆三层（绝对禁用 / 黄名单 / 路由内白名单） -->
> **分级原则**：单一禁用清单会误杀成熟作者的合法过渡词（在体量足够大的成熟作者语料里，「值得注意的是」这类词会高频且合法地出现，作为「审慎对冲段落」的标志性开头）。改为三层：**绝对禁用**（铁律层 / 一刀切）/ **黄名单**（按路由豁免）/ **路由内白名单**（特定主题豁免）。
>
> 🔴 **判罪双判据（黄名单及以下全部适用）**：一个词是不是"AI 味"，看的不是它出现了没有，而是——
> ① **密度**：200 字内同一个词反复出现、或连续两段用同一个词开头，才触发；孤立出现且语义贴合的一律放行。
> ② **可移植性**：整句话原样搬到任何别的文章里也成立 → 是套话，改；只在本文语境里成立 → 是正常表达，放行。
> 逐词单发命中式过滤会把活句改瘸、迫使模型绕行生僻表达——读者解码成本上升，恰恰制造"生涩"。

#### 2.1.1 绝对禁用（铁律层 / 所有路由一刀切）

出现任何一个都是事故：

**成语堆砌：** 毋庸置疑 / 不可否认 / 不言而喻 / 淋漓尽致 / 意味深长 / 前所未有 / 叹为观止
（注：「众所周知 / 显而易见 / 方方面面」不在本绝对禁用层，已降级为黄名单/软门级——上限与软门行为见 §2.1 顶部「单一裁决表」，不在此处另记数字）

**八股套话：** 在当今社会 / 在这个瞬息万变的时代 / 随着科技的飞速发展 / 引发了广泛关注 / 让我们拭目以待 / 值得深思 / 时代的浪潮

**连接词（仅真结构性八股，🔴 收窄）：** 首先…其次…最后（**整套**出现才算，单用"首先"不算）/ 总而言之 / 综上所述
（注：「此外 / 另外 / 不仅如此 / 更重要的是 / 在此基础上」从此层降级至黄名单——见 2.1.2。它们是正常汉语连接词，按双判据判罪，不一刀切）

**AI 惯用语核心：** 作为一个 / 让我们 / 需要指出的是

**空洞形容：** 非常重要 / 至关重要 / 具有重要意义 / 发挥着重要作用 / 意义深远 / 影响深远

**教科书腔开场：** 禁止"本文将介绍""今天给大家分享""今天聊聊"式课件腔开场。（🔴 不设「深度文 1000-1200 字内不出现核心论点」这类强制铺垫下限 -- 任何文体都不设铺垫字数下限；成果 / 资讯类第一屏就该交付干货，见 [outline.md 步骤 3.5](outline.md)）

**标题党词汇：** 震惊 / 竟然 / 太绝了 / 简直无敌 / 细思极恐 / 万万没想到

**假嗨和爹味总结：** "太绝了" / "简直无敌" / "让我们携手迎接AI的春天" — 结尾禁止上升到人类/时代/哲学高度

**感叹号堆砌：** 全文感叹号控制在 3 个以内

**全角破折号 `——`：** 硬规则 -- 所有给读者看的文字里不允许出现 `——`，统一用两个英文连字符 `--` 替代。详见 [iron-rules.md · 破折号统一用 `--`](iron-rules.md)

#### 2.1.2 黄名单（默认警示，按路由豁免）

以下词从绝对禁用降级为黄名单。**证据**：在体量足够大的成熟作者语料里，这些词高频出现（单词可达数百次），是「审慎对冲段落」的合法标志性开头。

| 词 | 默认处理 | 豁免路由 | 豁免后上限 |
|---|---|---|---|
| 值得注意的是 | 警示 | 深度报道型 / 智识杂文型 / 资深长文型 / 沉吟体型 | 不限 |
| 与此同时 | 警示 | 同上 | 不限 |
| 事实上 | 警示 | 同上 | 不限 |
| 不过 | 警示 | 同上 | 不限 |
| 然而 | 警示 | 同上 | 不限 |
| 从某种意义上说 | 警示 | 同上 | 不限 |
| 此外 / 另外（🔴 自绝禁层降入） | 警示 | 同上 | 不限 |
| 不仅如此 / 更重要的是 / 在此基础上（🔴 同上降入） | 警示 | 同上 | 不限 |
| 众所周知 / 显而易见 / 方方面面 | 警示 | 智识杂文型（**仅「众所周知」允许作反讽前置**） | 上限以 §2.1 顶部「单一裁决表」为准（反讽用法的众所周知不限；其余一律 ≤2 处/篇） |

**未豁免路由的兜底（🔴 放宽：原"7 词合计 ≤2"近乎归零，与本文件自引的成熟作者语料证据自相矛盾，已废）**：默认公众号深度文路由按**单词 ≤ 3 处 / 篇**，且**不连续两段用同一个黄名单词开头**。在此上限内再按 2.1 顶部的判罪双判据（密度 + 可移植性）逐处看——孤立且贴合语义的不算事故，凑在一起当机械过渡才是。

> 🔴 **诚实边界：本节「单词 ≤3 处/篇 + 不连续两段同词开头」的密度规则仅供磨稿自觉，无机器门承接 -- `contracts.verify_anti_ai_blacklist` 的机器硬门只扫约 30 对固定显性套话（黄名单词不计数、不卡密度），`audit_quant_signals` 也不统计黄名单词频。** 即 SKILL.md「显性套话进硬门」指的是那约 30 对显性串，**不含黄名单密度**；别误以为黄名单密度已硬验。连续两段同一黄名单词开头这类典型 AI 腔能穿过所有机器门，只能靠磨稿时自己数。

#### 2.1.3 路由内白名单（特定主题豁免）

| 词族 | 默认处理 | 豁免主题/路由 |
|---|---|---|
| 赛道 / 风口 / 牛市 / 高切高 / 老破小 | 默认禁（陈腐比喻） | 财经/商业主题、深度报道型路由——是行业术语而非陈腐比喻（成熟财经作者语料里高频合法使用） |
| 似乎 / 大概率 / 或将 / 可能 / 不一定 | 默认 OK | 财经评论体明确白名单——免责性表达，磨稿不删 |
| 众所周知（反讽前置） | 见 §2.1 顶部「单一裁决表」 | 智识杂文型路由允许作反讽前置（反讽用法不限；上限不在此处另记，统一查裁决表） |

> 🔴 **对冲栈 & 臆测填空补丁**：上表放行的是**单个**免责词。但——
> - **对冲栈**：两个以上对冲词叠加 = 空话，禁。"这或许在某种程度上可能会带来一定的改变" -- 每个对冲抵消下一个，句子听着谨慎却什么都没断言。叠 ≥2 个（或许 + 某种程度上 + 可能 + 一定…）就删到只剩 1 个、或直接给判断。
> - **臆测填空**：用"据推测 / 想来 / 应该是 / 很可能当年 / 不难想象"把**不知道的客观事实**伪装成陈述，比"我不确定"更坏 -- 读者分不清已知与臆造。要么查证补信源（§8.2 先补搜），要么老实说"没查到"，不许用臆测语气糊过去。

### 2.2 破句与句法变形（机制描述）

AI 的每个句子都语法正确、结构完整。人类不这样写——话说到一半改口、补一句、省掉主语。下面是**菜单不是配额**（自然出现即可，不设每 500 字命中数；为凑特征硬造的破句比工整句更假）：

- **破句**：故意不写完。"这个逻辑——算了，你自己品。"
- **括号插入语**："这个功能（说实话我一开始也没想到会这样）彻底改变了用户行为。"
- **口语省略**："能用吗？能。好用吗？呵呵。"
- **反问连击**："谁规定的？凭什么？"
- **语气词断句**："嗯……怎么说呢，就是那种感觉。"
- **倒装/非常规语序**："厉害是真厉害，但代价也是真大。"

> 🔴 **破句必须承载真实的迟疑 / 态度**：假装记混数字再改口、演一个其实没发生的口误 = 造假，禁。破句是"话真说到一半"，不是表演"我像人"。

### 2.3 意外用词（机制描述）

比喻 / 通感 / 借代能给读者一个画面，比直白词更抓人："这个产品的命运很**潮湿**"（不说"不确定"）、"数据**瘦**得可怜"（不说"少"）、"整个行业在**发烧**"（不说"过热"）。有就有，没有不硬造（不设每 500 字配额）；硬造的"意外"读者一眼识破。

### 2.3.5 可信细节锚 / 物件做证据 → 对抗"AI 编造的假细节"

AI 写人物/事件时倾向补出"合理但没有来源"的细节。真实感不由精确度担保，而由**来源 + 选择**担保：一个经核验的动作、物件、数字或原话，通常比形容词更能承重。

**执行标准：**
- 关键人物/事件优先寻找有来源的动作、物件、数字或原话；来源只支持约数就保留约数，缺细节就不补。
- 物件可以**自身承担论证**——动作、物件或原话已经让情绪成立时停止解释，删掉"这一幕令人……"式尾巴。
- **磨稿期自检（无机器兜底）**：逐段问「这条细节来自哪里？它能证明什么？删掉解释尾巴后是否更有力？」答不出来源就删或改为明确推断。
- 现实 / 虚构 / 混合模式与五类来源口径统一见 [material-integrity.md](material-integrity.md)。

**经典样本：**

| 类型 | 反常细节（原创示例） | 为什么是锚 |
|---|---|---|
| 精确数字 | 「抽屉里码着 37 张没拆封的名片」 | **前提：来源确有 37**；数字与动作共同承重 |
| 精确数量 | 「他只咬了两口就把包子搁下」 | 不是「没怎么吃」，是两口 |
| 具体比喻 | 「攥出的纸团被手汗浸湿了一角」 | 不是「紧张出汗」，是湿了一角（具体） |
| 物件自证 | 「桌角那杯茶浮着一层灰，没人动过」 | 不靠形容词评价，物件本身让读者得结论 |
| 动作特写 | 「他没敲门，一脚带上门就坐下」 | 不是「进屋坐下」，是动作特写 |

**反例（AI 味）：**
- ❌「他穿着体面的西装，神色严肃地走进会议室。」（合理但泛泛，零反常）
- ✅「他西装左袖口磨出了线头，进门先看了一眼桌上的水杯--空的。」（反常细节 + 物件自证）

### 2.4 过渡去机械化（🔴 原"连贯性打破"会反噬句间承接，已纠正）

> **重大纠正：原条款"禁止每段第一句都承接上一段"与「句间引力」(写作核心第 6 条) 直接冲突，已删除。** 之前为"对抗连贯性检测"而要求打断承接，是把病因看反了——读者抱怨的恰恰是"读起来不顺、缺承上启下"。承接本身是好的、必须保的；要避免的是**机械、千篇一律的过渡形式**（每段都"此外/而且/与此同时"开头、每个 H2 内部都同一套"观点→论据→总结"结构），而不是承接这件事本身。

**AI 的真问题是"过渡太机械"，不是"太连贯"：** 每个过渡词都标准、每段内部结构都一样、丝滑得像 PPT 动画的统一转场。解法是让**承接方式多样**，不是切断承接。

**要的（都是让承接更自然、更有变化的手法，不是断流）：**
- **变换承接方式**：别每段都用过渡词承接。可以靠顶真（上句尾词起下句）、靠一个共同的具体物、靠一个问句钩、靠情绪转折来接——形式换着来，但读者始终被推着走（见 [writing.md §句间引力](writing.md)）。
- **偶尔硬切**：相邻话题之间偶尔不用过渡词直接跳——但新话题与上文**仍有内在关系**，是"省掉了机械过渡词"，不是"跳到不相干的地方"。<!-- E-10 互指 -->**删哪类过渡词以 [writing.md §连词统一表](writing.md) 为唯一裁决**：硬切删的是机械学术连词（此外 / 与此同时 / 不仅如此），**结构性逻辑词「因此」默认保留**（删后语序仍承接才可删，见 [writing.md §句间引力](writing.md) 体检）——本条与那两处是同一口径，不构成三方打架，遇分歧一律以连词统一表为准。
- **跑题再回来**：讲着讲着岔出去一小段，再用"说回正题"/"扯远了"拉回来——这本身就是一种有人味的承接节奏。
- **非线性展开**：不总是"观点→论据→总结"，可以"场景→疑问→岔开→回来→观点"。
- **重复与微调**：后文换个说法重复前文的意思，或微调前文观点（"刚才说得绝对了，其实也不完全是"）。

**禁止：**
- 每段都用同一个机械过渡词开头（此外 / 而且 / 与此同时 / 值得注意的是）
- 每个 H2 段落都用相同的内部结构
- 结尾段逐一机械回顾前文要点
- 🔴 **为"反检测"而故意打断句间/段间承接**——承接是读者读得顺的命脉，不许为骗检测器牺牲它

## 三、内容层（密度与真实）

> 目标：每一句都让读者拿到真东西。读者一眼能分辨"编造的假细节"和"消化真实信息后的重组"——后者才留得住人。这一层是去 AI 味的本体（见顶部重定向第 6 条）。

### 3.1 信息密度呼吸与逐段新增（机制描述）

信息密度有波峰波谷：数据/论证密集的段落后面，可以跟一段感受/比喻/吐槽让读者喘口气。但每段都要推进至少一项：**事实 / 动作 / 例子 / 区分 / 后果**，或让理解、视角、语气发生必要变化。推理负责连接材料，不能把同一材料换说法当成新材料。答不出「这段比上一段多了什么」就删、并或补材料；压到原长约三分之一仍不损失信息与语气，就保留短版。

### 3.2 副词节制（机制描述）

中文 AI 文本副词显著多于人类。原则只有一条：**能用具体描述就不用副词修饰**——"非常快速地增长" → "三个月翻了一番"。数值检验由 `verify_pos_ratio`（§1.7）+ `audit_quant_signals` 机器报告，不占写作注意力。

## 四、追问下沉法（透明玻璃风自检）

每段文本输出前，静默执行：
- 试图输出抽象名词（"体验、格局、绩效、赋能"）→ 追问 **"what kind of（什么样的）"** → 替换为具体画面
- 试图输出抽象动词（"提升、改善、优化、推动"）→ 追问 **"how（怎么做）"** → 替换为具体动作
- 试图输出笼统判断 → 追问 **"谁来做？花多少成本？在什么条件下？"** → 加限定词

**示例：**
- ❌ "提升用户体验" → ✅ "把加载时间从 3 秒压到 0.8 秒"
- ❌ "市场低迷" → ✅ "那是 2024 年初，一个做了十五年的老板把店盘掉了"

## 五、AI 句式结构过滤

**四种高频 AI 句式（识别框架来自 [humanizer](https://github.com/blader/humanizer) by blader，MIT）：**

- **负向平行结构：** "不只是X，更是Y" / "不仅仅是...，还是..." → 直接说 Y 是什么，删掉 X 的铺垫
- **虚假范围结构：** "从设计到落地" / "从理念到实践，涵盖了..." → 说具体的一件事，不用"从X到Y"撑篇幅
- **"承载式"回避：** "作为智能家居的先行者，某品牌承载了..." → 直接说"某品牌做了什么"，避免用"作为...承载/肩负/代表"绕一圈
- **套路化结尾章节：** 最后一段必出现"当然，也面临挑战……但我们相信未来……" → 结尾是最后一个发现，不是对挑战的免责声明

## 六、人类经验插槽

遇到常识性解释不超过 2 句。遇到关键转折、微观体感、一手数据时，如果创作者未提供素材，**强制停止编造**，输出占位符：

> `[⚠️ 请主理人在此补充一段亲历细节/真实数据——这里是文章最需要人味的地方]`

此举核心目的：**不编造** -- 文章里每个细节都真实可查，是读者信任的底线（🔴 去 AI 味的本体是内容真实精炼，不是骗过查重）。

### 6.1 自嘲缓冲 / 自轻消解（通用技法）

AI 不会自然产生自嘲——它倾向把自己定位为权威解释者。人类作者用「自轻」换读者信任。可作开篇、过渡、收尾通用技法。

| 位置 | 形态 | 示例（原创） |
|---|---|---|
| **开篇** | 批判前先骂自己一句（软着陆） | 「这类烂文我自己也写过，今天就当自我检讨」 |
| **过渡** | 把自己降级到庸人（平视消毒） | 「我也就是个普通写字的，没什么了不起」 |
| **收尾** | 反向获力（结论从自轻里反弹） | 「这套你别全信，我自己也常犯糊涂」 |

**操作要点：**
- 必须**显式 prompt**——AI 默认走「我作为 AI 助手」式自我贬低（这是负面 AI 味，不是自嘲）。真自嘲是「我作为一个写文章的人，刚才那段写得也挺烂的」
- 跨篇频率上限 1/3 篇（不要每篇都用，否则变成新模式）
- 收尾位置可与 `self_deprecating` 收尾类型重叠（见 §1.5）

## 八、论证深度检查（So What + Prove It）

> **定位**：前七节解决"语言层反 AI 检测"——句长、温度、情绪、密度都达标后，**论点层面**仍可能空泛。本节补齐"论点是否立得住"的校验。
>
> **借鉴**：Corey Haines 的 copy-editing skill《Seven Sweeps Framework》中 Sweep 3 与 Sweep 4，本土化后落地。

### 8.1 So What 追问 — 为论点加"意味着..."桥梁

每个核心论点 / claim 后面，静默追问：**"所以呢？"** 如果答不出读者关心的下一层含义，就补一层桥梁。

**示例：**

- ❌ "Kimi K2.6 支持 300 agent 并行。"
  - 追问：所以呢？
- ✅ "Kimi K2.6 支持 300 agent 并行 —— **意味着**个体开发者第一次能用家用显卡跑过去只有大厂能撑的 agent 集群。"

**桥梁关键词（任选一种，不要每次都用同一个——避免变成新套路）：**
- 意味着... / 换句话说... / 落到实处就是...
- 对 {具体读者} 来说就是... / 放到咱们的场景里...

**使用边界：**
- 只在核心论点的读者后果尚未显现时补桥梁，不按 H2 配额；动作、物件、原话或案例已经让后果成立时停笔。
- 全文用"所以呢"找真正缺口，但不统计命中数。补出的桥梁若只是复述或升华，删掉。
- 禁止只陈述无法承重的观点，也禁止把每个事实都解释成一次"时代意义"。

**与追问下沉法的区别**（第 4 节）：
- 追问下沉法：对**抽象词**下沉（"体验" → "加载时间 3 秒→0.8 秒"）
- So What 追问：对**论点**升维（"支持 300 agent 并行" → "对个体开发者意味着什么"）
- 两者方向相反，互补使用

---

### 8.2 Prove It 核实 — 判断性 claim 必须有支撑

凡是带**判断色彩**的 claim（评价、趋势、对比、预测），必须有下列之一：

| 支撑类型 | 要求 |
|---|---|
| **具体数据** | 带官方链接或可复核来源（延续全局 CLAUDE.md"版本号/价格以官网为第一信源"的规则） |
| **一手案例** | 作者亲历必须由作者提供；否则使用具名、可追溯的公开案例，不得生成"我见过"或"老李家"冒充亲历 |
| **KOL 原话引用** | 必须额外标注"他在卖什么"——防止幸存者偏差（例如引用某位开发者，就注明他在卖自己的 CLI 工具；引用某位 newsletter 作者，就注明他在卖订阅）。没想清楚他的利益立场就别引用 |
| **同行复现 / 交叉验证** | 两个以上独立信源互证 |

**四项都凑不齐** → 三条路**按序**走（🔴 补搜是第一出路）：
1. **先补搜**：就地用 AnySearch / Tavily / WebSearch 搜数据 / 一手案例 / 交叉信源——搜索是 AI 相对人类作者的独有优势，缺支撑先搜、别急着删（这一步正是"发挥全网搜索能力、多加数据实例"的最高杠杆）
2. **补搜 1-2 轮仍无** → 降低 claim 强度："是...的" → "可能是...的" / "在 X 场景下是...的"
3. **仍不行 → 直接删除**：如果降强度后就剩废话，那本来就是废话

**绝对禁止**："行业都在说 / 有人认为 / 众所周知" 式无主论证——这比企业黑话更糟，它假装有依据。

---

### 8.3 修补回看（🔴 瘦身：原"递归回查指标清单"已删，回查对象只剩语流）

补 So What / Prove It 之后，把修补处**前后各一段连起来重读一遍**——回查的对象是"读着顺不顺"，不是指标清单（按指标递归回查会陷入"补一项破一项"的循环，那正是 5 层串行修补磨碎语流的现场）。

**修补优先级（语流第一）：**
1. **先保语流与句间承接（终审门，凌驾一切）**——任何修补让句子读着磕巴 / 承接断掉，立即回退该修补
2. So What / Prove It 的桥梁可以写短、写不工整——"A。而这，对做装修的来说就是亲妈。"这种破句式桥梁优于工整三段论
3. 破句、密度、情绪**自然出现即可**，不为保它们改写已经通顺的句子

## 九、审稿 team（opt-in / 提议制）

> **定位**：本节是磨稿阶段的**可选叠加层**，不改前八节任何内容。前一~八节是默认的「单 agent 磨稿」全流程；本节描述「当本篇显著受益于多角色围审时，编排器**提议**用户开一个短时审稿 team 把第一~八节的检查并行分工」的可选路径。
>
> **本节无 Legacy 章节衔接问题**（本文件不分 orchestrator on/off、无 `## Legacy` 段）：默认行为 = 第一~八节单 agent 磨稿；本节只在「编排器判定显著受益 **且** 用户确认」时叠加生效，其余一切情况（`orchestrator=off` / 未提议 / 提议后用户拒绝 / 提议交互不可用）一律走第一~八节单 agent 磨稿，**与既有行为字节级等价**——本节不删改不旁路前八节的任何一条规则、阈值或检查项。

### 9.1 何时提议（编排器判定「显著受益」）

磨稿阶段开始时，编排器（= 主 agent）静默评估本篇是否**显著受益**于多角色并行围审。判定为「受益」的典型信号（命中其一即倾向提议）：

- 篇幅长、H2 章节多（≥4 节），单 agent 串行磨稿易顾此失彼；
- 同时压三类高风险面：调性走样风险（风格审）+ 铁律违规风险（铁律审，如破折号/尾部总结/禁用词）+ 事实风险（事实核查，含版本/价格/时间类 claim）；
- 改稿轮次已多、人工反馈反复，需要多视角互相挑战才能收敛。

不满足上述、普通短文 / 风险面单一 → **不提议**，直接走第一~八节单 agent 磨稿（遵守全局 memory：不为了用而用，token 成本高）。

### 9.2 提议话术与未确认 fallback

判定受益后，编排器**必须先明确提议、等用户确认**，绝不擅自开 team（遵守 memory `feedback_agent_teams_propose`：team 不自动触发，Claude 提议 + 用户确认后才发起）。提议措辞简短一句，例：

> 「这篇磨稿适合开审稿 team（{命中的受益理由，如：4 节长文 + 同时压调性/铁律/事实三类风险}），三角色并行围审一轮即散。是否开审稿 team？」

- **用户确认（点头）** → 进 9.3 走审稿 team；
- **用户拒绝 / 未回应 / 提议交互不可用 / `orchestrator=off`** → **走第一~八节单 agent 磨稿，与 legacy 字节级等价**（不开 team、不调审稿门、不产 verdicts 集合；磨稿产物与未引入本节时逐字节相同）。

### 9.3 审稿 team 短时围审流程（确认后）

编排器按下列**确定性流程**驱动审稿 team，全程不把状态写权下放：

1. **TeamCreate 三角色**：风格审 / 铁律审 / 事实核查。各角色据 [agent-contracts.md](agent-contracts.md) review 节输入 bundle（`sansheng_context` / `iron_rules` 子集 / `article_meta` / `stage_input`=定稿全文 + 其维度清单）独立围审。各角色分工对应前八节：
   - **风格审** → 第一节统计层（句长/温度/情绪/密度节奏/收尾/风格漂移）+ 第四节追问下沉 + 第五节 AI 句式；
   - **铁律审** → 第二节语言层（禁用词黑名单 / 破句 / 连贯性）+ `iron_rules` 子集（破折号 `--`、无引导句、无尾部总结、感叹号 ≤3）；
   - **事实核查** → 第八节论证深度（So What / Prove It）+ 版本/价格/时间类 claim 官网信源核实。
2. **各角色独立出 verdict**：每角色返回对齐 [agent-contracts.md](agent-contracts.md) review tier-1 契约的结构化裁决 `{role, issues, pass}`（`role` 非空 str、`issues` list、`pass` 严格 bool）。subagent 是无状态执行单元：**不碰 `.state.json`、不调 `pipeline.py`、不自行 `skip`、不静默吞错**（违反即判不合规，见 [iron-rules.md](iron-rules.md) subagent 协作铁律）。
3. **过双门**：编排器收齐全部 verdict 后，先逐项过 tier-1 结构契约 `validate_output("review", payload)`，再对**新产出 verdicts 集合**过 tier-2 语义门 `scripts/contracts.py:verify_review_set(verdicts)`（① 去重后 ≥3 不同 role；② `pass=false` 的 issues 必须非空；③ `pass=true` 却带非空 issues 的弱不一致警示）。tier-2 门**只对本次审稿 team 新产出强制，不追溯历史冻结 golden**（历史无统一 review 产物）。
4. **编排器主轴汇总裁决 + 应用 fixes（汇总不外派）**：双门通过后，**编排器主轴自己**汇总三角色 issues、去重消冲突、形成统一处置清单，并按前八节规则**自己应用 fixes**（照 [agent-contracts.md](agent-contracts.md) content_enhance 合并关 / cover 选优「主轴自做不外派」定式）。**绝不派任何 subagent 做汇总/裁决/改稿**——汇总需要全局视野与最终裁量权，属编排器主轴职责，外派会丢上下文且违反单一状态写者精神。`verify_review_set` 是汇总裁决**前置**的机器化把关，不替编排器裁决该不该回流、也不判 issue 内容对错。
5. **失败回流**：任一 `pass=false` → 编排器按 [autopilot.md](autopilot.md) §失败语义就地处置（定向重磨该维度命中的段落 / 重派该角色复核）。**同一处连错 3 次才回报用户**，回报带三要素（阶段名 / 失败原因含哪关挂 / 已尝试恢复方式）。恢复决策权完全归编排器，subagent 无权放弃或 skip。
6. **短时即散**：围审一轮 + 主轴汇总应用 fixes 完成后，**立即 TeamDelete 解散 team**（审稿 team 是短时单元，不常驻、不跨阶段复用）。再继续走磨稿后续（第七节量化验收清单复查 → 排版阶段）。

> 与第一~八节的关系：本节只改**执行拓扑**（单 agent 串行检查 → 确认后三角色并行围审 + 双验证门 + 主轴汇总），**不改任何一条磨稿规则/阈值/禁用词/句式过滤/论证深度要求**。未确认 / `orchestrator=off` / 提议被拒时第一~八节单 agent 磨稿路径**原文不变**继续生效，与既有行为字节级等价。
