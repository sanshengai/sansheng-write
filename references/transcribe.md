# 音频转写（口述想法 → 写作素材）

作者用手机/电脑录下对某篇文章的思考（通常 10-20 分钟），音频直接丢进对话或 `素材/`。
处理分两层，**缺一不可**：

1. **机械层**：`scripts/transcribe_audio.py` 把声音转成文字（本页上半部分）；
2. **语义层**：按下方「口述素材梳理协议」理解这段话，产出梳理稿——
   **大纲阶段的主输入是梳理稿，不是转写稿**。口述是思维的原始流，
   语序、详略、重点都不等于成文结构，直接拿转写稿写文章是已知失败模式。

## 定位：转写稿是素材，不是逐字稿

- 转写稿供梳理与写作阶段**消化**，允许引擎按语义分段、少量清理语气词；
- 同音字/专名小错**由梳理阶段按上下文语义纠正**，不在转写层追求零错字；
  拿不准且影响事实的专名/数字，走「事实验证」直接搜证，而不是追问创作者；
- 录音里的口头指令（"这篇要写成教程"、"标题往直球走"）当作者约定执行。

## 触发与命令

| 场景 | 动作 |
|---|---|
| 对话里给了音频路径 + 写作意图 | 转写 → 口述梳理，两稿落该文章目录 `素材/`，再进正常流程 |
| `素材/` 里发现音频文件 | 开局先 `python "$SKILL/scripts/transcribe_audio.py" 素材/`，转写完即做口述梳理，再统一读素材 |

```bash
python scripts/transcribe_audio.py 素材/录音.m4a            # → 素材/录音.转写.md
python scripts/transcribe_audio.py 素材/                    # 目录批量（已有转写稿自动跳过）
python scripts/transcribe_audio.py 录音.mp3 --out 思考.md   # 指定输出（仅单文件）
python scripts/transcribe_audio.py 录音.mp3 --force         # 已有转写稿也重跑
python scripts/transcribe_audio.py 录音.mp3 --engine whisper  # 强制本地引擎
```

支持格式：mp3 / m4a / wav / aac / flac / ogg / wma / amr / opus（覆盖 iOS 备忘录与微信语音导出）。

## 引擎与配置

| 引擎 | 触发条件 | 质量 | 依赖 |
|---|---|---|---|
| **gemini**（默认优先） | 配了 `GOOGLE_API_KEY` | 高：专名准、分段自然（166s 实测 ≈ 半分钟、约 5900 tokens，费用可忽略） | 复用生图同一把 key；`AQ.` 前缀须配 `GOOGLE_VERTEX_PROJECT`，端点分流约定与 image-routing.md 一致 |
| **whisper**（本地兜底） | 没配 key 但装了 faster-whisper | 中：同音字错较多（"美金→米金"级），素材用途可接受 | `pip install faster-whisper`；CPU 可跑，无需显卡 |

- 模型默认 `gemini-3.7-flash`（取当前代 flash 即可，转写任务用不到 pro）；
  要覆盖用 env `SANSHENG_WRITE_TRANSCRIBE_MODEL` 或 `--model`。
- 两个引擎都不可用时脚本会明确报错指路，**不静默降级、不伪造转写稿**。

## 口述素材梳理协议（语义层，转写后、进大纲前必做）

> 这一步由在场模型完成，不是脚本。产出 `<同名>.梳理.md` 落 `素材/`，
> 与转写稿并存：转写稿是**原始层**（引用原话时回来取），梳理稿是**工作层**。

通读转写稿后按六栏分拣，每条注明来自转写稿哪一段（便于回溯）：

| 栏 | 装什么 | 规则 |
|---|---|---|
| **主旨/意图** | 这篇想说什么、为什么现在说 | 作者明说照录；没明说从反复出现的关注点**推断**，并标「推断」 |
| **受众与口吻** | 说给谁听、什么姿态 | 同上：明说照录，推断标注依据 |
| **论点与脉络** | 核心论点，按**逻辑**重排 | 口述顺序≠行文顺序，允许全部重组；作者花时间多、翻来覆去讲的默认加权为重点，但要经得起「主旨检验」——与主旨无关的岔题移「弃用」栏 |
| **案例与素材** | 具体故事、数字、场景 | 按来源分开标：**亲历（自述）/ 听来（转述）/ 假设举例**——对应 material-integrity 的来源边界，写作时不得混用 |
| **待查证/待补充** | 作者不确定的（"好像""大概""你查一下"）+ 一切事实性论断 | 列成清单，按「事实验证」纪律**当场搜证回填**结果与来源；查证不实的论点降级或移弃用栏 |
| **口头指令** | 文体/标题/风格/尺度等约定 | 提取为参数，进 `article-meta.yaml` 对应字段 |

三条原则：

1. **梳理是理解，不是代笔**——不替作者发明观点；归类拿不准的标「推断」，
   重大推断（主旨、受众级别的）在大纲阶段显式呈现给作者确认，不静默定案。
2. **弃用也要留痕**——判定与主旨无关的内容归到梳理稿末尾「弃用」栏一行一条，
   不静默丢弃；作者扫一眼就能捞回误杀的。
3. **梳理稿喂大纲**——进入 outline 阶段时，素材分拣表以梳理稿为主输入；
   转写稿仅供引用原话与争议回溯。

## 机制细节（排障时看）

- 转写前先用 ffmpeg 规整为 16kHz 单声道 48kbps mp3（手机各种原始格式一律先归一）；
- 超过 25 分钟自动切片逐段转写再拼接（避开单请求 20MB 体积上限），切片对产出透明；
- 输出文件头部有一行 HTML 注释注明源文件/时长/引擎/日期，正文即转写稿；
- key 走 `x-goog-api-key` 请求头不进 URL；异常串统一脱敏后才落日志。
