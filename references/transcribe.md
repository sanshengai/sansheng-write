# 音频转写（口述想法 → 写作素材）

作者用手机/电脑录下对某篇文章的思考（通常 10-20 分钟），音频直接丢进对话或 `素材/`。
处理分两层，**缺一不可**：

1. **机械层**：`scripts/transcribe_audio.py` 把声音转成文字（本页上半部分）；
2. **语义层**：按下方「口述素材梳理协议」理解这段话，产出梳理稿 -- **大纲阶段的主输入是梳理稿，不是转写稿**。口述是思维的原始流，
   语序、详略、重点都不等于成文结构，直接拿转写稿写文章是已知失败模式。

## 定位：转写稿是素材，不是逐字稿

- 转写稿供梳理与写作阶段**消化**，允许引擎按语义分段、少量清理语气词；
- 同音字/专名小错**由梳理阶段按上下文语义纠正**，不在转写层追求零错字；
  拿不准且影响事实的专名/数字，走「事实验证」直接搜证，而不是追问创作者；
- 录音里的口头指令（"这篇要写成教程"、"标题往直球走"）当作者约定执行。

## 触发与命令

| 场景 | 动作 |
|---|---|
| 对话里给了音频路径 + 写作意图 | 转写 → 口述梳理，两稿落该文章目录 `素材/`，再进正常流程 |
| `素材/` 里发现音频文件 | 开局先 `python "$SKILL/scripts/transcribe_audio.py" 素材/`，转写完即做口述梳理，再统一读素材 |

```bash
python scripts/transcribe_audio.py 素材/录音.m4a            # → 素材/录音.转写.md
python scripts/transcribe_audio.py 素材/                    # 目录批量（已有转写稿自动跳过）
python scripts/transcribe_audio.py 录音.mp3 --out 思考.md   # 指定输出（仅单文件）
python scripts/transcribe_audio.py 录音.mp3 --force         # 已有转写稿也重跑
python scripts/transcribe_audio.py 录音.mp3 --engine whisper  # 强制本地引擎
```

支持格式：mp3 / m4a / wav / aac / flac / ogg / wma / amr / opus（覆盖 iOS 备忘录与微信语音导出）。

## 引擎与配置

| 引擎 | 触发条件 | 质量 | 依赖 |
|---|---|---|---|
| **gemini**（默认优先） | 配了 `GOOGLE_API_KEY` | 高：专名准、分段自然（166s 实测 ≈ 半分钟、约 5900 tokens，费用可忽略） | 复用生图同一把 key；`AQ.` 前缀须配 `GOOGLE_VERTEX_PROJECT`，端点分流约定与 image-routing.md 一致 |
| **whisper**（本地兜底） | 没配 key 但装了 faster-whisper | 中：同音字错较多（"美金→米金"级），素材用途可接受 | `pip install faster-whisper`；CPU 可跑，无需显卡 |

- 模型默认 `gemini-3.7-flash`（取当前代 flash 即可，转写任务用不到 pro）；
  要覆盖用 env `SANSHENG_WRITE_TRANSCRIBE_MODEL` 或 `--model`。
- 两个引擎都不可用时脚本会明确报错指路，**不静默降级、不伪造转写稿**。

## 口述素材梳理协议（语义层，转写后、进大纲前必做）

> 这一步由在场模型完成，不是脚本。产出 `<同名>.梳理.md` 落 `素材/`，与转写稿并存：
> 转写稿是**原始层**（引用原话回来取证），梳理稿是**工作层**（大纲的主输入）。
> 规则化用自新闻引语规范（Reuters/AP）、口述史转写分级（CCOHR/Baylor）、
> 定性研究覆盖矩阵（framework method）与语音笔记产品的公开失败教训。

### 第一遍：全量抽取（先保全，再加工）

**这不是摘要任务。** 通读转写稿，把每一个独立的观点/案例/数字/情绪/口头指令
抽成编号条目 -- 零遗漏、不合并、不重排、不评价：

```
[S01](¶2) 观点：…
[S02](¶3) 案例（亲历）：…〔金句候选〕
[S03](¶5) 数字：… -- 原文没给来源
```

- 编号 `Sxx` + 段落坐标 `(¶n)` 是后面一切核对的审计轨迹，一条不能省；
- 🔴 **为什么拆两遍**：一次调用里「零遗漏抽取」和「按逻辑重组」天然打架 -- 重组会
  诱导丢弃"不好安放"的条目；而「你漏了什么」式的事后自查召回率达不到可用水平。
  防丢失只能靠这一步的结构保证，不能靠回头检查。

### 第二遍：分拣与重组（六栏，条目引 S 编号）

| 栏 | 装什么 | 规则 |
|---|---|---|
| **主旨/意图** | 这篇想说什么、为什么现在说 | 作者明说照录；没明说从反复出现的关注点**推断**并标「推断」，大纲阶段显式请作者确认 |
| **受众与口吻** | 说给谁听、什么姿态 | 同上：明说照录，推断标依据 |
| **论点与脉络** | 核心论点按**逻辑**重排（引 S 编号） | 口述顺序≠行文顺序，允许全部重组；作者翻来覆去讲的默认加权为重点，但须过「主旨检验」 -- 无关岔题移弃用栏 |
| **案例与素材** | 具体故事、数字、场景（每条标**引用档**，见下） | 来源三分：**亲历（自述）/ 听来（转述）/ 假设举例** -- 对应 material-integrity 来源边界，写作时不得混用 |
| **待查证/待补充** | 作者不确定的（"好像""大概""你查一下"）+ 一切事实性论断 | 列成清单按「事实验证」纪律**当场搜证回填**；查证不实的论点降级或移弃用栏 |
| **口头指令** | 文体/标题/风格/尺度/配图位等约定 | 提取为参数进 `article-meta.yaml`，并作**门控** -- 作者口头定过的，后续阶段不再另行改判 |

### 引用分档（案例与表达逐条标档，写作阶段照档执行）

作者原话能不能用、怎么用，梳理时就定死，共同底线一条（新闻引语铁律）：
**只能减，不能改写；减完意思不变。**

| 档 | 用途 | 允许动什么 |
|---|---|---|
| **甲 · 原文直用** | 鲜活口语、个人印记表达、金句候选 -- 逐字进正文或开篇种子 | 只删冗余与结巴；不改词序、不换词 |
| **乙 · 修整后引** | 意思完整但有语病/填充词 | ① 语气词分两张表：呃/嗯/啊类**直接删**；"就是/其实/然后/那个"类删前先问**删掉句意变不变**，宁多留勿误删；② false start 三分法：自我更正型只留更正、断后重述型删前半、**没绕回原意的保留**；③ 单点语法修正可以，整句改写不行 |
| **丙 · 段落块重排** | 同一论点散落多处 | 段落块级合并重排（口述顺序让位于行文逻辑）；**句子内部不重写** |
| **丁 · 转述取意** | 内容对但表达够不上引用标准 | 观点入大纲、文字弃用 -- **修不动的降级为转述，不硬修**（处理两难的标准出口） |

中文修整细节：按语义呼吸分段（话题/论证角色/视角切换即换段，一段 1-4 句，宁碎勿整）；
慎用句号链（同一论证链条用逗号连接）；中英夹杂在中文与英文/数字间加半角空格。

### 修正对照（同音/专名）

- 同音错按上下文与 profile 品牌语料校正（高频坑：的/地/得、成语、专业术语、人名、
  中英夹杂技术词），**只改有把握的**，没把握的进待查证栏，不悄悄猜；
- 全部修正列 `原→正` 对照置于梳理稿末尾，作者扫一眼即可纠偏。

### 覆盖闭环（防发散、防丢失的机制层）

1. 大纲定稿时**必附「素材覆盖表」**：每个 S 编号 → 落点（`H2-x` / 开篇种子 / 金句卡 /
   弃用+一句话理由）。**空格即违规** -- "已读未用"必须显式写成弃用，不允许默认蒸发；
2. 覆盖表随大纲一起过 blueprint 确认点，作者一眼看到什么被用了、什么被放弃了；
3. 🔴 **不得新增**：梳理稿与成稿中的数字/人名/时间/专名必须能在转写稿找到出处；
   找不到的一律进待查证搜证，查无实据就删 -- 转写引擎会在静音段与模糊处编造内容，
   这是实测过的已知失败模式，不是理论风险。正文里标为作者原话的句子，写作时须回
   转写稿核对出处（防二次漂移）。

### 与下游各阶段的衔接（映射表）

| 梳理稿栏位 | 喂给谁 |
|---|---|
| 主旨/意图 | outline 步骤 2 选题快评、步骤 8 大纲与标题、meta `digest` |
| 受众与口吻 | outline 步骤 1 受众分析的**主输入** |
| 论点与脉络 | outline 步骤 4 逻辑骨架 + H2 结构候选 |
| 案例与素材（带引用档） | outline 素材分拣（原始内容→模块映射）；**甲档直供步骤 1.5 人味种子**（meta `seed` 的「口语原话」型）与金句卡 |
| 待查证清单 | outline 步骤 5 调研任务的现成输入（轻素材直搜回填，深素材派调研工具） |
| 口头指令 | meta 对应字段 + 流程门控（如作者已口头定文体，步骤 3 不再另判） |

### 口述前须知（给作者，可选但省很多事）

- 手边放个粗提纲当提词器，防跑偏；
- 拿不准发音的专名，口述时说固定代号（"那个 A 公司"），录完统一替换；
- 想配图的位置直接口述"这里放一张 XX 图"，会进口头指令栏；
- 没把握的事实直接说"这个你查一下"，会自动进待查证清单。

## 机制细节（排障时看）

- 转写前先用 ffmpeg 规整为 16kHz 单声道 48kbps mp3（手机各种原始格式一律先归一）；
- 超过 25 分钟自动切片逐段转写再拼接（避开单请求 20MB 体积上限），切片对产出透明；
- 输出文件头部有一行 HTML 注释注明源文件/时长/引擎/日期，正文即转写稿；
- key 走 `x-goog-api-key` 请求头不进 URL；异常串统一脱敏后才落日志。
