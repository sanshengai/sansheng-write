# 事实复核（fact-check）-- 发布前的外部真伪核关

> **定位**：磨稿后、排版前的一道外部核关，与[冷读外审](semantic-review.md)同窗口、可并行派发。
> 冷读外审抓**内部**问题（读感卡顿 / 指代不清 / 数字前后打架）；事实复核抓**外部**问题（定稿里的数字 / 日期 / 价格 / 版本号 / 专名 / 引语与真实信源对不对得上）。两者划界、互不推诿。
> 🔴 **零停顿**：全自动后台跑，不停下打断作者；发现事实错，写作 agent 自行改正后复跑；`need_verify` 项自行改模糊表述或删，待核实清单随最终交付一并汇报。
> 事实复核的来源分类、现实/虚构边界与材料账本，以 [material-integrity.md](material-integrity.md) 为准。

## 为什么单列这道门

本 skill 此前缺一个独立的事实核验环节：冷读只查内部一致性、opt-in 审稿的事实核查默认关，多数文章从写完到草稿箱之间**没有任何对外核验数据的兜底**。而 AI 前沿信息 / 工具介绍类文章，版本号 / 价格 / 发布时间 / 参数错一个就伤公信力（这些必须以官网第一信源为准 + 权威媒体交叉核对）。

## 谁来跑

派一个**不带写作上下文**的全新 subagent（无大纲 / 种子 / 会话历史），只给定稿全文。高价值篇换不同模型族。它不改稿，只核事实、出清单。

## 核什么（从定稿提取可核事实）

逐项提取并判定：
1. **数字**：统计数据、跑分、比例、金额、倍数、增长率
2. **日期 / 时间窗口**：发布日、截止日、生效期、"X 天前"
3. **价格 / 计费**：定价、免费额度、订阅费
4. **版本号 / 型号**：模型版本、软件版本、产品代号
5. **专名**：公司 / 产品 / 人物 / 机构名（拼写 + 归属）
6. **引语**：KOL 原话、官方表述（有没有被改写走样）
7. **来源类型**：直接核验事实 / 当事方自述 / 第三方转述 / 作者推断 / 未知，正文归属是否写对
8. **推理越级**：先后顺序有没有被写成因果；结果有没有被写成动机；自述有没有被写成独立事实

## 怎么核（每条判定其一）

- **对上素材**：命中 `素材/research/*.json`（见 [agent-contracts.md §research](agent-contracts.md)）或大纲信源，一致 → ✓
- **现场搜索**：清单外的、或存疑的，就地用 AnySearch / Tavily / WebSearch 核 -- 版本 / 价格 / 时间以**官网第一信源** + 权威媒体交叉（复用 §research 官网级判据）
- **标 need_verify**：搜不到 / 无法确认 → 标记，写作 agent 据此改模糊表述或删（不硬给数字，全局铁律）
- **核断言边界**：证据只能证明先后时，不放行因果；没有当事人明确表达时，不把作者推断写成人物动机

## 产出：`_fact-check.md`（带签名）

    # 事实复核清单

    复核模型：<Sonnet / Opus / ...>（≠ 写作模型更佳）
    条目数：<N>
    结论：PASS ／ <n> 条待改

    ## 逐条
    - [✓] <claim> -- [直接核验事实] 对上 <信源>；可支持 <边界>
    - [△] <claim> -- [当事方自述/第三方转述/作者推断] 归属已明确，不升级为事实
    - [✗] <claim> -- 实际应为 <X>（来源：<官网 URL>），已回改
    - [⚠️ 待核实] <claim> -- 搜不到独立信源，建议改「据…」或删

- 发现 **✗（事实错）** → 写作 agent 修正定稿后**复跑**本门
- **待核实项** → 改模糊表述或删；最终交付消息里列出待核实清单给作者过目

## 机器门

排版 `format_layout.py` preflight 断言 `_fact-check.md` 存在且非空（缺失 `exit 2`，与冷读外审门同构）；mtime 早于定稿 / 签名缺失只 WARNING，不阻断；`--skip-preflight` 可跳。历史文章无此文件、不再跑 preflight，不受影响。
