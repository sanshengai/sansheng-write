# example-author · 执行手册（虚构示例）

> ⚠️ **这个人不存在。** 本文件纯为演示手册格式与颗粒度，所有例句均为原创虚构。
> 请照 `README.md` 的三步，做一份你真正想模仿的作者的手册来替换它。

## 招式（他特有的，别人不这么干）

1. **先说结论，再拆代价**
   开头一句给判断，第二句立刻讲这个判断要付什么代价。
   骨架：`X 是对的。代价是 ——{具体的、当下就要付的东西}。`
   例：`加缓存是对的。代价是从此你有两份真相，而它们迟早会吵架。`

2. **数字必带换算**
   出现任何数字，紧跟一个读者身体能感知的换算。
   骨架：`{数字}{单位}——{换算成时间/次数/日常物}。`
   例：`省下 240 小时——够把一门语言从零学到能点菜。`

3. **反问只用一次**
   全文最多一个反问句，且必须出现在读者刚要走神的地方（约 60% 处）。

4. **收尾不总结，只留一个动作**
   结尾不复述观点，给读者下一步能立刻做的一件小事。
   骨架：`如果你只想试一件事：{一个 5 分钟内能完成的动作}。`

## 他从不做什么

- 从不用"我们"绑架读者（"我们都知道…"）；只说"我"和"你"
- 从不在开头讲行业背景；背景最多压成一个从句
- 从不用感叹号
- 从不在同一段里同时讲两件事

## 三种起手式

| 起手式 | 骨架 | 例 |
|---|---|---|
| 数字锚 | `{反常的数字}。{它意味着什么}。` | `47 个版本。这是他给同一份方案存的文件数。` |
| 场景锚 | `{时间}{地点}，{一个动作}。` | `凌晨三点的会议室，他把回滚脚本又读了一遍。` |
| 反常识断言 | `{大家以为 X}。其实 {非 X}。` | `大家以为难的是写代码。其实难的是删代码。` |

## 节奏参数

| 参数 | 值 |
|---|---|
| 平均句长 | 18-24 字 |
| 段落长度 | 2-4 句，超过 5 句必拆 |
| 具体名词/数字密度 | 每 200 字至少 1 个 |
| 长短句配比 | 每 3 个长句配 1 个 ≤8 字的短句 |
