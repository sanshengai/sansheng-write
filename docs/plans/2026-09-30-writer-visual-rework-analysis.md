# Writer 新闻图文制作与生图返工分析

本次落实六项流程优化，并针对 OBS-38 的封面与导读图反复生成追查根因。分析以本地实际日志、最终计划、提示词编译器、QA 请求及最终结果为依据。没有重新调用付费模型；软件测试不能证明下一篇一定一次生图成功。

## 已确认的事实与证据边界

本篇采用新闻图片正文、生成主封面和 Hero，以及音乐、播客封面。渲染日志显示主封面调用 8 次、Hero 调用 5 次，13 次 renderer 均返回成功；另有 8 条失败批次 QA 记录及 2 条最终单图通过记录。因此“生图接口反复报错”不是这段日志显示的主要问题：返工主要发生在生成后的验收阶段。

失败记录反复涉及 `style_contract_match`、`brand_palette_match`、`ghost_layer_subdued`，另有文字出现次数和杂字检查。有一批缺少有效资产结果，属于验收结果结构/接口问题，不能算图片缺陷。旧日志把多轮失败记为 `(batch)`，单图统计却显示 QA 打回 0 次，无法直接归因到图片。

历史图片被后续生成覆盖，失败完整结果也只留下最后一份。现存哈希记录显示产物不同，不能还原每轮画面，故无法证明所有失败都是误判，也无法精确估计有多少额外调用可以省下。统计改称“额外渲染”，不把全部额外调用直接定性为浪费。

## 根因及修复

| 维度 | 证据与判断 | 修复 |
|---|---|---|
| 模板与规划冲突 | 主封面模板固定要求标签斜线分隔，本篇要求禁止斜线、竖线或标点；Hero 模板固定圆点边框，本篇禁止边框。是明确的互斥输入。 | 前置 `layout_options`，编译和 QA 使用同一合同；冲突在调用模型之前失败。允许明确选择空格分隔和无边框，保持原默认兼容。 |
| 产品身份参考 | 标准 QA 原来只有待验收图。本篇用临时脚本另加 Dots 新闻现场参考，最终描述明确比较附件 2。 | 正式支持有来源声明、有比较用途、有 SHA256 的只读参考图；Codex、Claude、OpenAI 三个适配器同序传递。 |
| 验收尺度 | “宁可误杀”鼓励保守拒绝，对陌生产品容易把记忆或个人审美当合同。没有充分证据证明具体失败全是这种误判。 | 改为逐项依合同与可见证据判断；不能确认仍拒绝，但须区分图片缺陷、参考缺失和附件读取失败。不得加合同外要求。 |
| 失败可观察性 | `run_visual_qa` 失败返回 None，外层因此丢掉逐图检查。只存最后图、最后结果，无法复盘。 | 保留失败接口兼容；仅读取本次新写、当前请求绑定、错误列表一致的结果记逐图日志。保存每轮请求、结果、原图、参考图及内容寻址提示词。 |
| 重试控制 | 缺少在同项连续失败之后诊断的执行闸门，容易整批反复重生成。QA 行还被混入渲染序号。 | 相同单图输入的不同渲染轮次连续两次同项失败，在下一次调用模型前暂停生成；产出诊断单。修输入或写有原因、绑定本次诊断的单次重生成决定后继续。该决定不豁免最终 QA。渲染序号只计渲染，超时单列。 |
| 规则实现边界 | 浅色检查原来整行出现任何否定词就跳过，肯定要求深色与禁止玻璃放在同一行会漏检。 | 按分号、句号和换行区分子句，修补明确的作用域漏洞。不是完整自然语言理解，复杂语义仍需规划复核。 |
| 制作编排 | 新闻正文图片的选择不能自动决定主封面、Hero、音乐和播客封面；人工清单及交付说明容易过时。 | 接管时生成完整角色计划与当前快照，交付和正式收尾时刷新。主题曲生成单继续前移，作者作曲与配图并行。 |
| 官网验收 | 旧“已上线”只看标题、歌曲封面和可选播客 URL；部署 exit 0 可被误记完成。 | 检查正式文章入口里的正文图片、声明视频、主题曲、播客；队列 queued/running 保持 pending，受理后不重复发起。媒体清单交 Website，上传/CDN/站点发布归 Website。 |

参考图的引入与最后一次重生成同时发生，不能从这次案例推断“只加参考图就能通过”。参考图只解释被声明的身份特征，不继承新闻图的紫色、背景字或布局；不进入待验收资产数量，不豁免文字、色板、裁切及来源字节检查。参考图缺失、越界、非图片、缺来源声明/用途、编译后哈希变化均拒绝。HTTPS 校验只能验证声明格式，真实性仍需取证；不得把网址格式合法说成来源已证实。

## 前期输入合同

先按用途列出正文新闻图、主封面、Hero、主题曲生成单、主题曲音频与封面、播客音频与封面、视频。分别写明来源、展示位置、生成或沿用、适用渠道、需人工完成的步骤。用户已明确的选择持续有效。

生成图先固定文字白名单、比例、字号层级、配色与材质，再规划主体、关系和具体物象。涉及可识别的新产品，准备真实新闻参考和身份特征；不要让验收器只凭名称猜外形。逐项核对模板默认、场景禁止项和布局选项；不能同时要求“包含框”和“禁止框”。新闻截图依据来源、清晰度、裁切和正文对应关系验收，不套生成图审美合同。音乐/播客封面继续使用既有小尺寸和主题盲配规则。

## 诊断次序

同一失败不要直接归因于提示词或闸门。先查附件是否送达、JSON 和资产集合是否完整；再检查当前编译词有没有互斥要求；随后逐项看图，对照合同和来源；最后审查 QA 是否增加了合同外标准。质量有错就局部编辑或针对该问题重生成，参考不足就补参考再复核，接口故障就修接口并受限重试。无法确认的历史项标未知，不改成通过。

`_visual-retry-diagnostic.json` 为机器生成的诊断绑定；需要重新生图时，`_visual-retry-decision.json` 声明匹配的 `binding`、`action: regenerate|edit` 和具体原因。它只是重生成决定，不是放行凭证。当前机制不要求用户再次批准已经授权的常规返修。

## 验证与剩余边界

新增反例覆盖：互斥模板在实际编译入口失败；明确选项后正常编译；空场景仍失败；参考图越界、缺来源、内容变更被拒；参考不增加资产数量且不能豁免检查；同项二次失败在候选渲染入口也阻止模型调用；失败逐图留痕且陈旧结果不重复计数；视频只有链接、歌曲只有封面、媒体 404 不可宣称同步完成；exit 0 + queued 不可完成且不重复提交；带空格文件链接可点击；缺文件的快照不宣称完成。

既有文字错误、杂字、重复文字、比例、字节绑定、独立复核器等测试继续保留。修订没有删除这些检查或调低配色阈值。

静态检查只覆盖已编码的常见互斥项，不能理解所有自然语言冲突。网页 HEAD 可访问也不等于所有地区的视频播放表现；跨地区 CDN 和视频播放实测由 Website 的媒体发布验收继续负责。复杂网站改变图片文件名或音频在浏览器动态加载时，需 Website 提供精确线上媒体映射，不能靠模糊匹配放宽本检查。此次没有执行新的付费生图或网站部署，不能宣称真实新图一次成功。

独立复核进一步发现并修复了空格方案仍带斜线示例、参考图可被静默重新绑定、单次决定被无限复用、重复 QA 被误计为多轮返工、package 导入依赖、全局结构错误漏记，以及用普通图片伪装媒体播放器等问题。相应攻击反例已纳入实际消费者入口测试。


第二轮独立复核补齐：前置检查失败不消耗返修决定；待处理部署回执在归档检查失败时不被覆盖；同名媒体替换使官网完成缓存失效；旧图片重复验收不算新产物；正文核对排除显式隐藏节点和文章外文本，正常有序列表不误拦。官网缓存变化通过真实 `cmd_finalize` 控制流的正反例验证。

网页正文检查是 HTML 文本同步证据，不能替代浏览器视觉验收：不能识别所有外部 CSS 隐藏、短句变化或复杂 Markdown 语义。媒体检查验证播放器归属、地址和响应类型，不验证远端全部文件字节；完整字节、实际播放和跨地区 CDN 验收继续由 Website 负责。机器二次失败暂停当前针对可归属单图的质量检查，结构/传输失败遵循先诊断接口的流程，不能宣称所有批次异常已自动归因。

最终验证：24 个受影响测试文件共 274 项通过；46 条既有 Pillow 弃用警告未影响结果。未调用付费生图或真实发布。四家共享入口均指向本次修改的同一 Writer 本体；入口核对不等于运行中的会话已重新加载。
